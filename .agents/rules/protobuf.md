# Protobuf

The connector contract in `packages/connector-proto` is cogmo's protobuf ([design/connectors.md](../../design/connectors.md) → Wire contract). CI's `Connector contract` job runs `buf lint` (STANDARD) and `buf breaking` (FILE), which enforce naming, layout and file-level compatibility. These rules cover what buf can't, after protobuf.dev's Proto Best Practices and API Best Practices.

- **Presence is `optional`, never a zero value.** A proto3 scalar can't tell unset from `0`, `""` or `false`. So a field whose absence means something is `optional`, and its comment says what absence means: `optional uint64 token_budget` (absent: no budget). A zero value is never a sentinel for "none", in the `.proto` or in the code that reads it. A field that is always set stays plain. For presence alone, use `optional`, not a one-member `oneof`: `optional` is a synthetic oneof in the descriptor, identical on the wire, and protobuf-es generates `field?: T` for it instead of `{ case, value }`.
- **Alternatives are a `oneof`.** When which fields mean something depends on another field, such as a flag or a status, the alternatives are a `oneof`: `VerifyVerdict` ends in `exit_code` or `timed_out`, not an exit code beside a `timed_out` bool. A value that may gain alternatives starts as a `oneof`, because moving a field into one later is breaking. Prefer an enum or a `oneof` to a `bool` when a third state is in sight.
- **Unknown values are expected.** An enum's zero value never means anything valid. Every consumer handles an enum value or `oneof` case it doesn't know with an explicit fallback, never an assertion: design/connectors.md → Failure reasons maps an unknown `JobErrorCode`, or a verdict with no outcome, to `connector_job_failed`. In protobuf-es an unset or unknown `oneof` arrives as `case: undefined`.
- **Nothing is deleted from v1.** A field, enum value or message cogmo stops using is marked `deprecated = true` and stays. `buf breaking` (FILE) fails a deletion even when its number and name are reserved. Deleting is a new package version's change, and that version reserves the numbers and names it drops.
- **Evolve additively; break with a new package.** Add fields, `oneof` cases, enum values, messages and RPCs freely. A breaking change is a new package (`cogmo.connector.v2`), served beside v1 until connectors move. Breaking changes include deleting anything, changing a field's type, number, label, presence or `oneof` membership, and moving a type between files. `buf breaking` fails on all of them.
- **Never key on the binary encoding.** No protobuf library promises the same bytes across versions or languages. A digest or idempotency key over a message is the SHA-256 of its proto3 JSON in RFC 8785 canonical form: `sha256(canonicalJson(toJson(Schema, message)))`, with `toJson` at its default options and the helpers from `src/util/canonical-json.ts`. design/connectors.md specifies the job id's spec digest this way.
- **Bound what crosses the wire.** The server reads messages up to 4 MiB (`readMaxBytes` in `src/connector/server.ts`, gRPC's default). Writers keep every message under that limit: a connector splits a large report across `ReportEvents` calls and sends command output's tail (`output_tail`). A field that can grow, such as a prompt, a plan or a batch of events, says in its comment what bounds it.
- **Name the unit.** A quantity carries its unit in its name (`cost_usd`). A point in time is a `google.protobuf.Timestamp`. A span is a `google.protobuf.Duration`, or an integer named for its unit when whole units are all it needs (`timeout_seconds`).
- **One file per kind.** `session.proto` holds the service, the session and the job envelopes. Each kind's payloads have a file of their own, which imports nothing from `session.proto`, since that would be a cycle. Moving a type between files is breaking, so a type a second kind may share starts in a file of its own.
- **Regenerate, never edit.** After a `.proto` change, run `pnpm --filter @cogmo/connector-proto generate` and commit `src/gen/`. CI fails when the two drift.
