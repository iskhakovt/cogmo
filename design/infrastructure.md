# Infrastructure

## Runtime Requirements `[confirmed]`

| Dependency | Version | Purpose |
|-|-|-|
| PostgreSQL | 18+ recommended (14+ supported via SQL polyfill) | Application state (Drizzle) + Hindsight server storage (pgvector). PG 18 ships native `uuidv7()`; older versions get a `plpgsql` fallback from `scripts/init-db.sql` that is non-monotonic and lower quality — fine for dev, avoid in production. |
| pgvector | latest | PostgreSQL extension for vector storage. Dev/test uses the `pgvector/pgvector:pg18` image. |
| Hindsight | latest | Self-hosted memory server (`ghcr.io/vectorize-io/hindsight`), HTTP API on port 8888 |
| Redis | 7+ | Inngest queue + state store (production); not needed in dev mode |
| Inngest | latest | Event-driven orchestration — `inngest dev` locally, `inngest start` in production |
| Node.js | 24+ (LTS Krypton) | Runtime |

## Local Development `[confirmed]`

Testcontainers via `scripts/dev-infra.ts` — starts PostgreSQL (with pgvector), Redis, Inngest, and Hindsight as reusable containers, applies migrations, then spawns the app with injected env vars. No Docker Compose files needed.

```bash
pnpm dev:infra          # start infra + app
pnpm dev:infra --only   # start infra only (prints env vars)
```

Containers survive across restarts (`withReuse()`). `Ctrl+C` stops the app; containers keep running. Use `docker stop` to kill them.

## Secrets `[confirmed]`

### Encrypted DB storage

All application-level credentials (LLM provider API keys, channel bot tokens, web tool keys) are stored as encrypted rows in a `secrets` table. The DB is the runtime source of truth — env vars are a fallback for dev/CI convenience.

```sql
secrets (
  id            UUID v7 PK,
  name          TEXT NOT NULL UNIQUE,    -- 'anthropic_api_key', 'tavily_api_key'
  ciphertext    BYTEA NOT NULL,
  nonce         BYTEA NOT NULL,          -- 12 bytes, random per row
  description   TEXT,
  validated_at  TIMESTAMPTZ,             -- last successful provider ping
  created_at    TIMESTAMPTZ NOT NULL DEFAULT now()
)
```

Auth tag is appended to `ciphertext` (standard GCM convention in `@noble/ciphers`). Channel-specific credentials (`channels.credentials` JSONB) are also encrypted, using the same helpers.

### Encryption scheme

AES-256-GCM via `@noble/ciphers`, HKDF-SHA256 key derivation via `@noble/hashes`.

**Master key:** 32 random bytes, base64-encoded, provided via `COGMO_MASTER_KEY` env var (or `COGMO_MASTER_KEY_FILE` for Docker secrets). Generated by `main.ts gen-key`. This is the **one secret that stays in env** — everything else is in the encrypted DB.

**Key derivation:** HKDF with purpose-scoped info strings for domain separation:

```
secretsKey = hkdf(sha256, masterKey, fixedSalt, "cogmo/secrets-at-rest/v1", 32)
```

The `v1` tag enables future re-derivation without rotating the master key. If a derived key is compromised, others are unaffected.

**Why `@noble/ciphers`:** Stateless API (`gcm(key, nonce).encrypt(plaintext)`) eliminates the call-order footguns in `node:crypto`'s stateful cipher API. Cure53-audited (September 2024, full scope). ~11 KB gzipped, pure TS.

### `_FILE` convention for Docker secrets

Standard Docker pattern (Postgres, MariaDB, Redis, Keycloak). For any env var `FOO`, if `FOO_FILE` is set, read the file contents and use as the value:

```typescript
function resolveEnv(name: string): string | undefined {
  const filePath = process.env[`${name}_FILE`];
  if (filePath) return readFileSync(filePath, "utf-8").trim();
  return process.env[name];
}
```

Applied to `COGMO_MASTER_KEY` and `DATABASE_URL`. Extensible to any env var.

### ConfigResolver

Reads credentials from DB first, env as fallback:

```typescript
interface ConfigResolver {
  getSecret(name: string): Promise<string | null>;
  getConfig(name: string): Promise<string | null>;
}
```

Env vars (`ANTHROPIC_API_KEY`, `OPENROUTER_API_KEY`, etc.) keep working as fallbacks indefinitely. DB takes precedence when present.

### Env lifecycle

| Context | `.env` loaded? | How env vars arrive |
|-|-|-|
| Production (Docker) | No — `src/env.ts` reads `process.env` only | `docker-compose.yml` `environment:`, Docker secrets via `_FILE` |
| Local dev | Yes — test setups use Node's `process.loadEnvFile` | `.env` file on disk (gitignored) |
| CI | No | Workflow `env:` block + `${{ secrets.* }}` |

`.env*` in `.dockerignore` as defense-in-depth.

## Deployment `[proposed]`

Build TypeScript -> `dist/`. Deploy however suits the host — systemd service, Docker, etc. The app is a standard Node.js process with no special requirements beyond PostgreSQL and Redis.

Future: containerised deployment with Docker.

## Monitoring `[proposed]`

Expose Prometheus metrics on a localhost port:
- LLM call count, latency, token usage, errors
- Memory operations (retain/recall/reflect count, latency)
- Inngest function runs (completed, failed, retried)
- Conversation count, messages per conversation

Monitor RAM usage — avoid bloat, but don't prematurely optimise. Address when actual pressure appears.

## Web UI (Optional) `[proposed]`

Inngest dashboard (built-in at port 8288) for event/function monitoring. Add custom status page when needed.

## Scaling Triggers `[proposed]`

| Signal | Action |
|-|-|
| RAM pressure or swap | Move to larger host or optimise |
| API costs unsustainable | Evaluate local inference for background tasks |
| pgvector index > 1GB | Evaluate dedicated vector store |
