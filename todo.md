### Future infrastructure

- [ ] `p3` Graceful shutdown handle for deferred boot work. `scheduleReconcileCrashedInstances` (and any future fire-and-forget at boot — Daytona snapshot pre-creation, MCP eager-connect, etc.) detaches its promise via `void`, so on rapid `SIGTERM`/`SIGKILL` the warn/error log callbacks may not fire before the event loop exits. Today's observable cost is one missing warn log per restart in a narrow timing window — no state corruption, no missed work (periodic reaper picks up orphans on its next tick). Fix when a real graceful-shutdown abstraction lands for other reasons (in-flight LLM calls, Inngest connections): the in-flight promise becomes a one-line `await` in the shutdown drain. Don't build the abstraction just for this. See PR #217 review residue and `design/infrastructure.md` → Boot-Time Blocking Policy.

Base on `ubi9-init` or `jrei/systemd-debian`; one named volume for all persistent state; first-boot oneshot unit runs setup wizard.
