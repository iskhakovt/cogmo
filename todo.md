- [x] Opt-in client-side encryption for R2/S3 attachments AND workspace files. New `S3_CLIENT_ENCRYPT=true` flag, off by default. Both `AttachmentStore.upload`/`download` and `Service.files.read`/`write` get AES-256-GCM client-side; the bucket sees only ciphertext bodies. Object body layout `[magic 4B: 0xC0 0x6C 0x6D 0x6F][version 2B BE][nonce 12B][cipher+tag]` — 18 bytes of header — keeps each blob self-contained, no separate metadata table or R2-side header. Magic and version split so neither is overloaded: 4-byte magic does the "is this Cogmo-encrypted?" check (collision probability ~1 in 2³²; zero for real attachment formats since `0xC0` is an invalid UTF-8 lead byte and doesn't collide with JPEG/PNG/GIF/WebP/PDF/OGG magic), 2-byte big-endian version drives format dispatch. Byte-level envelope primitives extracted to `src/secrets/blob-envelope.ts` and shared between attachments (decorator pattern via `wrapAttachmentStoreWithEncryption`, Buffer→Buffer transform) and workspace files (optional `encryption` arg to `createFileService`, string→bytes→encrypt on write / decrypt-or-passthrough→string on read). Reads fall back to returning raw bytes when the magic prefix is absent, so flipping the flag on a populated bucket is a no-op for old objects — pre-flag plaintext stays readable, new uploads are ciphertext, churn converges the bucket over time. A pathological plaintext that happened to match the magic would fail GCM auth-tag verification and surface as an error, not silent corruption. Object keys (S3 paths) remain plaintext for both stores, matching the AWS S3 Encryption Client convention; for attachments this is irrelevant (random UUIDs), for workspace files the operator's responsibility is to pick non-revealing file names. Full path-name encryption (rclone-crypt style) would break `list_files` semantics and is deferred. Content-Type for both stores becomes `application/octet-stream` when encrypted, and attachment paths land at `inbound/<uuid>.bin` via a one-line addition to the `mediaTypeToExt` table mapping `application/octet-stream → bin`. Key derived via HKDF purpose `"cogmo/s3-objects/v1"` (covers both stores). New binary `encryptBytes`/`decryptBytes` in `src/secrets/encryption.ts` skip the UTF-8 round-trip the existing string-typed `encrypt`/`decrypt` perform.
