Reasoning models on OpenAI-compatible providers can run with thinking off or capped: a model's routing row carries extra chat-completions request fields, and the adapter shows how much a model thought.

- **`model_providers.extra_body`.** A nullable JSONB column (migration `0069_model_providers_extra_body`) holding a JSON object `OpenAICompatibleProvider` adds to every request for the model, streaming and not — e.g. `{"reasoning":{"enabled":false}}`, `{"reasoning":{"effort":"low"}}` or `{"venice_parameters":{"disable_thinking":true}}`. It sits on the model × provider row because one endpoint serves models with different thinking controls. Keys the adapter sets itself (`model`, `messages`, `stream`, `stream_options`, `tools`, `response_format`, `max_tokens`, `max_completion_tokens`, `temperature`, `reasoning_effort`, `prompt_cache_key`, `session_id`, `cache_control`), and `tool_choice`, which a forced value would turn into a turn that never ends, are refused when the value is written, so the two never share a key and nested objects go out as written. A reserved key written outside the store is dropped with a warning on read rather than failing the model's lookup, and an object left empty reads as null.
- **CLI.** `cogmo model add --extra-body '<json>'`, a new `cogmo model set <model> --provider <name> --extra-body '<json>' | --clear-extra-body` that changes a row in place, and an `extra_body` column in `cogmo model list`. Input must be a non-empty JSON object; Anthropic providers are refused.
- **Reasoning visibility.** The adapter doesn't forward `reasoning_content` / `reasoning`, but now counts it: the chat span gets `cogmo.llm.reasoning_chars`, stamped even when the stream is cut off mid-thought, and a provider-reported `completion_tokens_details.reasoning_tokens` becomes `Usage.reasoningTokens` — on the span as `gen_ai.usage.reasoning.output_tokens` and summed into the `agent loop complete` log line's usage.
