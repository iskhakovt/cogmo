Promote the tier-2 skills python source from TS template-literal embeds (`src/skills/worker-sysbox/{supervisor,runner}.py.ts`) to a real Python project at `images/skills/`. Same runtime behaviour as the supervisor shipped in P3.2.B.2; the change is dev-experience and shipping mechanics.

What ships now: `images/skills/pyproject.toml` (uv-managed, hatchling build, src layout), `src/cogmo_skills_runtime/{__init__,__main__,supervisor,runner}.py` with full type annotations and `py.typed` marker, `tests/{test_supervisor,test_runner}.py` (21 pytest tests covering the bridge, fork+pidfd timeout, SIGKILL+reap, syntax-error / skill-raises / missing-async-run shapes), `uv.lock` for reproducible builds. Dev tooling: ruff (`F E W I B UP RUF` selects, 100-col), pyrefly as the typechecker (Meta's Rust-based replacement for Pyre — 87.8% spec conformance, real LSP, used by Instagram in production; chosen over mypy for speed + better inference on partially-annotated code, and over Astral's ty for spec-conformance maturity at the time of writing), pytest with `asyncio_mode = "auto"`. New CI job `skills-runtime` in `.github/workflows/ci.yml` runs `uv sync --locked` + `ruff check` + `pyrefly check` + `pytest`.

The Dockerfile becomes a two-stage multi-stage build: builder syncs the locked deps from a uv binary copied out of `ghcr.io/astral-sh/uv:0.11.12` (no apt install of uv); runtime stage copies just the venv to `/opt/cogmo-skills/.venv` and adds it to `PATH`. Default `CMD` is `python3 -u -m cogmo_skills_runtime`, which the TS worker overrides at create-container time the same way it always has. Production has zero runtime python deps today (stdlib only); the uv pipeline is wired so adding a dep is `uv add` + `uv lock` + the image picks it up — no Dockerfile changes per dep. Sets the convention for P3.4 per-skill `requirements.txt` resolution.

TS side: `src/skills/worker-sysbox/{supervisor,runner}.py.ts` deleted (~600 LOC of template-literal Python with TS escaping, all gone). `worker.ts` replaces the `python3 -u -c <SUPERVISOR_PY>` exec with `python3 -u -m cogmo_skills_runtime` — one-line change. No protocol, dispatcher, or worker semantics changed.

Why this matters: the previous embed had no Python tooling — no ruff, no pyrefly, no pytest, no editor LSP, manual escaping of backticks/`$`/`\n` in the TS string, and ~350 LOC of supervisor + runner code with zero unit tests. With the proper project the supervisor's pidfd-timeout + SIGKILL-reap primitives and the runner's bridge + result-shape contracts are now pinned by tests at every CI run; full type annotations expose latent type errors (the `_Bridge.deliver` `call_id` instance check, `dict[str, Any]` vs `Any` arg shapes, etc.) that pyrefly caught during the migration. Smoke-tested locally against the rebuilt `cogmo-skills:test` image: 3 sequential tasks share supervisor PID 1, fresh child PIDs per task, `sys.modules` state isolation holds task-to-task. Ships ~13 KB of bytecode-compiled Python in the image; ~30 MB venv is offset by removing the embedded source from the cogmo binary. Local dev: `cd images/skills && uv sync && uv run ruff check && uv run pyrefly check && uv run pytest`.

Decision pinned in design/skills.md "Warm pool" section. PEP 734 subinterpreters and `multiprocessing` / `pebble` rejection rationale preserved from P3.2.B.2 — those decisions don't change with the project promotion.
