Skills `ctx.files` RPC surface. Skills running on the Tier-1 (Pyodide WASM) runtime can now read, write, and list files in the agent's per-user S3-backed workspace via `ctx.files.read(path)`, `ctx.files.write(path, content)`, `ctx.files.list(prefix=None)` — the same `service.files` workspace the in-process `read_file` / `write_file` / `list_files` tools use, so the LLM and skills share one workspace. Reads/lists require `effects: [reads_filesystem]` in `SKILL.md`; writes require the existing `writes_filesystem` effect (new `reads_filesystem` added to the effect vocabulary in `src/skills/types.ts`). Every call audits to `skill_context_calls` with `target` set to the path (not the content). Backend errors surface as typed `read_failed` / `write_failed` Python exceptions; missing-effect refusals surface as `missing_effect`. New `_Files` class in `src/skills/worker-wasm/ctx.py.ts` mirrors the surface in async Python (`await ctx.files.read("notes/draft.md")`). `SkillRunnerImpl` accepts `files: Service["files"]` as a constructor dep, threaded from `src/index.ts` where the bootstrap already creates `fileService` for the agent. `design/skills.md` "Host context" section gains a `### File workspace [proposed]` deep-dive that contrasts `ctx.files` (named/mutable/listable text) with `ctx.attachments` (opaque/immutable binary), documents the planned per-tier POSIX shim at `/files` (s3fs-fuse for sysbox, custom Emscripten FS via SAB+Atomics for Pyodide — the JupyterLite DriveFS pattern, since Pyodide's FS layer hasn't migrated to JSPI yet), and calls out why `/files` is deliberate ( `/workspace` is taken by the coding-delegation worktree bind-mount). 2288 unit tests pass.
