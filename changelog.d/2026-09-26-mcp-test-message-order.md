`pipeline.mcp.integration.test.ts` reads the turn's last assistant message ordered by `id`. It had taken the last assistant row of an unordered `SELECT`. The integration tier shares one database, so rows come back in heap order, which depends on what other suites wrote. When the `tool_use` row sorted after the reply, the poll never saw the reply and timed out after 30 s, even though the turn had completed in about a second. Whether that happens depends on which suites overlap the MCP test. CI runs files in size order, so changing any integration test file's size could turn it on or off.
