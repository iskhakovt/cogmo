`pipeline.mcp.integration.test.ts` reads the turn's last assistant message ordered by `id`. A turn writes its `tool_use`, `tool_result` and reply rows in one insert, so they share `created_at`, and `id` (UUIDv7) is what carries their order. The integration tier shares one database, and an unordered read returns rows in heap order, which depends on what other suites wrote. That order can put the `tool_use` row after the reply.
