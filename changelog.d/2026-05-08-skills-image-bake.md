Cogmo-baked tier-2 skills image (P3.2.C) + Docker Bake adoption + match-parent versioning + multi-arch cogmo. Replaces the ad-hoc `python:3.14-slim` pull from Docker Hub with `ghcr.io/iskhakovt/cogmo-skills:<version>`, built and published from `images/skills/Dockerfile`. The image is intentionally minimal for now (slim base + non-root `cogmo` user) — the win is owning the pipeline so future deps (s3fs-fuse for the POSIX shim, baked pip wheels) land here without a per-cold-start `apt-get install` regression. Base image pulled from `mirror.gcr.io/library/python:3.14-slim@sha256:...` to avoid Docker Hub rate limits, matching the root cogmo Dockerfile's pattern. **Tag scheme is match-parent**: all three Cogmo-owned images (cogmo app, cogmo-devbase, cogmo-skills) ship at the same semver — the runtime baked from `cogmo:1.46.0` pulls `cogmo-devbase:1.46.0` and `cogmo-skills:1.46.0`. Versioning piggybacks on semantic-release / dunamai (no separate per-image release pipeline). `env.ts` defaults are version-aware via `process.env.VERSION` (set by the app `Dockerfile`'s `ENV VERSION=$VERSION` build arg) and fall back to `:latest` when unset, so the runtime auto-pulls the right image without any per-deploy env wrangling. Co-shipping with **Docker Bake adoption** (single `docker-bake.hcl` at repo root, three targets — cogmo, devbase, skills — with per-image `*-meta` stubs that publish.yml's `metadata-action` calls populate with semver + `:latest` tags + standard OCI labels) and **multi-arch for cogmo only**: `linux/amd64` + `linux/arm64` so Apple Silicon dev + Graviton/Ampere/CAX cloud consumers pull the right layer transparently. devbase + skills stay single-arch because sysbox itself is amd64-only today. Per-platform GHA cache scopes (`scope=cogmo-amd64` / `scope=cogmo-arm64`) sidestep moby/buildkit#2758's "last platform wins" cache-overwrite. Workflow split: `publish.yml` builds + pushes all three at release via three `metadata-action` calls + bake; `sysbox-e2e.yml` `bake --load`s the skills image at `:test` for the integration test (cache-shared with publish, no registry push, no `packages: write`); `ci.yml`'s e2e step migrated from `build-push-action` to `bake-action` so it shares the cogmo cache scope with publish; new `ghcr-cleanup.yml` cron prunes old packaged versions weekly (matrix over the three packages, `dataaxiom/ghcr-cleanup-action`, `keep-n-tagged: 20`, `older-than: 14 days` for orphan manifests, `workflow_dispatch.inputs.dry_run` defaulting to true so manual runs verify before the cron actually deletes). Old per-image `devbase.yml` and `skills.yml` workflows deleted. The sysbox install logic — `.deb` SHA256 pin, postinst-race retry, widened journal capture for diagnosis — moved out of `sysbox-e2e.yml`'s inline shell into `.github/scripts/install-sysbox.sh`.
