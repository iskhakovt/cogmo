Cogmo-baked tier-2 skills image (P3.2.C) + Docker Bake adoption. Replaces the ad-hoc `python:3.14-slim` pull from Docker Hub with `ghcr.io/iskhakovt/cogmo-skills:slice1`, built and published from `images/skills/Dockerfile` by a new `.github/workflows/skills.yml`. Slice-1 image is intentionally minimal (`python:3.14-slim` base + non-root `cogmo` user) — the win is owning the pipeline so future deps (s3fs-fuse for the POSIX shim, baked pip wheels) land here without a per-cold-start `apt-get install` regression. Tag pattern matches `cogmo-devbase`: durable `slice1` handle pinned by the runner via `COGMO_SKILLS_IMAGE` env (default in `src/env.ts`), per-build `slice1-<short-sha>` for rollback. `src/skills/runner.ts` `DEFAULT_TIER2_IMAGE` updated to match; `src/index.ts` threads `env.COGMO_SKILLS_IMAGE` through to the runner. Co-shipping with **Docker Bake adoption** for multi-image builds: new `docker-bake.hcl` at repo root defining three targets (`cogmo`, `devbase`, `skills`) inheriting from a `_common` block and an empty `docker-metadata-action` target the workflows fill via `metadata-action`'s `bake-target` integration. The existing `publish.yml` and `devbase.yml` migrate from `docker/build-push-action` to `docker/bake-action@v7.1.0`, sharing target structure / cache config / platform pins through the bake file; per-target tags + labels still arrive at runtime from each workflow's `metadata-action` call. Single-platform (`linux/amd64`) — sysbox is amd64-only today; multi-arch is a one-line bake change when an arm64 host enters scope. **Test strategy:** sysbox-e2e workflow now runs `bake --load` for the `skills` target before tests so the runner integration test exercises the actual production artifact (not `python:3.14-slim` from Docker Hub). `cache-from: type=gha,scope=skills` shares cache populated by `skills.yml` — steady-state cost is roughly a `docker pull`. `--load` keeps the test image unpushed (no registry pollution from PR builds, no `packages: write` permission needed on PRs, no cleanup tax). Local-dev convention: `docker buildx bake --load skills` before running the sysbox integration test. Closes the two `Later` todo items: `p2 Skills P3.2.C` and `p3 Adopt docker-bake.hcl`.
