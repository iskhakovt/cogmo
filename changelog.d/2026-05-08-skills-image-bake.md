Cogmo-baked tier-2 skills image (P3.2.C) + Docker Bake adoption + match-parent versioning. Replaces the ad-hoc `python:3.14-slim` pull from Docker Hub with `ghcr.io/iskhakovt/cogmo-skills:<version>`, built and published from `images/skills/Dockerfile`. The image is intentionally minimal for now (slim base + non-root `cogmo` user) — the win is owning the pipeline so future deps (s3fs-fuse for the POSIX shim, baked pip wheels) land here without a per-cold-start `apt-get install` regression. **Tag scheme is match-parent**: all three Cogmo-owned images (cogmo app, cogmo-devbase, cogmo-skills) ship at the same semver — the runtime baked from `cogmo:1.46.0` pulls `cogmo-devbase:1.46.0` and `cogmo-skills:1.46.0`. Versioning piggybacks on semantic-release / dunamai (no separate per-image release pipeline). `env.ts` defaults are version-aware via `process.env.VERSION` (set by the app `Dockerfile`'s `ENV VERSION=$VERSION` build arg) so the runtime auto-pulls the matching image without any per-deploy env wrangling. Co-shipping with **Docker Bake adoption** (single `docker-bake.hcl` at repo root, three targets — cogmo, devbase, skills — inheriting from `_common`) and **multi-arch for cogmo only**: `linux/amd64` + `linux/arm64` so Apple Silicon dev + Graviton/Ampere/CAX cloud consumers pull the right layer transparently. devbase + skills stay single-arch because sysbox itself is amd64-only today. Per-platform GHA cache scopes (`scope=cogmo-amd64` / `scope=cogmo-arm64`) sidestep moby/buildkit#2758's "last platform wins" cache-overwrite. Workflow split: `publish.yml` builds + pushes all three at release; `images-pr-check.yml` is verify-only on PRs touching image paths (single-arch override on cogmo for fast PR CI; cache-scope override too so amd64-only PR builds don't pollute the arm64 cache); `sysbox-e2e.yml` `bake --load`s the skills image at `:test` for the integration test (no registry push, no `packages: write`); a new `ghcr-cleanup.yml` cron runs weekly to keep the package UI tidy (matrix over the three packages, `dataaxiom/ghcr-cleanup-action`, `keep-n-tagged: 20`, `older-than: 14 days` for orphan manifests). Old per-image `devbase.yml` and `skills.yml` workflows deleted. Closes the two `Later` todo items: `p2 Skills P3.2.C` and `p3 Adopt docker-bake.hcl`. Sysbox-e2e bake-load runtime cost is roughly a `docker pull` once the cache is warm.
