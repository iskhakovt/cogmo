Skills P3.3 hardening — eight review-comment fixes on the dynamic skill-creation slice (PR #112). (1) `runner.register` rejects `branch === "main"` / `"refs/heads/main"` at the boundary; without this guard the flow would `update-ref` main onto itself then call `deleteRef("refs/heads/main")` and drop the skills repo's only authoritative ref. (2) `git-ops.deleteRef` refuses bare `main` and `refs/heads/main` (defense in depth — typed `GitOpsError` so any remaining caller bug fails loudly). (3) `executeApprove` writes the full set of manifest-derived columns (`tier`/`riskTier`/`effects`/`schedule`/`inputs`/`outputs`) projected from the just-approved sha, not just `gitSha`/`disabled`; runner re-reads SKILL.md at `deploy.gitSha` and passes them through, so tool definitions and ajv input validators reflect what's actually live. (4) `executeRollback` does the same — rolling back to a sha with a different inputs schema now updates the row's columns to match, instead of leaving the row pointing at v1's sha while still validating against v2's schema. (5) Per-turn tool-list rebuild factored into `mergeBuiltInsAndSkillTools` (in `src/skills/skill-tool-builder.ts`) — built-ins win on name collision; a skill named `web_search` / `delegate_coding` / `register_skill` is dropped with a warn instead of silently shadowing the built-in handler. (6) `runner.register` calls a new `#prevalidateSchemas` (ajv-compile `inputs` and `outputs` JSON Schemas) BEFORE `executeRegister`, so a malformed schema fails the register without moving main + persisting a half-broken row. (7) `runner.rollback` and `runner.approveDeploy` re-read SKILL.md at the target sha and reject if `manifest.name !== opts.name` (`target_skill_mismatch`) — without this, rolling back skill A to a sha originally registered for skill B would silently rebind A's tool to B's code. (8) `classifier.classifyManifest` promotes any skill declaring destructive/external/financial effects (`deletes_external`, `sends_email`, `sends_message`, `posts_public`, `financial`, `spawns_subprocess`) OR `tier: container` OR 3+ secrets to `approve`-tier instead of pinning everything to `notify`; pure declaration-based — full AST-lint detection of *undeclared* effects still deferred. New unit tests: `classifier.test.ts` (effect promotion matrix, container/secrets thresholds, version stamp), `git-ops.test.ts` extended (refuses-main on both `main` / `refs/heads/main`), `skill-tool-builder.test.ts` extended (built-in wins on collision, non-colliding skills retained, no input-array mutation), `runner.register.test.ts` extended (reject branch=main, reject invalid inputs schema without moving main, sends_message → pending_approval, end-to-end approve flow projects manifest, rollback rejects cross-skill SHA, approve/rollback project full manifest into row). 1788 unit + 88 integration tests pass.
