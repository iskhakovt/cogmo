Hybrid topic registry — per-user `custom_compartments` extends the curated `personal/work/health/financial/technical/misc` enum, completing the second half of the "go hybrid on topics AND speaker-driven isolation" design that shipped only the speaker half in PR #180. New `custom_compartments` table (id, user_id, name, description, created_at; cascade on user, unique on (user_id, name)) registers per-user buckets; the Observer loads them once per fire and templates `description` into both `extract-memories` and `drain-pending-memories` prompts via a new `buildCompartmentDefinitions` builder, then locks the structured-output compartment field to `[...CORE, ...customs]` via `buildExtractedMemorySchema(customs)` / `buildClassifiedMemorySchema(customs)`. Cap is 10 per user (Zep's number — beyond that the classifier accuracy degrades + prompt bloats); `MemoryCompartmentSchema` relaxed from `z.enum(...)` to `z.string().min(1)` because the legal set is now dynamic, with cross-table validation lifted to the Transport boundary on profile create/update — an unknown value (typo or unregistered custom) surfaces as `compartment_unknown` instead of silently filtering recall to no matches. Reserved-name guard rejects the six core values to keep the merged classifier set unambiguous. Forward-only delete: `/compartments rm dnd` drops the option from future classifications but leaves existing `compartment:dnd` Hindsight tags intact (Cogmo doesn't store memory rows, so an FK-style RESTRICT isn't possible). New Telegram surface: `/compartments [list|add <name> <description>|rm <name>]`, mirroring `/classes`'s shape. Transport gains a `compartments: { list, create, delete }` namespace with typed errors `compartment_cap_exceeded`, `compartment_name_taken`, `compartment_name_reserved`, `compartment_not_found`. Internal cleanup: classifier prompts moved from `MEMORY_EXTRACTION_PROMPT` / `PENDING_CLASSIFICATION_PROMPT` constants to `buildMemoryExtractionPrompt(customs)` / `buildPendingClassificationPrompt(customs)` builders so a per-fire prompt-cache key includes the customs state (1 cache key at single-user scale; invalidates on `/compartments add|rm`). Operator nudge embedded in the prompt: when customs are present, the classifier is told to prefer custom buckets over core for facts that fit both — without it an over-eager LLM might pick a custom for a borderline fact and silently shift the bank's compartment distribution. Two parser tests in `commands.test.ts` updated: case-mismatch and unknown-compartment guards moved off the parser (where they never had access to the user's customs anyway) onto the Transport layer; the parser now accepts any non-empty string and the Transport returns `compartment_unknown` with an actionable message pointing at `/compartments add`. Test coverage in this PR: 38 new unit tests covering the store (cap, reserved-name, dedup, forward-only delete, cross-user isolation), prompt + schema builders (core-only path, customs-appended path, prompt templating, structured-output enforcement that rejects an LLM emitting an unrecognized compartment), Transport (error mappings for all four `compartments.*` codes plus `profiles.update` scope validation rejecting unknown values and accepting core+custom), Telegram parser (new permissive-then-validate semantics), `extract-memories` and `drain-pending-memories` customs-threading (prompt contains custom name+description, LLM emitting custom value round-trips to a `compartment:<custom>` tag, classifier failure on a stale custom value is caught), and `/compartments` Telegram handler (16 tests covering dispatch, list/add/rm flows, error mappings, and the `compartment_unknown` cross-namespace surface from `/profile scope`). Plus 9 new Observer integration tests against real Postgres + recording memory mock + stub LLM provider — exercising `runObserver` end-to-end via a refactored `runObserver(event, step, deps)` entry point that's directly callable, covering the conversation_not_found / too_short skip paths, full happy path with tag emission, profile_class lineage on emitted memories (composite-FK happy path), customs templated into both extraction and pending-classification prompts, pending drain with row deletion, mixed-profile speaker-isolation through the LEFT JOIN, and per-row classifier-failure recovery. 2679 unit tests pass; 9/9 integration tests pass in 18s.
