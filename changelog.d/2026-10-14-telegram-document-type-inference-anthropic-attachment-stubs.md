An attachment of a type the model can't read leaves its conversation answerable.

- **Telegram infers a document's type** when `mime_type` is missing or `application/octet-stream`, the type clients send for a file they don't recognise (`.html` among them): from the file name's extension through `mime-types`, then from the content, where UTF-8 text is `text/plain`. An HTML file or a script whose extension mime-db lacks reaches the model as text, and an untyped image sent as a file routes to vision. A specific `mime_type` wins.
- **The Anthropic adapter stubs what it can't send**: a document that is neither PDF nor text-like, or a base64 image that isn't JPEG, PNG, GIF or WebP, becomes a text block naming the file and its type (`[document: page.html (application/octet-stream) — not supported on this provider]`), as the OpenAI-compatible adapter does for binary documents. Such an attachment replays from its stored row on every later turn, and a conversation carrying one is answered.
