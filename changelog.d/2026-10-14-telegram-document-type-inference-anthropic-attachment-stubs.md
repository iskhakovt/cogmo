An attachment of a type the model can't read leaves its conversation answerable.

- **Telegram infers a document's type** when `mime_type` is missing or `application/octet-stream`, the type clients send for a file they don't recognise (`.html` among them). The content decides between text and binary, and the extension (`mime-types`) names the type within each: UTF-8 text keeps a `text/*` type and is otherwise `text/plain`, so HTML, scripts and source files reach the model as text; binary takes the extension's type. A specific `mime_type` wins. Only JPEG, PNG, GIF and WebP route to an image block; HEIC, BMP and other image formats stay named documents.
- **The Anthropic adapter stubs what it can't send**: a document that is neither PDF nor text-like, or a base64 image that isn't JPEG, PNG, GIF or WebP, becomes a text block naming the file and its type (`[document: page.html (application/octet-stream) — not supported on this provider]`), as the OpenAI-compatible adapter does for binary documents. Such an attachment replays from its stored row on every later turn, and a conversation carrying one is answered.
