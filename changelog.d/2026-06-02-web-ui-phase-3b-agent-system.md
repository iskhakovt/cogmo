Make the web admin API contract-first and build out the AGENT and SYSTEM screens — Phase 3b.

The oRPC layer is now defined by a single `webContract` in `packages/contracts`: inputs via Zod, outputs via the type-only `type<DTO>()` helper reusing the existing Transport DTOs, and one generic `TRANSPORT_ERROR` carrying the `TransportError` union. The server `implement`s the contract instead of hand-rolling a router, and the SPA derives a fully-typed client (`ContractRouterClient<WebContract>`) from it — the hand-authored `WebApi` is gone, and client/server can't drift. To carry the runtime contract, `packages/contracts` stops being types-only: it ships TS source (`exports.import` → `./src`) that `tsx`/`vite` transpile and `tsup` bundles into the server (`noExternal`); the web side imports the contract type-only. `TransportErrorSchema` and its compile-time parity guard move here next to the `TransportError` union, and a new `McpServerSummary` projection keeps server config / secret-source values off the client.

On top of the typed client, AGENT and SYSTEM become real screens (replacing the 3a stubs). AGENT renders profiles, the selectable model list, MCP servers, and the skills library; SYSTEM renders scheduled tasks and the "what it learned" evolution audit with a detail drawer for a single event's full payload. Both are built from a small read-screen kit — a `useResource` hook (loading / inline `Result`-error / ready), ruled Ledger tables, trust-palette status pills — so every panel surfaces a failed read as an explicit inline row. These screens are read-only; the editing/mutation surface is tracked as a follow-up. The component/hook DOM test harness remains deferred to Phase 5.
