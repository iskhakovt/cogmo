**Channel sessions are an explicit state machine.** `design/transport/sessions.md` → Lifecycle names the unit (`channel_sessions.id`), the two states, a transition table (create, close, swap, expire) and a failure-mode table for the races the session path has: two inbounds on one lazy rotation, a crash between `/new`'s close and create, a concurrent `/new` and `/resume`, a stale close, an expired row holding its address.

The schema enforces the one invariant snapshot isolation cannot: migration `0075_sessions_one_active_per_address` adds `uq_sessions_active_address`, a partial unique index on `channel_sessions (channel_id, platform_address) WHERE status = 'active'`, after `0074_sessions_close_duplicate_active` closes every active row but the newest per address so the index builds over existing data. `createSession` writes through it as a keyed insert (`ON CONFLICT DO UPDATE` no-op SET, `RETURNING (xmax = 0)`), returning `new` or `recovered` with the holder's id and conversation, so a create that loses a race retries past `40001` onto the winner's row instead of raising `23505`. `closeSession` is a conditional transition (`WHERE id AND status = 'active'`) returning `closed`, `stale` with the row's status, or `not_found`; `swapSession` returns the ids it closed with the id it opened, and throws if its insert recovers a row — the close in the same transaction makes that an invariant violation.

`Transport.createConversation` looks the address up inside its transaction and joins the active session when there is one, so the retry after a race inserts no orphan conversation; `/new` and the Web UI's new-chat route close the current session first to supersede it. The boundary resolver's fresh path swaps out a session that opened on the held address during the hold instead of draining the buffered inbounds into it. `resolveSession`'s lazy rotation runs its lookup, idle check and close in one transaction and branches on the close outcome. `/end` reports a `stale` close as "already ended"; the direct adapter, the reset command service and the Web UI's disconnect close log it.

Tests: PGlite store and migration cases, namespace and caller cases for every outcome branch, and `session-keyed-insert.integration.test.ts`, which races create against create and against swap on two real connections (the loser retries past `40001`) with a plain-insert `23505` control.
