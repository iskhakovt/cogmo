Daytona managed-sandbox backend (Phase 3a — worktree-less). New `DaytonaSandboxClient` at `src/sandbox/daytona/` implements the `SandboxClient<DaytonaSessionState>` contract from PR #160, alongside the existing `LocalDockerSandboxClient`. Skills tier-2 runs end-to-end on Daytona today; coding-delegation rejects with a clear "Phase 3a doesn't accept worktree" error until Phase 3b ships git-as-transport. New `SANDBOX_BACKEND` env (`local-docker` default, `daytona` opt-in) selects the backend at boot via `src/sandbox/factory.ts`; the Daytona key lives in the encrypted `secrets` table as `daytona_api_key`. Streaming exec wraps Daytona's `executeSessionCommand({ runAsync: true })` + `getSessionCommandLogs(...)` WebSocket — one Daytona session per `execStreaming()` call so `dispose()` (which can only `deleteSession`) tears down a single command. Per-sandbox `refreshActivity()` ticker (every 5 min, `unref()`'d) keeps long coding tasks alive against Daytona's default 15-min auto-stop.
