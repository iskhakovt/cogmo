- Fix a regression introduced in v1.66.0 where every naturally-completed Daytona `executeSessionCommand` call failed with `DaytonaNotFoundError: session not found`. PR #267's wedge-resilience refactor lifted `await cleanupSession()` out of the per-branch conditionals in `wsPromise.then(...)` to the top of the handler, but the natural-success branch's `getSessionCommand(sessionId, commandId)` call depends on the session still existing — Daytona returns 404 once it's deleted. Every Daytona coding-delegation task hit this on exit-code fetch before reaching the actual `claude plan/exec` work.
- Use `try/finally` around the natural-success branch: cleanup runs exactly once on every settle path (`timedOut`, `disposed`, success, fetch-error), but always *after* `getSessionCommand` resolves so the exit-code fetch sees a live session. `cleanupSession()` is already idempotent via its in-flight guard.
- Strengthen the `Process` test double in `exec-streaming.test.ts`: `getSessionCommand(sid, _)` now throws `DaytonaNotFoundError` after `deleteSession(sid)` has been called for that session, mirroring live Daytona. The pre-fix mock returned the recorded exit code regardless of `deleteSession` state, which is exactly why the wrong-ordering bug shipped through CI for a full release. New tests pin (a) the relative order `getSessionCommand → deleteSession` on the success path, and (b) the fake's own contract.
