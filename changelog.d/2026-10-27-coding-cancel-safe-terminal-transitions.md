Coding tasks' in-run terminal transitions are conditional, so a Cancel that lands while an orchestrator is working stands. The verify run's `verifying → pushed` and `pushed → pr_open` writes (`transition-pushed`, `transition-pr-open`) and every orchestrator's in-run `→ failed` (`transition-failed`, `transition-failed-after-push`) go through a conditional UPDATE whose result the bare body branches on. A task that left its status under the run — a Cancel during the plan or execute session, the verify suite, the push or the PR open — is neither pushed on, nor announced as failed, nor given a PR announcement: the run reclaims its worktree and sandbox (`reclaimEndedTask`) and returns `skipped`, leaving the status exactly as the canceller wrote it. A row already at `failed` still counts as recorded, so a step re-executing after a lost result, or a reconcile that got there first, keeps the failure flow intact.

The superseded step ids (`set-status-pushed`, `set-status-pr-open`, `set-status-failed`, `set-status-failed-after-push`) memoized `void`; a run in flight across the deploy runs the new step once, finds the row `stale` at its own target (or `already_terminal` at `failed`), and carries on. Event names and idempotency ids are unchanged.

Residuals, named in design/coding-delegation.md → Task lifecycle: a PR GitHub has already opened when a Cancel lands before `transition-pr-open` stays open, recorded in `pr_metadata` with no `pr-opened` event; the catch path's `failed` write stays unconditional, so a Cancel followed by a throw in the same run reads `failed`; and an in-run `failed` whose `emit-task-failed` then exhausts its retries is never announced, since reconcile finds the row already terminal.

Tests: a cancel landing during a failing plan session, during a failing execute session, during a failing execute push, during the verify suite (whether it then passes or fails) and during the PR open each pin the task at `cancelled` with no failure or PR announcement; replay tests pin the in-flight shape for `transition-pushed`, `transition-pr-open` and `transition-failed`.
