**Tier-1 `ctx.http` takes an injectable network, and the skill-authoring integration test uses it.** `DefaultCtxHandler` accepts a `fetch` alongside its existing `resolveHost`. `SkillRunnerOptions.ctxHttp` passes both to every handler the runner builds, and a test reaches that through `BootstrapOptions.skillCtxHttpOverride`. Production leaves all three unset, so it gets real DNS and the global `fetch`, looked up per call.

`skill-authoring.integration.test.ts` passes in a stand-in network. It resolves `api.coingecko.com` to a public address and serves the one price endpoint that the authored `btc-spot` skill calls. It applies in record mode as well as replay. The cassettes cover the chat and the Daytona sandbox but not the skill's own request, so without the stand-in the suite depends on CoinGecko's uptime and its rate limits on datacenter IPs, and fails offline. The test asserts that the skill's output equals the stand-in's figure exactly. That figure is 64,725, the price in the recorded reply, and the match only holds if the request stayed in the test process.

The seam needs both halves. A stand-in `fetch` alone still leaves the address guard resolving `api.coingecko.com` through real DNS. A loopback stub server cannot stand in either: `ctx.http` refuses loopback, link-local and private addresses by design, and no allowlist entry can name one. The allowlist and address checks run unchanged against whatever the stand-in answers, so it replaces the network, not the policy. A unit test pins that a refused destination never reaches an injected `fetch`.

No fixtures change, and no re-record is needed.
