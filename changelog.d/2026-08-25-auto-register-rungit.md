**Every host-side git call resolves through `runGit`, `auto-register-skill`'s fetch of the PR branch included.** The primitive owns the askpass env threading and raises failures naming the git command and its stderr, so a fetch that fails while writing the skill branch reports the ref it could not write. Its siblings on that path — `fetchFeatureBranch`, `pushTaskBranchToRemote`, the `repos.add` clone — go through the same helper, which is what makes the askpass contract one thing to audit rather than one per call site.

**On serializing that fetch against the verify orchestrator's fetch-back.** Both write `refs/heads/<branch>` in the same bare repo — for the skills repo `coding_repos.local_path` is `COGMO_SKILLS_PATH` — ordered only by the `coding/task/pr-opened` emit that precedes the fetch-back step. Measurement says no serialization is warranted, and `todo.md` carries the numbers: in the production shape (local repo lacking both the ref and its objects, 5000 packed `cogmo/*` refs) two fetches staggered 0-250ms against a 163-283ms fetch produced 0 failures in 125 trials. Both target the same value, so the loser either creates the ref or finds it already at that value — no second update, no lock, no error.

The contended case is real but needs a precondition the coding flow does not supply: the two fetches must observe *different* old values, which means the branch tip moved on origin between them. Forced into that state it fails 20/20 with `cannot lock ref … is at X but expected Y` — an old-value mismatch that `core.filesRefLockTimeout` does not address, since that setting governs the lock-file variant. Raising it would also convert a stale `.lock` left by a crashed process from a fast failure into a slow one, which is the more commonly reported pathology.

The replay PR stub refuses a `POST /pulls` whose `head` is missing or carries the `owner:branch` cross-repo form it does not model, rather than skipping materialization — a skipped branch strands the ref and resurfaces much later as the register fetch's `couldn't find remote ref`, naming neither the absent head nor the stub. Matches the fail-loud branch the same stub already uses for unsupported calls.
