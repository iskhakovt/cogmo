Conversation status guard — break the retry storm on unrecoverable failures. Migration `0020_conversation_status.sql` adds `conversation_status` enum (`active`, `errored`) and `conversations.status NOT NULL DEFAULT 'active'`. `handle-message` early-returns `{ status: "skipped", reason: "errored" }` when status is `errored`, refusing to spend more LLM calls on a known-broken conversation. New `recover-conversation` Inngest function (`retries: 0`, concurrency-locked per conversation) listens for the `conversation/errored` event emitted by PR #125's `onFailure` handler and flips the status. Catches every unrecoverable failure class — model deprecated, credentials revoked, content-moderation block, persistent provider outage, malformed tool schema, programmer bug — that would otherwise produce a retry-storm with every new inbound. New `setConversationStatus(id, status)` store method; `getConversation` now returns `status`. Tests: 3 unit tests in `recover-conversation.test.ts` (conversation-not-found / already-errored skip / first-failure marks errored); new status-guard test in `handle-message.test.ts`; 2 PGlite tests in `agent/store/store.test.ts` (default `active` round-trip, `setConversationStatus` reversibility). 1983 unit + 90 integration tests pass. **Heal-on-persist deferred** — durable repair of orphan `tool_use` rows (the original PR #125 follow-up) intentionally not in this PR. PR #125's in-memory `sanitizeHistory` already keeps every load clean for the LLM call; the only thing heal-on-persist adds is DB convergence, which is handleable with a one-off psql `DELETE` at single-user scale. Tracked as `p2` in `todo.md` to ship when there's a concrete second writer (`/repair`, MCP tool-result ingestion, evolution-stage rewrites) or after a real recurrence proves the in-memory path isn't enough.
