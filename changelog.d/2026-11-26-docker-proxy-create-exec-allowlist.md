The Docker API proxy rebuilds every container create and exec create from an allowlist, so a coding task's testcontainers or `docker compose` can't create privileged children, join another container's namespaces, mount host paths or volumes, or create them past the task's resource limits.

- **The allowlist.** Each body is parsed through Zod schemas that list the fields the proxy reads. Keys fold case-insensitively, as the daemon's Go decoder matches them. A non-ASCII key, a `__proto__`-like key, two keys that differ only in case, or a value of the wrong shape is refused with 400. A field outside the allowlist is dropped when it is zero, and refused with 403, by name, otherwise. An empty list counts as zero, except `MaskedPaths` and `ReadonlyPaths`, where `[]` would unmask the runtime's masked paths and make its read-only ones writable.
- **What's refused.** `Privileged`, `VolumesFrom`, devices, sysctls, `PidMode`, `UTSMode`, `UsernsMode`, host IPC and cgroup namespaces, `container:` network modes, every bind and named-volume mount (tmpfs only), and `SYSBOX_` variables in the create's env, the exec's env or the image's own `ENV`. `CapAdd` accepts Docker's defaults plus `IPC_LOCK`, and `SYS_NICE` only under sysbox-runc. An exec can't be privileged, whatever the container's name looks like: the exec route matches names with slashes, as the daemon does.
- **Resources.** The task's memory, pids and CPU limits are injected when a create sets none and cap it when it sets one. CPU is one quantity in either form, swap equals memory, and a negative "unlimited" value is refused.
- **The image and platform.** The proxy inspects the image and forwards its id, so the checks and the run see the same image. A missing image gets the daemon's 404, so clients pull and retry as usual, and a reference the daemon can't parse gets 400. A `platform` other than the daemon's own is refused after containerd's normalization.
- **Ports and query.** Published ports bind to the `bridge` gateway on a rootful daemon and to `127.0.0.1` on a rootless one, never to every host interface. A rootless daemon publishes through RootlessKit in the host's namespace, where the gateway isn't an address. Only `name` and `platform` are forwarded from the create query, which dockerode fills with a copy of the body. Create and exec requests on an API version below 1.44 are refused.
- **Ryuk.** Coding sessions on Local-Docker set `TESTCONTAINERS_RYUK_DISABLED=true`, since Ryuk needs a host bind of the socket. On Daytona, Ryuk stays on against the sandbox's own daemon.
- **Logs.** The proxy logs a request's path without its query, which dockerode fills with the create body's `Env`.
- **Compatibility.** Recorded creates from testcontainers-node 12.2.1 and the Docker CLI 29.9.3 pass, changed only by the injections.

On a rootless daemon, testcontainers inside a task still can't reach a child's published port; that's tracked in todo.md. `POST /containers/{id}/update` is still forwarded, so a created child's limits can be raised until slice 2's route table denies it.
