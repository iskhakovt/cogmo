`learning-loop.integration.test.ts` checks that what one conversation teaches changes what a later conversation sends to the model. It runs real `handle-message` turns and the real Observer through Inngest, on its own user and profile, against recorded fixtures and a real Hindsight. In the first conversation the agent writes a core fact to core memory, the user mentions a dinner and asks for no bullet points, and the Observer stores an inactive rule and retains the facts to Hindsight. In the second the same correction graduates the rule to active. In the third the test reads the request from llmock's journal and asserts that its system prompt carries the core-memory block under `# User`, the rule under `# Rules` and the dinner under `# Recalled Context`.

Sharing the integration tier with it takes four test-side changes. The llmock request transform adds the structured-output name to the fixture key of the Observer's correction and memory extraction, which both send the transcript as the user message. `observer.integration.test.ts` deletes and counts only its own rule, and cleans up after each test. `pipeline.integration` and `skill-authoring` bind their conversations to the profile `bootstrap()` resolves as the default instead of an unordered `profiles` row, which could be the new suite's profile. Each test file gets its own skills bare repo, so concurrent boots no longer collide in `git init --bare` or in registering the `skills` coding repo. The new test deletes the rules it learns by id in `afterAll`; its user's conversations, core memory and Hindsight bank stay until the containers go.
