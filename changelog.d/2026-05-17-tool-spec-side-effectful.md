Add an optional `sideEffectful?: boolean` field to `ToolSpec` and opt the read-only built-ins into `sideEffectful: false` (`read_file`, `list_files`, `get_current_time`, `web_search`, `web_answer`, `fetch_url`, `memory_recall`, `core_memory_read`, `list_tasks`). The field is the prerequisite metadata for the Class D loop-pathology gate described in `design/agent-resilience.md` — an iteration whose tool calls are all `sideEffectful: false` makes no observable progress, so a repeating read-only fingerprint can trip the stuck-loop detector instead of hiding behind the iteration cap.

Semantics are fail-safe: `undefined` is treated as `true` by future consumers (`spec.sideEffectful ?? true`), so any tool that doesn't opt out keeps counting as progress and never causes Class D to falsely trip. This PR ships the field and the opt-outs only — the Class D detector itself is a later PR in the rollout, and no other behavior changes here.
