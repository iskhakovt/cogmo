Settle the "Resume / Start fresh" boundary prompt to its outcome once the hold resolves, instead of leaving it as an open question.

The idle-boundary prompt — *"It's been a while since our last chat. Pick up where we left off, or start fresh?"* — lingered after resolution. A button tap dropped the keyboard but left the question text dangling; a `/new` or `/resume` during the hold left the whole prompt, buttons and all; and the waiter-timeout path (no Telegram callback runs) left a live keyboard whose buttons, once tapped, only reported "Already resolved." The user was left looking at a question that had already been answered.

`conversation/boundary/resolved` now carries the `promptMessageId` (copied off the holding row before it's deleted), and the Telegram adapter registers a listener on that event that rewrites the prompt in place to its settled outcome — *↶ Picking up where we left off.* (resume), *↶ Resuming that conversation.* (`/resume <alias>` to a different chat), *✦ Started a fresh chat.*, or *✦ No reply — started a fresh chat.* (timeout) — and strips the keyboard. Because the cleanup hangs off the resolution event rather than the channel callback, it covers every resolution path uniformly, including the timeout case that no synchronous handler can reach. The button-tap callback still drops the keyboard synchronously for an instant de-fang; the listener owns the authoritative text edit. The edit is best-effort: a deleted prompt or a rejected edit logs at warn and no-ops rather than throwing, since the resolution itself already happened.

First adopter of `ts-pattern` (already named in the stack but previously uninstalled): the outcome-text mapping uses `match(reason).…​.exhaustive()`, so a future `BoundaryResolvedReason` that isn't mapped is a compile error.

Along the way the Inngest client moved to a single top-level `AdapterDeps.inngest` instead of being smuggled through per-capability bundles, and the Direct adapter was migrated off its hard-import of the client to the same injection — its inbound body is now the standalone, directly-testable `handleDirectInbound`. No behavioural change; adapters are now uniformly dependency-injected on Inngest.
