**Durable LLM iterations — the agent loop pays for each model call once, not once per step boundary.** Inngest re-invokes the whole function at every step boundary on success, so anything expensive in the bare function body re-executes once per remaining boundary of a clean run. The streaming agent loop therefore runs each iteration inside `step.run("llm-iter<N>")`: the body drains the stream (tokens reach the delivery layer live, from inside the step), runs the Class C classifier and the non-streaming replay in-step so their verdicts cache as data rather than escaping as blind-retried throws, and returns a JSON outcome carrying the content plus an `emitted` ledger. A replay reproduces the iteration bit-for-bit — no provider call, no re-emission, an identical downstream step graph, and repair budgets the loop recomputes deterministically from cached outcomes. This is what makes a turn's model spend equal its iteration count, keeps streamed output single-copy on the user's screen, and pins the tool-call shape the executor's step plan depends on.

The other expensive or user-visible units in the streaming section are steps for the same reason: the degraded off-ramp (synthesis LLM call + retract/apology pushes) is a `degraded-reply` step, auto-recall an `auto-recall` step, and the compaction status banner lives inside the `summarize-prefix` body. The degraded-turn retraction reads the loop's `streamed` ledger — derived from durable outcomes, so identical on every invocation. Each tool-bearing iteration's `tool_result` events are pushed from their own `emit-tool-results-iter<N>` step, which keeps delivery exactly-once under every invocation pattern — the bare-body continuation after a parallel step group only runs in fully-memoized invocations, where an unguarded emission would repeat and a body-ran-gated one would never fire.

Tool durability policy: **side-effectful or billable ⇒ `durable: true`** — a non-durable handler re-executes once per remaining boundary, which for a DB-writing tool means duplicate rows and for a paid API means re-billing. Durable: `memory_recall`, `memory_retain`, `web_search`, `fetch_url`, `write_file`, `edit_file`, `core_memory_update`, `schedule_task`, `remove_task`, `activate_pipeline`, `delegate_coding`, `register_skill`, and every per-skill dynamic tool (which also gives the agent-loop skill path exactly-once semantics; the deferred idempotency key now only covers the mid-step-crash window), joining `generate_image`, `web_answer`, `memory_reflect`, `define_pipeline`, `send_document`, sub-agent tools, and MCP tools. Cheap idempotent reads (`read_file`, `list_*`) stay bare; their persisted `tool_result` is whatever the last invocation returned.
