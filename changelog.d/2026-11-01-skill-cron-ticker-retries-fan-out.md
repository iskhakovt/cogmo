The skill cron ticker retries its fan-out. `lock-and-advance` moves each due row's `next_run_at` in a memoized step and `fan-out` sends the fire events in a later one; the function now carries a retry budget, so a failed send replays against the memoized advance and the deterministic event ids (`<skillId>:<scheduledFor>`) deduplicate the re-send on the bus. Cron is not the recovery for an advanced row; the remaining residuals (a fan-out that fails every retry, an advance whose step result Inngest never records) are named in the ticker's header.
