Observer and prefix summarization now resolve their model per-conversation from the active profile, not from the bootstrap profile. The Observer's `extractionModel` override is read inside the Inngest function — a new `load-profile` step fetches `profiles` for the conversation under extraction, falls back `extractionModel ?? model`, and feeds that into `extractCorrections` / `consolidateRules` / `extractMemories` / `classifyPendingMemories`. The bootstrap-time `extractionModel` dep on `createObserver` is gone; same for `summarizationModel` on `createHandleMessage`. `handle-message`'s `load-turn-snapshot` now also returns `summarizationModel: p.summarizationModel ?? p.model`, and the prefix-summarize callback uses the snapshot value directly. The `DEFAULT_EXTRACTION_MODEL` constant in `observer.ts` (hardcoded `claude-sonnet-4-6`) is removed.

Why: a profile pointing its chat model at Haiku still paid the Sonnet rate for extraction and summarization because those models were captured once at boot from the *default* profile. The DB columns `profiles.extractionModel` / `profiles.summarizationModel` already existed (nullable, "null = use main model") but nothing read them at fire/turn time. Now both subsystems consult the conversation's actual profile.

Decision on the threading question: resolve at idle-event time inside the Observer rather than threading `profile` through `createObserver`. Observer is a single shared Inngest function — there's no per-conversation instance to thread into — and it already loads `conv` per fire, so adding one cheap profile lookup is a natural extension. The summarization side falls out of the per-turn snapshot the orchestrator already takes for `(profileId, model)` stamping.

Mid-turn / mid-conversation switches behave consistently with existing snapshot semantics: a `/profile switch` mid-turn keeps the running turn on the original `summarizationModel`; the Observer fires after idle so it always sees the latest `profiles.profile_id` for that conversation. No tests needed updating — `mockAgentStore` already returns the full profile shape (with `summarizationModel: null`, `extractionModel: null`), so the snapshot's `?? model` fallback transparently produces the same value as the dropped bootstrap dep did.
