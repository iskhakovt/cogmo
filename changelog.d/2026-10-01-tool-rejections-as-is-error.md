`generate_image`, `schedule_task`, `list_tasks`, `remove_task`, `web_search` and `web_answer` now answer every failure with an `is_error` tool_result. The handler throws its LLM-facing message and the agent loop answers with `Error: <message>`, flagged, so the model reads the same text and the rest of the turn sees a failure.

- **`generate_image`.** An aspect ratio the picked model doesn't take, an unknown model or provider, a misused or unreadable reference image, and every provider, moderation and size-canary failure reject the call. The Telegram stream handle passes over the flagged result instead of parsing it as an image payload, so it no longer logs `generate_image tool_result didn't match expected payload shape` for one.
- **Class D.** A rejected call to a side-effectful tool counts as no progress, so repeating it trips the stuck-loop detector rather than resetting it.
- **Durability.** `generate_image`, `schedule_task`, `remove_task`, `web_search` and `web_answer` are durable, so a rejection fails the call's `tool-iter<N>-<P>` step; `list_tasks` isn't, and its rejection reaches the loop directly. The turn step runner makes a failed tool step final, and a replay re-throws it at the call site with its message, where the loop flags it the same way. Probe tests against the installed Inngest SDK (4.21.0) pin all three: the step fails with `StepFailed` on its first throw, its cached rejection comes back with the message without re-running the body, and the run completes.
- **Wording.** A scheduling validation failure reads `Error: invalid schedule: …`, and a conversation without scheduling reads `Error: Scheduling is not available in this conversation.` Every other message keeps its text.
