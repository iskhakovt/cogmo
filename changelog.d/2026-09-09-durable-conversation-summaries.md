**Conversation summaries are durable now, and `/compact` produces one on demand.** Compaction used to be entirely ephemeral: the pipeline ran at turn time and the collapsed array was discarded, so the one strategy that costs an LLM call — Strategy 2, summarize the prefix at 80% of budget — re-billed the same span of conversation on every turn that crossed the threshold. Its output now goes to a new `conversation_summaries` table and is replayed instead of recomputed.

The table is an **append-only overlay**, not a rewrite: `through_message_id` names the last `messages` row a summary stands in for, and `loadTurnHistory` drops that prefix in favour of one synthetic user message. Re-compaction inserts a new row covering the previous summary plus what arrived since; the loader reads the row with the *widest* coverage rather than the last inserted, because a slow `/compact` can commit a narrower summary after a turn already stored a wider one, and ordering by insertion there would orphan the wider one and silently re-include messages it covers. The raw transcript is untouched, so the Observer still extracts facts from the complete conversation, and dropping the table restores full-history behavior with no migration. `source` records which path wrote the row (`turn` vs `manual`), which is also what makes "the system compacted for you" distinguishable from "you asked" in the audit trail.

The one guarantee durability costs is that a stored summary is never re-derived: improving `SUMMARIZATION_PROMPT` or switching `summarizationModel` no longer reaches spans already compacted. That is the deliberate trade — re-deriving would re-bill every historical span on every prompt tweak — and `design/context-management.md` now says so instead of claiming every prior property survived.

`/compact` is the manual trigger. It forces the same split the budget-triggered path would pick (`DEFAULT_KEEP_TURNS`) and runs Strategy 0 over the prefix first — count-based, so it needs no token count — but deliberately not Strategy 1, since clearing tool results would have the summarizer read placeholders instead of the output it exists to compress, and there is no budget pressure here to justify that loss. Because there is no budget gate it also carries a floor the automatic path doesn't need: below `MIN_MESSAGES_TO_COMPACT` outside the retain window it returns `too_short` rather than paying for a call to replace two turns with a paraphrase of them.

It runs synchronously on the `/reflect` model: the user is waiting on the reply, single-user scale means no concurrent fire to race, and errors reach the caller instead of a retry log. Because the driver has no retry budget behind it, its throws are converted to a `compaction_failed` Transport error rather than escaping a `Result`-returning method — an escaping rejection would skip the adapter's error branch and leave the "Compacting…" ack as the last thing the user sees. `nothing_new` also covers the case where a concurrent turn stored the same span first: the conflict arm keeps the winner's text, so reporting success would describe a summary that was discarded. Racing an in-flight turn is otherwise safe by construction — the turn froze its history inside the durable `load-history` step, and a manual compaction only ever covers a prefix of what that turn already read.

Two constraints shaped the write path. **Idempotency:** `durable: true` buys replay-safety, not exactly-once, so a crash between the commit and Inngest recording `persist-summary` re-runs the write. `(conversation_id, through_message_id)` is UNIQUE and the insert goes through `ON CONFLICT DO UPDATE` with a no-op SET — the `DO NOTHING` shape would fail deterministically for a concurrent loser under the project's REPEATABLE READ default. **Cutoff derivation:** `loadTurnHistory` returns `messageIds` positionally aligned with the messages it hands back, `null` for the synthetic entry. Strategies 0 and 1 rewrite block content in place and never change the array's length, so `messagesSummarized` indexes it directly and the cutoff is the last real id in the summarized span. When that span holds only the previous summary there is nothing to advance to and the write is skipped — re-summarizing a summary while covering nothing new is pure loss. An empty summary is likewise never stored; that path falls through to truncation and the next turn re-attempts.

`getHistory` is gone: with the turn path on `loadTurnHistory`, it and `listMessages` were the same query modulo the `id` column, and the Observer — its one remaining caller — ignores ids. `design/context-management.md` carries the durable-summaries and manual-compaction sections and no longer claims the pipeline is ephemeral end to end; `design/crash-recovery.md` gains `persist-summary` in the durability map, the reshaped `load-history` body, and a ninth replay case (cached step → no store call, with the uncached run asserted to reach it as a non-vacuity control). The background-compaction entry in `todo.md` narrows to what actually remains: moving the round trip off the critical path by triggering it after delivery, now that the storage half exists.
