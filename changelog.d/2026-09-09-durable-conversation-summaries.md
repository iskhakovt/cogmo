**Conversation summaries are durable, and `/compact` produces one on demand.** Strategy 2 — the 80%-of-budget prefix summarizer, and the one compaction strategy that costs an LLM call — writes its output to a new `conversation_summaries` table. Later turns replay that text instead of paying for the same span again. Strategies 0, 1 and 3 stay ephemeral: they rewrite or drop blocks in memory and cost nothing to redo.

The table is an **append-only overlay** on `messages`, never a rewrite. `through_message_id` names the last row a summary stands in for; `loadTurnHistory` drops every message at or before it and prepends the summary as one synthetic user message. Re-compaction appends a row covering the previous summary plus what arrived since. The raw transcript stays intact, so the Observer and the web history read see every turn — the collapse is LLM-facing only, and dropping the table restores full-history behavior with no migration. `source` records which path wrote each row (`turn` vs `manual`), so the audit trail distinguishes "the system compacted for you" from "you asked".

Reads take the row with the **widest coverage**, ordered by `through_message_id`, not the last inserted. The two orders agree while each compaction covers strictly more than the last, and diverge when a slow `/compact` commits a narrower summary after a turn has already stored a wider one — ordering by insertion there orphans the wider summary and silently re-includes messages it covers. The `(conversation_id, through_message_id)` unique index serves that sort scanned backwards, so it carries the read as well as the conflict target.

Durability has one cost worth stating plainly: a stored summary is never re-derived, so a change to `SUMMARIZATION_PROMPT` or `summarizationModel` reaches only spans compacted after it. Re-deriving would re-bill every historical span on every prompt tweak, which is the expense the table exists to remove. Deleting the affected rows re-summarizes from the transcript, which is still there.

`/compact` is the manual trigger. It takes the same split the budget-triggered path takes (`DEFAULT_KEEP_TURNS`) and runs Strategy 0 over the prefix — count-based, so it needs no token count — but deliberately not Strategy 1, since clearing tool results feeds the summarizer placeholders in place of the output it exists to compress, and no budget pressure justifies that loss here. Lacking a budget gate, it carries a floor the automatic path does not need: below `MIN_MESSAGES_TO_COMPACT` *real* messages outside the retain window it reports `too_short` rather than paying for a call that replaces two turns with a paraphrase of them. The floor counts messages, not compaction-view entries, so a re-compaction cannot clear it on the strength of the previous summary being folded in.

Execution is synchronous, the same direct-call shape `/reflect` uses — the summary itself comes from the profile's `summarizationModel`. The user is waiting on the reply, single-user scale leaves no concurrent fire to race, and errors reach the caller rather than a retry log. Since the driver has no retry budget behind it, its throws become a `compaction_failed` Transport error rather than escaping a `Result`-returning method; an escaping rejection would skip the adapter's error branch and leave the "Compacting…" ack as the last thing the user sees. `nothing_new` covers a concurrent turn winning the race, either way it can: taking the same cutoff, where the conflict arm keeps its text, or a wider one, where this row is inserted but coverage-ordered reads will never return it. Both leave a summary the user paid for that is not the one that gets used, so reporting success would promise an effect that never happens. Racing an in-flight turn is otherwise safe by construction — the turn freezes its history inside the durable `load-turn-history` step, and a manual compaction only ever covers a prefix of what that turn already read.

Two constraints shape the write path. **Idempotency:** `durable: true` buys replay-safety, not exactly-once, so a crash between the commit and Inngest recording `persist-summary` re-runs the write. `(conversation_id, through_message_id)` is UNIQUE and the insert goes through `ON CONFLICT DO UPDATE` with a no-op SET — the `DO NOTHING` shape fails deterministically for a concurrent loser under the project's REPEATABLE READ default. **Cutoff derivation:** `loadTurnHistory` returns `messageIds` positionally aligned with the messages it hands back, `null` for the synthetic entry. Strategies 0 and 1 rewrite block content in place and preserve the array's length, so `messagesSummarized` indexes it directly and the cutoff is the last real id in the summarized span; `context.test.ts` pins that length invariant, since it is load-bearing and would fail silently. A span holding only the previous summary has no cutoff to advance to and is skipped. An empty summary is never stored — that path falls through to truncation and the next turn re-attempts.

The retain window also bounds what a summary can ever cover: the split is `length - DEFAULT_KEEP_TURNS` and pair-snapping only moves it earlier, so the turn's own inbound message always sits in the retained tail. A turn that fails after `persist-summary` leaves a summary that is correct and useful for the next turn, not one that has swallowed an unanswered message. That step degrades rather than propagates — caching a summary is not worth costing the user their reply over a span the next turn would re-summarize anyway.

`getHistory` is gone — `listMessages` is the single full-history read, serving `loadTurnHistory`, the Observer, and the web chat history alike; the Observer simply ignores the ids it now also receives. `design/context-management.md` carries the durable-summaries and manual-compaction sections; `design/crash-recovery.md` carries `persist-summary` in the durability map, the `load-turn-history` step that replaces the old history read, and a ninth replay case (cached step → no store call, with the uncached run asserted to reach it as a non-vacuity control). Two follow-ups are filed rather than shipped: the summarization prefix can exceed the *summarization* model's own context window on either path, and `/compact` / `/reflect` hold grammY's sequential polling loop for the length of their LLM call.
