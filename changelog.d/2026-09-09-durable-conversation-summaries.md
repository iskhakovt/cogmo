**Conversation summaries are durable now, and `/compact` produces one on demand.** Compaction used to be entirely ephemeral: the pipeline ran at turn time and the collapsed array was discarded, so the one strategy that costs an LLM call — Strategy 2, summarize the prefix at 80% of budget — re-billed the same span of conversation on every turn that crossed the threshold. Its output now goes to a new `conversation_summaries` table and is replayed instead of recomputed.

The table is an **append-only overlay**, not a rewrite: `through_message_id` names the last `messages` row a summary stands in for, and `loadTurnHistory` drops that prefix in favour of one synthetic user message. Re-compaction inserts a new row covering the previous summary plus what arrived since; the loader reads the newest per conversation. The raw transcript is untouched, so the Observer still extracts facts from the complete conversation, and dropping the table restores full-history behavior with no migration. `source` records which path wrote the row (`turn` vs `manual`), which is also what makes "the system compacted for you" distinguishable from "you asked" in the audit trail.

`/compact` is the manual trigger. It forces the same split the budget-triggered path would pick (`DEFAULT_KEEP_TURNS`), summarizes immediately rather than waiting for pressure, and stores the result — so the next turn starts from a summary it never had to wait for. It runs synchronously on the `/reflect` model: the user is waiting on the reply, single-user scale means no concurrent fire to race, and an LLM or DB error reaches the caller instead of a retry log. Outcomes are `too_short`, `nothing_new`, `empty_summary`, or the message counts. Racing an in-flight turn is safe by construction — the turn froze its history inside the durable `load-history` step, and a manual compaction only ever covers a prefix of what that turn already read.

Two constraints shaped the write path. **Idempotency:** `durable: true` buys replay-safety, not exactly-once, so a crash between the commit and Inngest recording `persist-summary` re-runs the write. `(conversation_id, through_message_id)` is UNIQUE and the insert goes through `ON CONFLICT DO UPDATE` with a no-op SET — the `DO NOTHING` shape would fail deterministically for a concurrent loser under the project's REPEATABLE READ default. **Cutoff derivation:** `loadTurnHistory` returns `messageIds` positionally aligned with the messages it hands back, `null` for the synthetic entry. Strategies 0 and 1 rewrite block content in place and never change the array's length, so `messagesSummarized` indexes it directly and the cutoff is the last real id in the summarized span. When that span holds only the previous summary there is nothing to advance to and the write is skipped — re-summarizing a summary while covering nothing new is pure loss. An empty summary is likewise never stored; that path falls through to truncation and the next turn re-attempts.

`design/context-management.md` carries the durable-summaries and manual-compaction sections and no longer claims the pipeline is ephemeral end to end; `design/crash-recovery.md` gains `persist-summary` in the durability map, the reshaped `load-history` body, and a ninth replay case (cached step → no store call, with the uncached run asserted to reach it as a non-vacuity control). The background-compaction entry in `todo.md` narrows to what actually remains: moving the round trip off the critical path by triggering it after delivery, now that the storage half exists.
