Containers reach the in-process llmock through Testcontainers' host port forwarding: `exposeHostPort()` in `dev/containers.ts` publishes the port and returns the `host.testcontainers.internal` base URL used by the integration setup, the e2e setup and the fixture recorder.

Not `--add-host host.docker.internal:host-gateway`. Under rootless Docker that gateway sits inside RootlessKit's network namespace rather than on the host, so the connection is refused and no host-side bind helps. The sshd sidecar tunnels back to the test process instead, so no host address is involved: one path for rootful, rootless and CI, and loopback-bound listeners work as well as `0.0.0.0` ones. The mapping is injected at container create time and each container joins the forwarder's network alongside its own, so exposure precedes container creation and the user-defined network needs no extra wiring. The sidecar image is pinned in `vitest.config.ts`, the only place early enough — `SSHD_CONTAINER_IMAGE` is read into a module-level const at import time.

`claude-cli.integration.test.ts` stays on the bridge gateway and so stays rootful-only: its containers come from the sandbox supervisor via dockerode, not Testcontainers.
