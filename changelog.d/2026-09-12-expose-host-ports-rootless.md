Containers reach the in-process llmock through Testcontainers' host port forwarding. `exposeHostPort()` in `dev/containers.ts` publishes the port and returns the `host.testcontainers.internal` base URL that the integration setup, the e2e setup and the fixture recorder hand to Hindsight, Inngest and the app container.

Not `--add-host host.docker.internal:host-gateway`. Under rootless Docker `host-gateway` resolves to the default bridge's gateway *inside* RootlessKit's network namespace, which is not the host — the connection is refused, and no amount of binding on the host fixes it, because the address never leaves the namespace. Testcontainers tunnels through an sshd sidecar and remote-forwards to the test process instead, so no host address is involved: one code path covers rootful, rootless and CI, and it reaches loopback-bound listeners as well as `0.0.0.0` ones. `GenericContainer` injects the host mapping at container *create* time and joins each container to the forwarder's network alongside its own — hence the exposure happens before any container is created, and user-defined networks need no extra wiring.

`claude-cli.integration.test.ts` stays on the bridge gateway, and so stays rootful-only: its containers come from the sandbox supervisor via dockerode rather than Testcontainers, and giving the supervisor a test-only `ExtraHosts` seam would mean changing production container config for a test. Its comment says so now.
