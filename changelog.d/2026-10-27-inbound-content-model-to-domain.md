**The inbound content model lives in the domain.** `src/agent/conversation/inbound-content.ts` holds `InboundContentSchema` and its block types, `ForwardedOrigin`, the `ImageRef`/`DocumentRef`/`VoiceRef` references, `contentToBlocks`, `contentToText`, `isVoiceContent`, `renderInboundText`, `previewInboundText` and `MAX_INBOUND_FILE_BYTES`; `src/transport/content.ts` is gone. The agent's own vocabulary for what a user sent is no longer an import from the transport edge: `agent/handle-message/*`, `recall-gate`, `normalize-arrival` and the conversation store read it from `agent/conversation/`, and transport (`store/schema.ts` for the `inbound_messages.content` column, `store/index.ts` for the boundary snippet, `namespaces/sessions.ts`, the Telegram adapter) imports it the direction the architecture wants. The table stays transport's to migrate. Slice 0 of [design/operator-facade.md](../design/operator-facade.md).

Nothing is split out. `previewInboundText` is rendered by two stores (`/sessions` previews and the boundary-resume snippet), and the 20 MB cap bounds every channel's originals at arrival, so both stay with the model. Behaviour-preserving: stored shapes, event payloads, rendered text and step ids are unchanged; the module's tests moved with it, and one PGlite store test pins that `inbound_messages.content` still rejects a malformed block through `jsonbZod` now that the schema is imported across the module boundary.
