**A late reply no longer persists after a newer turn re-batched its inbounds.** A failed turn's retry can run between a younger turn's steps, and the younger turn re-reads every inbound above the last answered cursor. `create-user-message` now records the batch's first inbound on the turn row (`messages.first_inbound_message_id`, migration 0070, NULL on other rows and on older turn rows). In its insert's transaction, reading only rows newer than the reply admission found, `persist-new-messages` checks the turn's cursor: a reply with this run's final content is its own write before a retry and returns `persisted` without writing; a different reply is another run of the same batch, and a later non-pipeline turn row covering the cursor (`TranscriptStore.isCursorRebatched`) means a newer turn re-batched it. Both return `superseded` and write nothing. A superseded run reports a degraded loop (its apology already streamed), skips the cooldown event, delivery, `send-response` and `flush`, and ends `skipped: superseded`. `cogmo.agent.iterations` records once for every run whose loop ran. A `{ id }` memo from a run in flight across the deploy reads as `persisted`. Residuals, in design/observation.md → Late replies: the window before the younger turn row commits, a superseded reply that has already streamed, and a covering turn that then fails for good, after which the next turn answers the words again.
