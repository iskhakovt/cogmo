Bake the `uv` binary into the `ghcr.io/iskhakovt/cogmo-skills:<version>` runtime image and wire register-time lockfile verification: when a skill declares `dependencies`, register now spins up a short-lived sandbox session, runs `uv pip compile --generate-hashes` against the manifest, and byte-compares the result with the committed `requirements.lock`. A mismatch fails register with `requirements_lock_stale` (the author needs to re-run uv pip compile and recommit) without advancing main; resolver failures surface as `requirements_lock_resolver_failed` carrying uv's stderr. Tier-1-only deployments and test paths without a configured sandbox keep PR1's behaviour — lockfile must exist and parse, but the resolver isn't re-run. The compiler is exposed as a `LockfileCompiler` interface on `SkillRunnerOptions` so tests can swap a stub; the default sandbox-backed implementation lives in `src/skills/deps.ts` next to the existing lockfile read helpers.
