**Local-Docker coding/skill tasks: working trees are now standalone clones, fixing in-container commit+push.** Every coding and skill task on `SANDBOX_BACKEND=local-docker` died at the commit+push step with `fatal: not a git repository: <parent-gitdir-path>`: the host-side `git worktree add` produced a linked worktree whose `.git` file points at an absolute gitdir inside the parent repo, which doesn't exist inside the task container once the tree is bind-mounted at `/workspace`. Daytona never hit this because it clones a self-contained tree inside the sandbox. `allocateWorktree` now materializes a standalone clone (`git clone --no-hardlinks` from the registered parent, `git checkout -B <branch>`, `origin` repointed at `remote_url`), staged in `<path>.partial` and atomically renamed into place for crash-safe retries. A legacy linked worktree found at the path is replaced; teardown removes the clone with a plain recursive delete and prunes any leftover linked-worktree metadata in the parent repo. Cloning (rather than mounting the parent `.git` into the container) also preserves the sandbox boundary — the container never gets write access to git state that host-side git later executes — and matches the per-task self-contained-checkout pattern used by Codespaces, Gitpod, Coder, and CI agents.
