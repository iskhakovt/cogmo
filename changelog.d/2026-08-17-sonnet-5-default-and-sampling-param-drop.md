The seeded default profile targets `claude-sonnet-5` — same tier as the Sonnet 4.6 it replaces, same 1M/64k limits already in the bundled LiteLLM snapshot, identical list pricing. Only new installs see it; an existing deployment keeps whatever `profiles.model` it holds. The rest of this entry is the request surface that default exercises.

The Anthropic adapter sends no sampling parameters. `temperature`, `top_p` and `top_k` are rejected with a 400 on Opus 4.7 and later and across the 5 series, so `AnthropicProvider` strips `temperature` and logs once per model. The drop is unconditional rather than keyed on the model id, since the alternative is a table of which models accept what — the kind that goes stale silently and 400s the request when it does. `ChatParams.temperature` stays canonical and the OpenAI-compatible adapter still honours it, so the degraded-reply synthesis keeps asking for `temperature: 0` and gets it wherever sampling is supported.

It sends no `thinking` parameter either, leaving each model its own default — adaptive thinking on the 5 series. Explicit depth control belongs in `output_config.effort`, which nothing needs yet.

Thinking blocks make the round trip untouched, because the API accepts them exactly as received — empty text included — and rejects blocks that have been edited or reconstructed. So the streaming adapter reads a block's signature from its `signature_delta` event rather than from `content_block_start`, where the field is empty, and the agent loop forwards history verbatim: blanking thinking text is an edit, and stripping blocks risks ordering and signature errors. Little is lost either way, since `thinking.display` defaults to `omitted`. Server-side context editing (`clear_thinking_20251015`) is the mechanism if thinking ever creates real context pressure.

Each turn's output cap is the model's resolved `maxOutputTokens` — the same number `computeBudget` reserves when sizing the input budget, so a request can use the room compaction set aside for it. Reasoning shares that allowance, and a cap sized for reply text alone truncates the answer on a turn that thinks; `classifyPostStream` reports a truncated turn as `ok`, so it would be delivered as finished. Non-streaming calls are clamped below the SDK's client-side ceiling, above which it refuses to send at all, and sub-agent delegation refuses a truncated answer rather than passing off a partial one.

Summarization is bounded by its own model's ceiling, and an empty summary reports summarizing nothing rather than standing in for the prefix it would replace, leaving the messages to truncation. A non-positive `context_window` or `max_output_tokens` override resolves as unset: zero max-output makes every request invalid and zero context window drives the budget negative, so `addModelRouting` refuses to store one and the resolver ignores any already stored.

`skill-authoring.integration.test.ts` is disabled. The skill it authors requests `urllib.request` and declares no dependencies, placing it in tier 1, where Pyodide offers no raw sockets and no HTTP path — `design/skills.md` describes a fetch shim that `src/skills/` does not implement. Its closing assertion wants a bitcoin price the skill cannot produce; the price comes from `web_answer`, whose hardcoded `openrouter.ai` URL bypasses llmock, so every recording rides on a live third-party answer. The rest of the flow works — authored, pushed, merged, registered, invoked as a tool on the following turn — so the suite waits on a tier-1 network path rather than being deleted. `todo.md` tracks that work and the re-enable.
