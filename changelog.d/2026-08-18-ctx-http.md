Tier-1 skills reach the network through `await ctx.http.get(url)`, performed by the host.

Pyodide has no sockets, so `urllib`, `http.client` and every library built on them fail at first use inside the WASM sandbox — `design/skills.md` promised a fetch shim that nothing implemented, which made "HTTP API wrappers" the documented use for a tier that could not make a request. Routing through the host is what the `ctx` bridge already does for secrets, memory and files, and it suits Pyodide: the call is async, where patching the stdlib would mean synchronous XHR and, in Node, a process per request.

`request` / `get` / `post` return `{status, headers, body}`. A 4xx or 5xx is a value carrying that status — only failing to obtain a response raises. Requests are `http`/`https` only, so a `file:` or `data:` URL cannot turn a network call into a host filesystem read; responses are capped at 5 MiB, counted while streaming so an oversized body is abandoned rather than buffered and then measured; and a 30s default timeout (120s max) is separate from the skill's `wall_clock_s`, so a hung request is a catchable error rather than a killed task.

Every call is audited to `skill_context_calls` by origin and path. Query strings routinely carry API keys, so the query is dropped — the audit shows where a skill reached, not the credential that got it there. Egress is otherwise open, matching tier 2, which talks to the network directly through real sockets; host mediation is what makes a policy possible later, at a point skills cannot route around.

`wasm-lint` now rejects `urllib`, `http.client`, `ftplib`, `smtplib` and friends at deploy time, pointing at `ctx.http`. These are what a dependency-free skill actually reaches for, and they fail on first invocation rather than at import, so a skill using them deployed clean and broke later — the outcome the lint exists to prevent. The `raw_socket` rule's advice to "use httpx/requests" is corrected for the same reason: those need sockets too.

`skill-authoring.integration.test.ts` is re-enabled, its authored skill repointed at `ctx.http`, and its cassette re-recorded. Its closing assertion now waits for a finished `skill_runs` row with a numeric price rather than matching the reply text — the reply is a weak proxy, and it is how the suite passed for months while the skill under test errored and the agent fell back to `web_answer`.

The record path of `daytona-mock` forwarded upstream's `transfer-encoding` alongside the `content-length` it recomputes after rewriting a body, handing the SDK a response carrying both, which Node's parser rejects. Replay already filtered those headers; record now does the same and lets `res.end(buffer)` set the framing. It only bites once upstream chunks a response, which is why it read as an intermittent upstream fault.
