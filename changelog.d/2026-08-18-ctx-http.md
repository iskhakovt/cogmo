Tier-1 skills reach the network through `await ctx.http.get(url)`, performed by the host.

Pyodide has no sockets, so the stdlib modules that open a connection — `urllib.request`, `http.client`, `ftplib`, `smtplib` — have nothing underneath them inside the WASM sandbox. Routing through the host is what the `ctx` bridge already does for secrets, memory and files, and it suits Pyodide: the call is async, where patching the stdlib would need synchronous XHR and, in Node, a process per request.

`request` / `get` / `post` return `{status, headers, body}`. A 4xx or 5xx is a value carrying that status — only failing to obtain a response raises. Requests are `http`/`https` only, so a `file:` or `data:` URL cannot turn a network call into a host filesystem read. Responses cap at 5 MiB, counted while streaming so an oversized body is abandoned rather than buffered and then measured — the consumer is a WASM heap. The request deadline covers hostname resolution as well as the request itself, and is held under the skill's own `wall_clock_s`: the wall clock ends the task, where a hung request stays a catchable error. A timeout is classified apart from other transport failures, on the request and on a body that stalls mid-read.

Every call is audited to `skill_context_calls` by origin and path, dropping the query string, which routinely carries API keys — the record shows where a skill reached, not the credential that got it there.

Destinations resolving to loopback, link-local or private ranges are refused, and redirects are not followed — the 3xx returns with its `location`, so the next hop is a separately-checked call rather than a way around the check. `fetch` runs in the Cogmo server process, which can see internal services a skill should not: Hindsight sits on `HINDSIGHT_URL` and takes no auth, so reaching it directly would read or write any memory bank around the `memoryBankId` scoping and the `reads_memory` / `writes_memory` gates that govern `ctx.memory`. This is the one place tier 1 is not at parity with tier 2, whose sandbox has no route to the host's network. Names are checked by resolved address, since the interesting targets are names rather than dotted quads.

Beyond that, a destination has to be named in the manifest's `network:` block, so a skill declaring none reaches nothing. Entries are hostnames, optionally prefixed `*.` for subdomains — `*.example.com` admits `api.example.com` but not the apex, the rule TLS certificates use — and a lone `*` does not parse. Matching happens ahead of resolution, so a host the manifest never named does not become a DNS query either; the address check then judges what a permitted name points at, which is the separate question of whether a declared destination resolves inward.

The allowlist is what bounds where a credential can travel, which is why it also drives risk tiering: a skill declaring both secrets and a `network:` block never classifies `auto`, at any count. `ctx.secrets.get` returns a secret's plaintext value gated only by the manifest's own list, so reading one next to a route off the machine is the exfiltration pair — and `APPROVE_SECRETS_THRESHOLD` answers a different question, how broad a skill's permissions are, which does not bound where a secret can go. Network without secrets classifies `notify`. `design/skills.md` → *Secret exposure and egress control* carries the staged plan this is the first part of; host mediation is what leaves room for the later stages, at a point skills cannot route around.

The request timeout is held under the skill's own `wall_clock_s`, so a hung request surfaces as a catchable error instead of the worker being terminated mid-call. `ctx.http` is present in the tier-2 runtime too, so a skill does not break when declaring a dependency moves it across the tier boundary.

`wasm-lint` rejects the connection-opening stdlib modules at deploy time, pointing at `ctx.http`. The rule names `urllib.request` rather than the package: `urllib.parse` is string manipulation and `urllib.error` is exception classes, both fine in tier 1 and common in a skill that fetches through `ctx`. The `raw_socket` rule points at `ctx.http` too, since `httpx` and `requests` need sockets as much as the stdlib does.

`skill-authoring.integration.test.ts` is re-enabled with its authored skill written against `ctx.http`, and its cassette re-recorded. Its closing assertion waits for a finished `skill_runs` row carrying a numeric price, which is what proves the authored skill produced the answer — reply text alone can be satisfied by the agent's `web_answer` fallback.

`daytona-mock`'s record path filters body-bound response headers, matching what replay already does. Forwarding upstream's `transfer-encoding` alongside the `content-length` recomputed after a body rewrite hands the SDK a response carrying both, which Node's parser rejects; `res.end(buffer)` sets the framing instead.
