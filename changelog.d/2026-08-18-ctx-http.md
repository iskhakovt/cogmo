Tier-1 skills reach the network through `await ctx.http.get(url)`, performed by the host.

Pyodide has no sockets, so the stdlib modules that open a connection — `urllib.request`, `http.client`, `ftplib`, `smtplib` — have nothing underneath them inside the WASM sandbox. Routing through the host is what the `ctx` bridge already does for secrets, memory and files, and it suits Pyodide: the call is async, where patching the stdlib would need synchronous XHR and, in Node, a process per request.

`request` / `get` / `post` return `{status, headers, body}`. A 4xx or 5xx is a value carrying that status — only failing to obtain a response raises. Requests are `http`/`https` only, so a `file:` or `data:` URL cannot turn a network call into a host filesystem read. Responses cap at 5 MiB, counted while streaming so an oversized body is abandoned rather than buffered and then measured — the consumer is a WASM heap. The request deadline covers hostname resolution as well as the request itself, and is held under the skill's own `wall_clock_s`: the wall clock ends the task, where a hung request stays a catchable error. A timeout is classified apart from other transport failures, on the request and on a body that stalls mid-read.

Every call is audited to `skill_context_calls` by origin and path, dropping the query string, which routinely carries API keys — the record shows where a skill reached, not the credential that got it there.

Destinations resolving to loopback, link-local or private ranges are refused, and redirects are not followed — the 3xx returns with its `location`, so the next hop is a separately-checked call rather than a way around the check. `fetch` runs in the Cogmo server process, which can see internal services a skill should not: Hindsight sits on `HINDSIGHT_URL` and takes no auth, so reaching it directly would read or write any memory bank around the `memoryBankId` scoping and the `reads_memory` / `writes_memory` gates that govern `ctx.memory`. This is the one place tier 1 is not at parity with tier 2, whose sandbox has no route to the host's network. Names are checked by resolved address, since the interesting targets are names rather than dotted quads.

Beyond that, a destination has to be named in the manifest's `network:` block, so a skill declaring none reaches nothing. Entries are hostnames, optionally prefixed `*.` for subdomains — `*.example.com` admits any host under that zone at any depth, but not the apex, which needs its own entry — and a lone `*` does not parse. Matching happens ahead of resolution, so a host the manifest never named does not become a DNS query either; the address check then judges what a permitted name points at, which is the separate question of whether a declared destination resolves inward.

The allowlist is what bounds where a credential can travel, which is why it also drives risk tiering: a skill declaring both secrets and a `network:` block never classifies `auto`, at any count. `ctx.secrets.get` returns a secret's plaintext value gated only by the manifest's own list, so reading one next to a route off the machine is the exfiltration pair — and `APPROVE_SECRETS_THRESHOLD` answers a different question, how broad a skill's permissions are, which does not bound where a secret can go. Network without secrets classifies `notify`. `design/skills.md` → *Secret exposure and egress control* carries the staged plan this is the first part of; host mediation is what leaves room for the later stages, at a point skills cannot route around.

The request timeout is held under the skill's own `wall_clock_s`, so a hung request surfaces as a catchable error instead of the worker being terminated mid-call. `ctx.http` is present in the tier-2 runtime too, so a skill does not break when declaring a dependency moves it across the tier boundary.

`wasm-lint` runs on the register path and rejects, at deploy time, the imports tier 1 cannot run: the connection-opening stdlib modules, and `httpx` / `requests` / `urllib3` / `aiohttp` / `websockets`, all pointing at `ctx.http`. The third-party rule is what makes the authoring prompts' claim true — both tell the model these are rejected at register, and a skill reaching for `httpx` is the likeliest way to arrive at "deploys clean, fails on first invoke".

The rules match at a name position rather than anywhere on the line, so a networking module is caught wherever it sits in `import json, urllib.request`, while `import mypkg.smtplib` and the alias `from urllib import parse as request` are left alone — the imported name there is `parse`. A parenthesised name list is collapsed onto its opening line before scanning, which is the shape a formatter produces once the list grows; the newlines it occupied are re-emitted so later rules keep their line numbers. The stdlib rule names `urllib.request` rather than the package: `urllib.parse` is string manipulation and `urllib.error` is exception classes, both fine in tier 1 and common in a skill that fetches through `ctx`.

`skill-authoring.integration.test.ts` is re-enabled with its authored skill written against `ctx.http`, and its cassette re-recorded. Its closing assertion waits for a finished `skill_runs` row carrying a numeric price, which is what proves the authored skill produced the answer — reply text alone can be satisfied by the agent's `web_answer` fallback.

`daytona-mock`'s record path filters body-bound response headers, matching what replay already does. Forwarding upstream's `transfer-encoding` alongside the `content-length` recomputed after a body rewrite hands the SDK a response carrying both, which Node's parser rejects; `res.end(buffer)` sets the framing instead.

The request deadline is proportional below a 25s budget rather than a flat 5s margin under the wall clock, and the wall-clock default it sizes against is now per-tier — `DEFAULT_WALL_CLOCK_S` in `src/skills/wall-clock.ts` carries both, read by the WASM host, the sysbox worker and `ctx.http` alike. Proportionality is what keeps a short budget usable, since a flat margin consumes the whole of one; reading the tier's own default is what keeps a container skill's ceiling in step with what its supervisor actually allows.

## The staged plan behind it

`design/skills.md` → *Secret exposure and egress control* carries five stages, ordered by what actually bounds the damage.

Stage 1 is the allowlist above, plus the risk rule. Stage 2 honours the `binding` fields `SkillSecretSchema` parses but does not act on: `secrets.get` yields `cogmo-secret://<uuid>` and `#httpRequest` substitutes the real value at the `fetch`. Stage 3 pins the connection to the address the SSRF guard vetted. Stage 4 vends short-lived tokens for secrets that support exchange. Stage 5 is the proxy, for the one case the others leave.

The proxy is last, and is recorded as additive to stage 2 rather than an alternative to it — a proxy can only substitute for a placeholder the host already issued, so the `secrets.get` work is a precondition either way. The designs it would copy exist to reach inside a socket the platform does not own, and tier 1 has no socket: Pyodide cannot open one, so `ctx.http` runs `fetch` in the host process and substitution is an assignment before the call rather than a CA, a sidecar and `iptables`. Tier 2 keeps raw `httpx`, and a placeholder sent that way reaches the destination as an opaque UUID and earns a 401 — bound secrets fail closed off the host path, which makes `ctx.http` the route of least resistance instead of a rule needing enforcement. Controlling a remote sandbox's egress is therefore off the critical path, which matters because it is not something we can enforce: `design/sandbox.md` scopes policy to where it can be applied, and on managed backends that is the provider's boundary.

Stage markers: 1 through 3 `[confirmed]`, 4 `[proposed]`, 5 `[research]`.

The risk-tier table carries secrets-plus-network as its own `approve` trigger, distinct from the 3-secret breadth threshold — the count answers how broad a skill's permissions are, the pairing answers whether a skill can read a credential and also reach somewhere to send it. `classifyManifestStub` applies the same pairing rule: it cannot reach `auto` at all, but `notify` deploys live, so a degraded classifier must not be the looser path.
