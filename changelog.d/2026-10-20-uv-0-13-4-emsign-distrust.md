**The task images and CI run uv 0.13.4, whose bundled Mozilla roots drop the emSign root behind the compromised eMudhra intermediates ([GHSA-hq85-5cpj-mr62](https://github.com/astral-sh/uv/security/advisories/GHSA-hq85-5cpj-mr62)).** uv checks PyPI's certificate against roots compiled into its binary, not the system store, so only a uv release removes that trust. The pin skips the usual seven-day soak because it is the fix. `uv pip compile --generate-hashes --no-header` output is byte-identical to 0.12.23's, so committed skill lockfiles still pass the register-time byte compare.

`images/skills/.python-version` holds the skills runtime's tests on Python 3.14, the image's minor: with no interpreter installed, as on a CI runner, uv 0.13 downloads 3.15. The image build syncs against the same file with downloads off, so a base image on any other minor fails the build.
