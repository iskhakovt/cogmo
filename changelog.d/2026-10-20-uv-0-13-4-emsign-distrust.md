**The task images and CI run uv 0.13.4, whose bundled Mozilla roots drop the emSign root behind the compromised eMudhra intermediates ([GHSA-hq85-5cpj-mr62](https://github.com/advisories/GHSA-hq85-5cpj-mr62)).** uv checks PyPI's certificate against roots compiled into its binary, not the system store, so only a uv release removes that trust. The pin skips the usual seven-day soak because it is the fix. `uv pip compile --generate-hashes --no-header` output is byte-identical to 0.12.23's, so committed skill lockfiles still pass the register-time byte compare.

The Python minor is pinned wherever uv resolves. `images/skills/.python-version` holds CI's skills-runtime tests on 3.14, the image's minor, where uv 0.13 would download 3.15. The image build syncs against the same file with downloads off, so a base image on any other minor fails the build. devbase installs that minor as a uv-managed Python from bake's `SKILLS_PYTHON`, so an author's `uv pip compile` resolves on it rather than on Ubuntu's 3.12. A lockfile whose dependencies carry Python-version markers, such as `discord.py`'s `audioop-lts`, matches cogmo-skills' register-time compile.
