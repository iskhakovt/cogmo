Setup wizard and non-interactive bootstrap now collect the Daytona managed-sandbox API key. The wizard adds a Keep/Replace step that probes the key with the same `daytonaHealthProbe(daytona)` helper `DaytonaSandboxClient.healthCheck` calls (factored into `src/sandbox/daytona/probe.ts`), so the validator can't drift from the runtime probe. Validation branches on the SDK's typed errors with a `DaytonaError` base-class catch arm — rate-limit, timeout, and conflict failures surface the SDK message instead of falling through to a generic "Unexpected error", which matters when an operator iterates on `cogmo setup` and momentarily trips the per-key rate limit. Non-interactive seeds `COGMO_DAYTONA_API_KEY` (with `_FILE` variant) into the encrypted `daytona_api_key` secret on first boot. `DAYTONA_API_URL` and `DAYTONA_ORGANIZATION_ID` stay in the runtime env — they're operator config, not credentials, and both wizard and non-interactive read them from `process.env` to validate against self-hosted endpoints. Closes the gap where flipping `SANDBOX_BACKEND=daytona` after PR #173 required a hand-rolled DB write to seed the key.
