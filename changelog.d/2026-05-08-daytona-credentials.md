Setup wizard and non-interactive bootstrap now collect the Daytona managed-sandbox API key. The wizard adds a Keep/Replace step that probes the key against `daytona.list({}, 1, 1)` (the same call `DaytonaSandboxClient.healthCheck` runs, so validation fails on whatever the runtime would). Non-interactive seeds `COGMO_DAYTONA_API_KEY` (with `_FILE` variant) into the encrypted `daytona_api_key` secret on first boot. `DAYTONA_API_URL` and `DAYTONA_ORGANIZATION_ID` stay in the runtime env — they're operator config, not credentials, and both wizard and non-interactive read them from `process.env` to validate against self-hosted endpoints. Closes the gap where flipping `SANDBOX_BACKEND=daytona` after PR #173 required a hand-rolled DB write to seed the key.
