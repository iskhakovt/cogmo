**The `cogmo-skills` runtime image no longer ships the base image's pip.** Nothing in the image used it: the supervisor and every skill run in venvs without system site-packages, and uv does every install (`uv pip compile` at register, `uv venv` + `uv pip sync` at first invoke). It still put pip's vendored certifi, urllib3, msgpack and `pkg_resources` in front of Trivy, so every one of their advisories became an image alert that only a pip release could close. The latest of these was the emSign root in certifi ([GHSA-6q48-6c7w-9gw2](https://github.com/advisories/GHSA-6q48-6c7w-9gw2)). Trivy at the release scan's settings (HIGH and CRITICAL, fixed only) reports nothing for the image now; what is left is below that threshold, in uv's bundled rustls. A skill lockfile compiles byte-identically with or without pip.
