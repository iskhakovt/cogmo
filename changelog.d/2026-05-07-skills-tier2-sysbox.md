Skills Tier-2 (sysbox container) worker — first slice of P3.2. Skills declared `tier: container` now run as Python subprocesses in sysbox-managed containers via the existing `Sandbox` interface, mirroring the Tier-1 (Pyodide WASM) lifecycle: same `Dispatcher`, same `CtxHandler`, different transport. New `runOnSysboxContainer` host (`src/skills/worker-sysbox/host.ts`) ensures the image is present (`Sandbox.ensureImagePresent`, new method that lazily pulls — cheap when cached), creates a task container with no worktree and no home volume (the `recycle` isolation contract forbids state survival, and the `TaskContainerSpec.{worktreePath,homeVolumeName}` fields are now optional in `src/sandbox/index.ts`), execs `python3 -u -c <RUNNER>` with stdin attached, drives the dispatcher over a new NDJSON-over-streams transport (`src/skills/worker-sysbox/transport.ts`), and tears the container down via `stopTask` on success, failure, or the host-side wall-clock timer firing. Embedded Python runner (`src/skills/worker-sysbox/runner.py.ts`, ~3 KB) inlines the ctx SDK in plain asyncio + JSON — no Pyodide proxies — and routes `task_invoke` / `ctx_result` from stdin while writing `ctx_call` / `task_result` to stdout. Skill body is JSON-stringified into the runner source as a Python literal at the head; total source is bounded by `ARG_MAX` (rejected pre-flight at 100 KB with a typed error). `SkillRunnerImpl` accepts a new `sandbox?: Sandbox` and `tier2Image?: string` (default `python:3.14-slim`) and routes by `skill.tier`; tier-container invocations without a configured sandbox fail fast with `no sandbox is configured`. The runner reuses `DefaultCtxHandler` unchanged — `ctx.{secrets,memory,files,log,now,user}` work identically across tiers. Resource caps default to 512 MB / 1 CPU / 60 s wall-clock with manifest overrides via `resources.{memory_mb,wall_clock_s,cpu_shares}`. Wall-clock enforcement is host-side (`setTimeout` → `stopTask`), with the reaper TTL as a backstop. Tests: 6 transport unit tests (NDJSON framing, mid-line buffering, malformed-line rejection, close), 5 host unit tests with a fake sandbox (lifecycle, ctx round-trip, timeout, image-pull failure, body-too-large), one runner unit test for the no-sandbox guard, and a sysbox-gated integration test (`src/skills/runner.sysbox.integration.test.ts`) that pulls `python:3.14-slim` and validates a real ctx.now round-trip plus wall-clock kill against a real container. CI workflow `.github/workflows/sysbox-e2e.yml` now triggers on `src/skills/**` and runs the new integration test alongside the existing supervisor one. Deferred to P3.2.B: warm pool (min=1, max=3), subinterpreter-per-task isolation (PEP 734's `concurrent.interpreters` shipped in Python 3.14), worker recycle policy.
