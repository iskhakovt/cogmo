Skills run with memory scoped to a user and profile. A chat invocation runs as the turn's user through the turn's scoped `Service`: `ctx.memory.recall` honours the profile's `memoryScope` and the restricted-class exclusion, and `ctx.memory.remember` stages into `pending_memories` for the Observer. A cron fire runs as `skills.run_as_user_id` / `run_as_profile_id`, written by each deploy that puts the schedule live: the requesting conversation's user and profile, or for an approval the approver, with their own conversation's profile or else the default. The CLI and existing schedules run as the install owner with the default profile. Approving a skill deploy from Telegram records the tapper's `user_identities` row in `skill_deploys.approved_by`, which the foreign key requires.
