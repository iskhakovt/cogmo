Skills run with memory scoped to a user and profile. A chat invocation runs as the turn's user through the turn's scoped `Service`: `ctx.memory.recall` honours the profile's `memoryScope` and the restricted-class exclusion, and `ctx.memory.remember` stages into `pending_memories` for the Observer. A cron fire runs as the identity that put the schedule live: the requesting conversation's user and profile, or for an approval or `/enable` the user who acted, with their own conversation's profile or else the default. The CLI and existing live schedules run as the install owner with the default profile, and a disabled skill runs as no one. The approval prompt shows the pending version's effects and, for a scheduled skill, who it will run as. Approving a skill deploy from Telegram records the tapper's `user_identities` row, which the foreign key requires, and deleting a profile that a schedule or steering rule uses reports what to clear.
