Turn the web SPA into a real streaming chat — the frontend half of Phase 2a. After login it opens the most recent conversation (or creates one), loads its history, and streams turns over the SSE + inbound routes the backend already exposes. Built on `@assistant-ui/react`'s `ExternalStoreRuntime`: the SPA keeps its own message list, an `eventsource-client` reader folds each `StreamEvent` (text deltas, tool cards) into the in-flight assistant message, and a `convertMessage` maps to assistant-ui's shape. A per-tab id (`crypto.randomUUID`) keys the session + SSE; sending posts to `POST /api/chat/:cid` and the response streams back. New chats go through `POST /api/chat`.

The backend gains one read to back history-on-open: `Transport.conversations.getMessages` (identity- and ownership-checked) + its oRPC procedure + a lean `ChatHistoryMessage` contract (`{ id, role, text }`). Each turn is flattened to displayable prose — internal tool-roundtrip turns are dropped, and tool-call *cards* render live only; reconstructing them from history pairs with the reconnect-replay work (Phase 2b).

`@assistant-ui/react` is pinned exact (`0.14.8`) with a pnpm override forcing `@assistant-ui/core` to `0.2.5`: react@0.14.8 declares `core@^0.2.5` but imports an export core dropped by 0.2.9 — a broken peer range in this churning pre-1.0 line. The two now bump in lockstep (tracked in todo). `eventsource-client` (mature) is the SSE reader. The frontend test harness is deferred to Phase 5; the new backend read is covered (store + transport, incl. the ACL branches and the flatten/filter).
