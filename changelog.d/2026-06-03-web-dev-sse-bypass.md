Fixed the web chat under `pnpm dev`, where every message send failed with "Couldn't send your message." The Vite dev proxy can't hold a long-lived SSE connection open, so the backend saw the stream drop right after it opened and tore down the per-tab session — the next send then resolved no session and returned 409. In dev the SPA's chat `EventSource` now targets the backend directly via `VITE_SSE_BASE_URL` (`http://localhost:9090`), bypassing the proxy, and the backend answers that origin with credentialed CORS when `WEB_DEV_ALLOW_ORIGIN` is set (`scripts/dev-infra.ts` wires both for the web and server children). Only the SSE stream — a `GET`, so CSRF-exempt — goes cross-origin; the send, RPC, and login stay same-origin through the proxy, so the CSRF gate is unchanged. Production is unaffected: the SPA is served same-origin by sirv and neither variable is set, so no CORS headers are emitted.
