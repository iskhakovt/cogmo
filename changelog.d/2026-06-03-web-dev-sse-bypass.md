Under `pnpm dev`, the chat SSE stream bypasses the Vite proxy. The proxy can't hold a long-lived SSE connection open, so routing the stream through it drops the per-tab session as soon as it opens and a send then finds no session (`409`). The SPA's chat `EventSource` now targets the backend directly via `VITE_SSE_BASE_URL` (`http://localhost:9090`), and the backend answers that origin with credentialed CORS when `WEB_DEV_ALLOW_ORIGIN` is set — `scripts/dev-infra.ts` wires both for the web and server children. Only the SSE stream — a `GET`, so CSRF-exempt — goes cross-origin; the send, RPC, and login stay same-origin through the proxy, so the CSRF gate is unchanged. Production serves the SPA same-origin via sirv and sets neither variable, so no CORS headers are emitted.
