Per-turn LLM provider dispatch. The `model_providers` routing table and the `/model` picker already supported configurations like "profile A on Anthropic, profile B on xAI" — but bootstrap resolved one `LlmProvider` against the default profile's model and reused it for every turn forever, so picking a model the bootstrap provider couldn't serve silently mis-routed (Anthropic 404 on an `x-ai/grok-*` slug, etc.). New `LlmProviderResolver = (model: string) => Promise<LlmProvider>` (`src/llm/resolver.ts`) replaces the single-provider injection: `handle-message.ts` resolves immediately after `load-turn-snapshot` and threads the result into the agent loop, summarization, and `countTokens`; when `summarization_model` differs from the turn model it gets its own resolution, so the main turn can land on Anthropic while a cheap haiku summarizer rides through OpenRouter. `observer.ts` resolves once per fire against its fixed extraction model. The DB-backed resolver memoizes by model — first time a model is seen we hit `model_providers` + decrypt the secret, every subsequent turn is a `Map` lookup; transient resolution failures don't poison the cache. `BootstrapOptions.providerOverride` still accepts a single `LlmProvider` (wrapped via `constantResolver`) so integration tests don't have to change shape. Bootstrap no longer depends on the default profile's model existing at boot. `design/providers.md` "Provider dispatch" section rewritten to describe the per-turn model with the cache-invalidation policy (process-lifetime; DB changes need a restart). `mockResolver(provider?)` helper in `src/test/factories.ts`. 2112 unit tests pass.
