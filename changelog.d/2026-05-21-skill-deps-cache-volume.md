Skill virtualenvs now live on a shared persistent Docker volume mounted at `/skill-venvs`, not in each worker's container overlay. The pool passes the volume name to every worker it spawns, so a venv populated on worker A is reused by worker B without re-running `uv pip sync`, and the cache survives `recycleAfterTasks` / `recycleAfterMs` recycles. Cross-worker rename races on the same lockfile hash are race-safe via the populate script's existing `.ready` marker: the loser's `mv` fails EEXIST, confirms the winner published a complete venv, drops its own tmp dir, and exits success — no advisory lock needed. Sandbox `SessionSpec` gains a `depsCacheVolume?: DepsCacheVolumeSpec` (mirrors `homeVolume`), wired through `LocalDockerSandboxClient` (supervisor `Mounts`), the `SysboxWorkerPool` (via new `depsCacheVolumeName` option), and `SysboxSkillWorker`. Default volume name is `cogmo-skills-deps-cache`, configurable via `COGMO_SKILLS_DEPS_VOLUME`.
