**The integration tier keeps the transactor's `40001` retry, and a rootless-Docker cleanup failure is gone.**

- **Serialization retry under `RETRY_DISABLED`:** the integration and e2e tiers set `RETRY_DISABLED=true` so `withRetry` stops masking transient failures, which also switched off the transactor's `40001` retry. Tests then ran concurrent transactions without the retry production has: when several forks booted at once, every loser of the `fal_api_key` seeding race failed `bootstrap()` outright (`pipeline.integration.test.ts`, `pipeline.mcp.integration.test.ts` and `bootstrap-daytona.integration.test.ts` all hit it). `withRetry` takes `ignoreRetryDisabled`, which the transactor sets.
- **`worktree-in-container.integration.test.ts` on rootless Docker:** the cleanup chowned files written through the bind mount to the host uid from inside the container. Under rootless Docker that maps onto a subordinate uid the host user cannot delete, so `afterAll` failed with `EACCES` and left the temp dir behind. It now chowns to the mount root's owner as the container sees it.
