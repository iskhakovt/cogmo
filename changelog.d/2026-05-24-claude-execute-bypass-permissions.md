Execute-mode claude-cli invocations now pass `--permission-mode bypassPermissions`. Previously no `--permission-mode` was set, so the CLI defaulted to interactive prompts; with no `--permission-prompt-tool stdio` to answer them, every `Write` / `Edit` / `Bash` tool call silently denied itself and claude gave up after ~15 turns of permission errors. The sandbox container is the security boundary (see `design/coding-delegation.md` -> Sandbox isolation); `bypassPermissions` matches that stance. `acceptEdits` would still gate `Bash`, which the CLI routinely uses for `cat > file << EOF` writes.

Surfaced while recording the first end-to-end skill-authoring cassette: claude's PTY transcript showed it attempting `Skill update-config "add write permission to /workspace"` and finally giving up with "the system is blocking write operations and I need your explicit approval". The execute orchestrator then pushed an empty commit and verify opened a PR with no diff against main — GitHub rejected the PR open with `422 No commits between main and cogmo/<idShort>`.
