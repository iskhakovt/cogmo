Steering rules can now hold a user's standing instructions and be retired; the rule tools that write them come in a later release.

- **Schema.** Migration 0067 adds `retracted_at`, `user_id` and `quote` to `steering_rules`, with a CHECK (a retired rule is inactive, an instruction rule never learns, and only instruction rows carry a user and a quote) and a unique index allowing one live instruction per user, normalized text and scope. Existing rows are unchanged, with all three columns NULL.
- **Who sees a rule.** `# Rules` renders only the conversation user's instruction rules, and none in a third-party or unloadable profile. On equal scope and priority the newer rule is listed first. That reverses the seeded Telegram defaults and any learned rules sharing a scope, so each conversation whose `# Rules` holds such a pair opens one `configuration` epoch at its next turn. `/status` counts the rules `# Rules` renders.
- **Store.** Setting an instruction rule is idempotent on its text and scope, holds a user to 20 live instruction rules, and retires learned rules with the same text and scope. Retiring by text covers the user's instructions and learned rules visible to the profile, never an operator rule or a channel default. A review list shows live, learning and recently retired rules.
- **Retired rules stay retired.** Correction extraction doesn't list them, a reinforcement of one retired meanwhile is skipped, and a consolidation group holding one rolls back and is skipped. Consolidation now runs once the active learned rules pass 20 rather than all active rules passing 30.
