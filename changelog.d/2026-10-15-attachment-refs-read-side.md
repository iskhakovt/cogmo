Append-only step 4a: `messages.content` can hold attachment references, and every request renders them through one renderer. Nothing writes a ref yet (step 4b does), so a rollback from 4b lands here safely.

- **Stored shape.** `messages.content` is validated by `StoredMessageContentSchema` (`src/agent/stored-content.ts`): the sent `ContentBlock` without base64 `image` and `document` blocks, plus `image_ref` (the normalized object's path, type, dimensions and size, the file's name, and the original) and `document_ref`. Two harness tags join the schema for arrival's labels and placeholders, `image_label` and `attachment_placeholder`; neither makes a row the loop's, so `findUserMessageByInbound` still finds a turn row holding them. Store reads return stored messages and writes go through `toStoredMessage`, which refuses a base64 block. Rows from before keep their JSON string and render as it.
- **One renderer** (`render-stored-content.ts`) turns a ref into base64 of its write-once object through a per-process LRU memo capped at 24 MB, the largest route's attachment budget, and puts the dimensions on the rendered `ImageBlock`. An object that can never be read (a missing key, `AttachmentStore.read`'s `missing`; a failed decryption, `undecryptable`) renders as a placeholder naming the file and is counted once per process in `cogmo.attachments.placeholders{reason: "unreadable"}`; a transient read error throws so the retry renders the same request. The placeholder wording (cutoff, unreadable and the 4c rejection) is pinned and covered by the configuration digest, so this deploy opens one `configuration` epoch per conversation at its next turn.
- **Attachment limits and the cutoff.** `LlmProvider.attachmentLimits(contextWindow)`: Anthropic's API 32 MB and 100 images (600 from a 1M window), OpenAI-compatible routes and third-party Anthropic endpoints 20 MB and 100, a fallback chain the minimum. `freeze-model-limits` records them (optional in a memo) and now runs before `auto-recall`. The turn fixes its attachment cutoff from the refs' sizes before compaction: kept while the view fits the budget (request bytes less 8 MB, plus the image count), otherwise advanced oldest first, over rows that carry attachments, to within half of it, opening an epoch that stores the cutoff on `system_prompt_snapshots.attachment_cutoff` (migration 0071); later epochs carry it. Stage turns fix their own from none, stripping thinking when it advances. The size trigger's cap now follows the route's request bytes.
- **Forks.** The summarization fork, at turn time and in stages, and `/compact` render their span under the conversation's cutoff and advance their own, stripping every thinking block, where the summarization route's budget is smaller; the decision runs inside `summarize-prefix-outcome`.
- **Readers.** The Observer's transcript names refs (`[Image: name]`, `[Document: name]`), drops labels and shows placeholders as notes. The web history returns each message's `attachments` (kind, name, media type, or a placeholder's text), so an image-only message stays in it, and the chat shows them as lines after the text.
