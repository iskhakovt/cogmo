OpenTelemetry export — opt-in via standard `OTEL_EXPORTER_OTLP_ENDPOINT`. SDK is loaded as a Node `--import` hook (`dist/otel.js`) so instrumentation patches before any module resolves; with the env var unset the hook early-returns and ~10 MB of SDK + instrumentations never load. Hand-picked instrumentations only: `instrumentation-http`, `-undici` (covers Anthropic/OpenAI SDK fetches and Hindsight/Tavily/Telegram), `-pino` (auto-injects `trace_id`/`span_id` into log records). Skips the meta `auto-instrumentations-node` package and skips pg tracing (no maintained `postgres.js` integration; query overhead would dwarf span cost at our point-read pattern). Inngest's engine opens `inngest.execution` per function run via the global tracer — our domain spans parent under it via standard OTel context, no Inngest OTel middleware required. (`extendedTracesMiddleware` would also install an `InngestSpanProcessor`, but that one only activates when the function run is started with a W3C `traceparent` on the request — which would require propagating traceparent through event payloads, deferred.) Domain spans: `chat` with GenAI semantic conventions (`gen_ai.provider.name`, `request.model`, `usage.input_tokens`/`output_tokens`/`cache_read.input_tokens`/`cache_creation.input_tokens`, `response.finish_reasons`) emitted from both `AnthropicProvider` and `OpenAICompatibleProvider`, with try/finally lifecycle that handles consumer-abandoned streams; `tool.execute` with `cogmo.tool.name`/`cogmo.tool.error`; `memory.recall`/`memory.retain` with `memory.hit`/`memory.count`. Metrics surface kept narrow — `cogmo.llm.tokens` counter (labels `type`/`model`/`provider`), `cogmo.agent.iterations` histogram, `cogmo.debounce.wait_ms` histogram. Span-derivable metrics (LLM/tool latency, error rate, recall hit rate) intentionally not duplicated as counters. OTLP/protobuf over HTTP — works with Grafana LGTM all-in-one (default local recommendation), SigNoz, and Grafana Cloud without a Collector. New test harness (`src/test/otel-harness.ts`) registers in-memory trace + metric exporters before bootstrap, with a metrics-cache reset hook (`__resetMetricsForTests`) to work around `metrics.getMeter()` lacking a proxy. 4 unit tests (gen_ai attrs, cache tokens, counter labels, error span) + 1 integration test asserting span shape (`inngest.execution` parent + `chat` children) and metric labels through the live pipeline. DEPLOYMENT.md gains an Observability section with LGTM, SigNoz, and Grafana Cloud examples + sampling guidance, and a "Cross-function-run correlation" note explaining the current one-trace-per-run boundary. Testcontainers e2e image build opts into BuildKit via `.withBuildkit()` so `pnpm test:e2e` works locally without requiring a pre-built image.
