Cogmo records the skills remote's mirror state (design/skills.md → Repo location → Mirror state).

- A new singleton row, `skills_repo_mirror`, says whether the remote's `main` is `synced`, `behind` or `diverged` from local `main`. Every transaction that advances `main` (register, approve, rollback, the layout move) marks it `behind`, and every push records its result: `synced` when the push landed `main`, the cause (`unreachable`, `auth`, `timeout`) when it failed, and `diverged` when a remote `main` that local `main` does not descend from rejected it.
- The `skills-mirror-reconcile` cron pushes local `main` every 10 minutes while the remote is behind, and records `synced` again once a diverged remote's `main` matches local `main`, or `behind`, then pushes, once local `main` descends from it again. Each tick, and each boot, first catches the recorded `main` up to the real one, so a `main` that moved without being marked is still pushed. `cogmo serve` also runs one reconcile in the background at boot, so a commit the boot made reaches the remote before a draft branches from it. Without an `origin` the tick does nothing.
- `/skills` ends with the remote's lag when it is not synced.
