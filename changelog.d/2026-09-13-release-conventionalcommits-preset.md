**Releases read `!` breaking markers.** `.releaserc.json` uses the `conventionalcommits` preset for both `@semantic-release/commit-analyzer` and `@semantic-release/release-notes-generator`. A title like `feat(infra)!: …` produces a major version and a "⚠ BREAKING CHANGES" section in the release notes, as does a `BREAKING CHANGE:` footer.

- **Why the preset matters:** under the plugins' default Angular preset, the header pattern doesn't allow `!`, so such a commit doesn't parse and is dropped from both the version calculation and the notes. That is how #491 shipped in v2.10.0 as a minor. The v2.10.0 release notes now carry a breaking-change warning.
- **Pin:** `release.yml` installs `conventional-changelog-conventionalcommits@9.1.0` alongside the pinned plugins. 10.x analyses commits correctly but needs `conventional-changelog-writer@9`, which `release-notes-generator@14.1.0` doesn't ship, so notes generation fails. The two move together.
- **Verification:** run with the pinned plugin versions, `analyzeCommits` rates #491's title `null` under the old config and `major` under the new one. A `BREAKING CHANGE:` footer is `major`, `feat(pipelines)` is `minor` and `test(coding)` produces no release.
- **Docs:** `CONTRIBUTING.md` → *Release process* describes the manual dispatch of `release.yml`, its CI-green gate and `production` approval, and `publish.yml` running in the same dispatch. It drops the "Release" row from *What CI runs*. `DEPLOYMENT.md` no longer says releases happen on every push to `main`.
