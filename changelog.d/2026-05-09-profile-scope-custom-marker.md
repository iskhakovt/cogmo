`/profile scope` now marks custom compartments visually — when a profile's scope contains a custom-compartments-registered value, the show-reply and set-confirmation render it with a trailing `*` and append a `(* = custom)` legend (`compartments: work, dnd*, music* / trust: first-party (* = custom)`). Resolves the small UX gap from the hybrid-topic-registry PR (#193) where the scope output was ambiguous about which values were core enum vs. user-registered. Render goes through the canonical `formatScope` (`sessions-ux.ts`) so the marker stays consistent if other surfaces opt into it later. The `/profile list` and `/status` views are unchanged for now (they don't load the customs set; passing an undefined customs argument leaves the output bare rather than misleadingly empty). Pure additive change to `formatScope`'s second arg, no schema or wire-format change.
