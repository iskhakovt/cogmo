Skills can declare their contract as pydantic models (design/skills.md → Contracts).

- For a skill that defines `Input` or `Output` as a pydantic `BaseModel`, `run` receives `Input.model_validate(inputs)`, so defaults and coercion apply, and the result is `Output.model_validate(...).model_dump(mode="json")`. Inputs the model refuses finish the run as `input_invalid` without starting it; an output it refuses is `output_invalid`, which keeps what `run` returned when JSON carries it and it fits the result frame beside the message. An output JSON mode would change, a non-finite float or two keys written alike, is refused too. A `SkillError` raised by `run` or a model's validator is `skill_failed` or `skill_retryable`. Both tiers run one implementation, `cogmo_ctx._run.call_run`. A skill with neither model is unchanged.
- Approve refuses a lockfile that pins another pydantic, as register does; rollback restores a revision as it went live.
- `SUPERVISOR_PROTOCOL_VERSION` is 6, so the container tier needs the `cogmo-skills` image of this release.
