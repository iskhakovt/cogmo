**`fetch_url` judges the addresses it connects to, not the hostname string.** Each hop must be http(s); an IP literal is judged as written and a name by every address the injected resolver returns, through the address classification `ctx.http` uses, now in `src/util/blocked-address.ts`. Redirects are followed by hand with the same check per hop and a cap of 10. A blocked destination is refused with only the URL's host named (the resolved address goes to the log) and never falls back to Tavily; neither does a name the resolver can't resolve, after `EAI_AGAIN` and lookup timeouts are retried. A redirect loop or unreadable page still falls back to Tavily, as a bot block does. The string check missed `[::1]`, `169.254.169.254`, `127.0.0.2`, CGNAT and every public name resolving privately, and `redirect: "follow"` reached any internal address unchecked.

**The address classification closes its IPv6 gaps**: multicast (`ff00::/8`, matching the IPv4 arm's 224.0.0.0/4), the IPv4-translated form `::ffff:0:0/96`, every IPv4-compatible `::/96` address judged by its embedded IPv4, and Teredo (`2001::/32`) blocked whole. The IPv4 arm judges the third octet, so it blocks exactly the reserved 192.0.0.0/24, 192.0.2.0/24, 192.88.99.0/24, 198.51.100.0/24 and 203.0.113.0/24 rather than all of 192.0.0.0/16 and 192.88.0.0/16, which held wordpress.com and iana.org.
