Unified image-generation failure surfacing behind one typed error. Venice's response-header signals (`x-venice-is-content-violation`, `x-venice-is-blurred` when `safe_mode=false`) and 4xx responses, fal's `providerMetadata.fal.images[i].nsfw` flag, the cross-provider size canary, and openai-compat's `content_policy_violation` 4xx now all produce the same `ImageFailure` shape: `{ kind: "moderation_blocked" | "blur_unexpected" | "placeholder_size" | "provider_error", reason, provider }`. The tool handler has a single format point (`surfaceFailure`) that logs the structured failure and returns the LLM-facing `Error: ...` string regardless of which surface detected the failure.

The agent module `src/agent/image-moderation.ts` is renamed to `src/agent/image-failure.ts` — the prior name was too narrow (size canary isn't moderation; Venice's `blur_unexpected` isn't moderation). `ImageGenerationFailedError` (extends `AbortError` so `withRetry` still treats it as fatal) lives in `src/llm/image-failure.ts` as a sibling to the adapters that throw it; the agent module imports and re-exports it alongside the `detectImageFailure` inspector.

openai-compat coverage closes a gap: gpt-image-1's `content_policy_violation` 4xx previously died at the generic AbortError guard. The tool handler now matches `responseBody.includes("content_policy_violation" | "safety system")` and tags the failure `kind: "moderation_blocked"` so the LLM sees the same structured signal it gets from fal or Venice.

**Behavior change worth flagging for operators:** non-retryable 4xx errors from fal/openai-compat (previously surfaced as raw `AbortError` propagating up the agent loop) now flow through the tool handler's `.catch` and return as an `Error: ${message}` string in the tool result. The LLM sees a soft, structured failure instead of an exception. Original `APICallError` (with request URL, response body, status code) is chained as `cause` on the wrapping `ImageGenerationFailedError` for debugging. Existing fal-NSFW / size-canary / Venice flows are unchanged.

The error vocabulary (`ImageFailure`, `ImageFailureKind`, `ImageGenerationFailedError`) lives in `src/llm/image-failure.ts` — adapters throw into it, the agent imports it. Keeps the layer direction clean: `agent → llm` for runtime imports, never the reverse. The agent-side `detectImageFailure` inspector (size canary + fal-metadata read) lives in `src/agent/image-failure.ts` and re-exports the shared types so the tool handler and tests can pull everything from one place.
