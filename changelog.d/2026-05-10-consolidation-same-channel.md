Same-channel-scope consolidation in correction extraction. Closes the gap left by PR #197 (channel-scoped Observer extraction): `consolidateRules` no longer skips channel-scoped rules wholesale. Instead it groups active rules by `channelType` (with `null` keying the global bucket) and runs an independent merge pass per scope — each pass calls `chatTyped` with only its scope's rules in the prompt, then writes the merged row through `replaceRules` carrying the same `channelType` it started with. This keeps cross-scope merging structurally impossible (the LLM never sees rules from a different scope) while finally letting two similar Telegram-only rules ("avoid markdown headings here", "skip section headings on Telegram") fold into one. Addresses gemini-code-assist's review feedback on PR #197 that consolidation as written would let channel-scoped rules accumulate without bound.

`AgentStore.replaceRules` grows a required `channelType: string | null` on the `newRule` payload — a thin pass-through to the existing `steering_rules.channel_type` column. The prompt itself stays scope-agnostic: each LLM invocation is naturally narrowed to a single channel scope by the caller, so adding "the rules below are all `telegram`-scoped" wording would just be redundant noise. Per-channel `mergedGroups` and `rulesRemoved` are summed across scopes for the same return shape consolidation has always exposed; nothing downstream had to change.

Single-rule channel groups (e.g. one Telegram correction sitting alongside ten global ones) skip the LLM entirely — the existing `< 2` short-circuit now runs per scope instead of once globally, so adding the first Telegram correction never spends tokens until a second similar one arrives.

Tests: dropped the old "excludes channel-scoped rules from consolidation" guard; added "merges same-channel rules within a group" (asserts `replaceRules` is called with `channelType: "telegram"`), "consolidates global and channel-scoped rules independently in one fire" (two scopes with two mergeable rules each → 2 separate `replaceRules` calls preserving each scope), and "does not call LLM for a single-rule channel group" (one Telegram rule + two global → exactly one `chatTyped` call).
