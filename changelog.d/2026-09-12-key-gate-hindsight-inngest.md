**Hindsight and Inngest are key-gated, and boot refuses a server that isn't.** Anything that can reach an unkeyed Hindsight reads and writes every memory bank; anything that can reach an unkeyed Inngest posts `adapter/direct/inbound` (a user turn) or `coding/task/plan-approved` (a plan approval). Both now require credentials, and `cogmo serve` verifies the server enforces them.

- **Hindsight:** `HINDSIGHT_API_KEY` is a **required** env var (also `HINDSIGHT_API_KEY_FILE`). Both Hindsight clients — the class wrapper and the raw sdk client used for recall and reflect — send it as a bearer token, built in `memory/hindsight-clients.ts`. The server runs `ApiKeyTenantExtension` with the same value in `HINDSIGHT_API_TENANT_API_KEY`.
- **Inngest:** `INNGEST_EVENT_KEY` and `INNGEST_SIGNING_KEY` are required unless `INNGEST_DEV` is set, both accept `_FILE`, and the client hands them to the SDK explicitly.
- **Auth boot checks:** `checkHindsightAuth` and `checkInngestAuth` fail at once when the server answers an unauthenticated request with a 2xx, or rejects Cogmo's key. The probes leave no trace: Hindsight gets a bank list, Inngest gets `GET /v1/events` plus an empty event batch. Base-URL path prefixes and query strings are kept.
- **Where the probes run:** `checkS3Bucket`, both auth checks and `checkHindsightVersion` run from `verifyDependencies` in `bootstrap`, so `cogmo serve` and the integration harness probe them while one-shot admin CLIs neither wait on dependencies they don't touch nor need Inngest keys. `checkUuidv7` and the pure Hindsight client-version check stay in `bootstrapCore`.
- **Boot probes fail closed.** A deterministic verdict fails at once: missing or rejected credentials, an unkeyed server, a version out of range, a missing bucket, an S3 301 (bucket in another region, named from `x-amz-bucket-region`), a service URL with embedded credentials. Anything else — an unreachable dependency, a request that doesn't answer, a status that proves neither outcome, S3's transient `400 RequestTimeout` — is retried with backoff for up to 60 s per check (`BOOT_PROBE_DEADLINE_MS`), then boot fails with the last reason. Each attempt is aborted after 5 s (`BOOT_PROBE_ATTEMPT_TIMEOUT_MS`) or at the deadline, the last attempt is made close to the deadline rather than sleeping into it, and the deadline runs on a monotonic clock. The clock is injected, so the retry and timeout paths are unit-tested without waiting.
- **Nothing credential-shaped reaches the logs:** probe URLs in retry warnings and boot errors drop query strings, fragments and userinfo, and the Inngest event key is redacted. A Hindsight `/version` failure reports the underlying error message rather than an empty object.
- **Dev and test:** the Hindsight containers enforce a fixed test key, so every integration and e2e run exercises the authenticated path. `checks.integration.test.ts` pins the probe premises against the pinned images — keyed `inngest start` refuses both anonymous probes, `inngest dev` refuses neither — and `version-pins.test.ts` keeps its Inngest image equal to the dev harness's.

Keys do not cover every route. Inngest v1.41.1 serves its dashboard and GraphQL API — including the `invokeFunction` and `rerun` mutations — without auth unless started with `--no-ui`; Hindsight 0.9.1 serves `/health`, `/version`, `/metrics` and `/docs` without auth. `DEPLOYMENT.md` → *Securing internal services* covers the deployment side: `--no-ui`, private ports 8288/8289, Redis and Postgres passwords, and keys generated once.

**Breaking:** `cogmo serve` requires `HINDSIGHT_API_KEY` with a matching `ApiKeyTenantExtension` on Hindsight and, unless `INNGEST_DEV` is set, Inngest keys matching a keyed `inngest start`. A dependency that stays unreachable for 60 s fails boot instead of logging a warning.
