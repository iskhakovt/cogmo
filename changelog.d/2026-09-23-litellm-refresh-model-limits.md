**The current frontier models resolve real limits instead of a 128k guess.** The bundled LiteLLM snapshot had drifted a month behind upstream, so every model released since — `claude-opus-5-5`, `claude-fable-5-1`, `gpt-6-astra` / `-sol` / `-luna`, `grok-4.7` — missed the snapshot entirely and fell through to the resolver's conservative 128k/4k default. That boots and answers, it just compacts turns that would have fit: a 1M-context model budgeted at 128k throws away seven eighths of its window, and the only signal is one `WARN` per model id. `pnpm tsx scripts/refresh-litellm-models.ts` takes the snapshot from 2,162 to 3,012 entries and every id above now reports `litellm` in `cogmo model list`. The refresh also drops 234 entries, all of them retirements upstream (legacy Claude 3, Bedrock regional variants, dated GPT-4 previews); a profile pinned to one of those falls back to the same conservative default, and `cogmo model add --context N --max-output N` pins it explicitly.

The default org profile stays on `claude-sonnet-5`, now as an exported `DEFAULT_PROFILE_MODEL` rather than a literal, and `seed.test.ts` pins that whatever it names resolves from the snapshot instead of the fallback. A default the snapshot doesn't know breaks nothing loudly, so nothing else in the suite would catch it — the failure mode is every fresh install compacting early, forever.

A cassette is bound to the model id it was recorded with: aimock's fixture match key includes `model`, and it is enforced whenever the fixture carries one. The skill-authoring integration test and the e2e stack both routed whatever model the seed shipped, which made a product decision about the default able to turn every recorded turn into a strict-mode 503 — surfacing as a 60-second `vi.waitFor` timeout that names nothing. Both now pin `CASSETTE_CHAT_MODEL` and route that.
