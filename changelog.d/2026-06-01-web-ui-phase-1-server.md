Promote the health server into an in-process web UI server — raw `node:http`, same `:9090`, one process. It mounts `GET /health` (unchanged), a fail-closed auth gate, and an **oRPC** admin API at `/rpc/*` over the existing `Transport` namespaces. Each procedure resolves the owner server-side from the session and surfaces a `TransportError` as one typed `TRANSPORT_ERROR` the client re-narrows on `code`. The surface is read-only for now (`models.list`, `profiles.list`, and the other `list`/`get` methods); mutations append as their editing screens land.

Auth is single-user, lock-the-internet-out, with server-side sessions. `POST /api/session` exchanges a bootstrap login token — derived from `COGMO_MASTER_KEY` via HKDF and stored nowhere (`cogmo web-token` prints it) — for an `httpOnly` / `SameSite=Strict` / `__Host-` cookie carrying an opaque token whose SHA-256 hash lives in a new `web_sessions` row. The gate is an ordered strategy chain (cookie now, a trusted-identity-header strategy later), fail-closed; `DELETE /api/session` deletes the row. CSRF rides SameSite + strict `application/json` content-type + an `Origin` / `Sec-Fetch-Site` check, no token. Bind is `WEB_HOST` / `WEB_PORT` (default `0.0.0.0:9090`; set `WEB_HOST=127.0.0.1` bare-metal). A `web` channel (fixed identity, wildcard owner) is seeded at boot so the oRPC layer scopes its Transport to it. The minimal SPA that completes the acceptance demo follows in a second PR.
