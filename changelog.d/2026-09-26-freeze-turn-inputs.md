Each turn's voice decision and tool table are frozen in a `freeze-turn-inputs` step, in chat and pipeline stage turns alike. Both came from reads that can change or fail between Inngest invocations of the same turn: the profile, the delivery handle, and the image, skill, sub-agent and MCP catalogs, where `buildSkillTools` returns `[]` on a list failure. So a later iteration could send different `tools`, or skip a voice reply its prompt was assembled for. The step returns the tool table as JSON text and every invocation parses it, because the Inngest server hands memoized objects back with their keys sorted. Live handlers are bound to the frozen table each invocation, and a call to a frozen tool whose handler didn't load gets an `is_error` result. Replay tests cover a skill that stops loading mid-turn, voice switched off mid-turn, and a cached table with re-sorted keys.
