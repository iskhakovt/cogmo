Each chat turn's voice decision and batch-delivery decision, and the tool table of chat and stage turns alike, are frozen in a `freeze-turn-inputs` step, so every iteration of a turn sends the same `tools`, delivers the voice reply its prompt was assembled for, and plans the same steps. They come from reads that can change or fail between Inngest invocations of the same turn: the profile, the voice config, the delivery handle's sessions, and the image, skill, sub-agent and MCP catalogs, where `buildSkillTools` returns `[]` on a list failure. The step returns the tool table as JSON text that every invocation parses, since the Inngest server hands memoized objects back with their keys sorted. Each invocation binds its live handlers to the frozen table; a call to a frozen tool whose handler isn't loaded gets an `is_error` result. `voice-delivery` and `batch-delivery` are gated on the frozen decisions and re-check the live capability inside their bodies. Replay tests cover a skill that stops loading mid-turn, voice switched off mid-turn, batch targets appearing or disappearing between invocations, and a replay from the server's key-sorted copy of the step result.
