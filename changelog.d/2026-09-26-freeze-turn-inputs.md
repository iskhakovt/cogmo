Each turn's voice decision and tool table are frozen in a `freeze-turn-inputs` step, in chat and pipeline stage turns alike, so every iteration of a turn sends the same `tools` and delivers the voice reply its prompt was assembled for. Both come from reads that can change or fail between Inngest invocations of the same turn: the profile, the delivery handle, and the image, skill, sub-agent and MCP catalogs, where `buildSkillTools` returns `[]` on a list failure. The step returns the tool table as JSON text that every invocation parses, since the Inngest server hands memoized objects back with their keys sorted. Each invocation binds its live handlers to the frozen table; a call to a frozen tool whose handler isn't loaded gets an `is_error` result. Replay tests cover a skill that stops loading mid-turn, voice switched off mid-turn, and a replay from the server's key-sorted copy of the step result.
