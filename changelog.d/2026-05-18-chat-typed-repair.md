`chatTyped` now grows a `repair` option that bundles three pieces of recovery behavior the evolution background jobs and other out-of-loop callsites need from structured-output calls: a `jsonrepair` pre-pass on the parsed text (default on), a feedback-injection retry on Zod validation failure with a tunable budget (default `maxRetries: 1`), and an `onZodFailure: "throw" | "feedback"` knob for callsites that prefer a hard failure to a re-prompt. The pre-pass delegates to `parseProviderJson` from `src/llm/errors.ts`, so a trailing comma or other recoverable malformation is fixed deterministically without consuming a retry; an irrecoverable parse failure surfaces as `ProviderProtocolError` instead of a bare `SyntaxError`.

The Zod-failure retry budget is tightened from the previous unconditional `maxRetries: 2` (legacy top-level option) to `repair.maxRetries: 1` — half the prior budget. The `jsonrepair` pre-pass closes most of the gap by handling parse failures deterministically without consuming the budget; only true Zod-shape mismatches now cost a retry.

The four evolution callsites — `drain-pending-memories`, `extract-corrections`, `extract-memories`, `consolidate-rules` — now pass `repair: {}` to opt in explicitly with the defaults. The legacy top-level `maxRetries` option is replaced by `repair.maxRetries`; the retry now distinguishes JSON-parse failures (deterministic repair, no retry) from Zod-validation failures (feedback retry).

Out-of-loop repair semantics differ from the in-loop Class C repair documented in `design/agent-resilience.md`: budget is per-call (per callsite, not per turn), exhausted retries throw to the caller (no `conversation/degraded` event — there is no user-facing conversation on these surfaces), synthetic feedback turns are fully ephemeral, and no `turnLogger` is threaded through. The shared repair *logic* is what's reused; the budgeting and off-ramp are intentionally different.
