Sandbox design doc reshaped around a `SandboxClient` / `SandboxSession` split mirroring the OpenAI Agents SDK shape, with discriminated `SandboxClientOptions` / `SandboxSessionState`, a `SandboxCapabilities` flag set, and an explicit per-backend matrix. Two backends documented end-to-end: Local-Docker (existing topology, proxy, reaper, cgroup parent — all rescoped under one heading) and Daytona (managed cloud default, self-hosted via `DAYTONA_API_URL`, working-tree transport via ephemeral GitHub branch with `sandbox.git.clone`/`push`, streaming exec via the non-PTY session-logs WebSocket wrapped behind `stdbuf -oL -eL` to defeat claude-code's stdout block-buffering, askpass via `fs.uploadFiles` with `0600` perms). Backend selection at deploy time via `SANDBOX_BACKEND` env. `ensureImagePresent` and worktree-less sessions surface in the abstraction so skills tier-2 (no worktree, no home volume) and coding-delegation (worktree + home volume) share one interface. Reference Implementations split into Abstraction / Local-Docker / Daytona subsections. Module structure shows `src/sandbox/clients/{local-docker,daytona}/` in-tree.
