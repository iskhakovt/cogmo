Release images (`cogmo`, `cogmo-devbase`, `cogmo-skills`) are built with `no-cache` in `publish.yml`. The Dockerfiles pin base images by digest, so the `apt-get upgrade` RUN line never changes its cache key; with the GHA layer cache (`mode=max`) it replayed whatever package set it first saw. The release scan flagged CVE-2026-13221 (Perl regex trie overflow, critical) in `cogmo` and `cogmo-skills` at perl `5.40.1-6`, while `trixie-security` already carries the fixed `5.40.1-6+deb13u1`; the release logs show that upgrade step as `CACHED`. A cacheless release re-runs every unpinned fetch (apt, NodeSource) against the current archives. `cache-to` still exports, so PR and e2e builds reuse the fresh layers.

Verified locally: a fresh `skills` build installs `perl-base 5.40.1-6+deb13u1`. The Trivy alerts close on the next release scan.
