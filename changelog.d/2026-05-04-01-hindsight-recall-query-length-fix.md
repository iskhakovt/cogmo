Hindsight recall query length fix (issue #120). `HindsightMemoryProvider` truncates queries to a configurable token budget (cl100k_base, matching Hindsight's server-side tokenizer) before the network call; new `HINDSIGHT_RECALL_MAX_QUERY_TOKENS` env var (default 500, mirrors the upstream `HINDSIGHT_API_RECALL_MAX_QUERY_TOKENS` default) lets deployers raise both caps in lockstep. `HindsightError` 4xx responses surface as `AbortError` so `withRetry` no longer burns its budget on deterministic failures. Auto-recall in `handle-message` wraps the call with a `memories: []` fallback + warn log — a Hindsight failure no longer aborts the turn or wedges the Inngest queue on poison messages. Unit tests cover truncation, short-query passthrough, 4xx no-retry, 5xx retry. DEPLOYMENT.md documents the new env var.
