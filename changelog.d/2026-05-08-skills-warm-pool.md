Skills tier-2 warm pool (P3.2.B.1). Replaces P3.2.A's spawn-per-task lifecycle (`runOnSysboxContainer` creates → execs `python3 -c <RUNNER>` → tears down per invocation, ~1-2s cold) with a pool of long-lived sysbox containers reused across skill invocations. Steady-state cost drops to ~300ms per task — the cost of a fresh `python3 -u -c <RUNNER>` exec on a warm container, no image-pull or container-create on the hot path.

New code in `src/skills/worker-sysbox/`: `pool.ts` (`SysboxWorkerPool`) holds a list of workers tracked by `idle / busy / draining / disposed`, scales between `min=1` and `max=3` on demand, recycles after 500 tasks or 24 h age, sweeps idle workers above `min` after 30 min, and tears everything down on `dispose()`. `worker.ts` (`SysboxSkillWorker`) wraps one long-lived `SandboxSession` and runs tasks via the existing dispatcher. `host.ts` is split: `runTaskOnSession(session, params)` is the per-task helper (drives the dispatcher over a fresh `python -c` exec on a pre-existing session) — the pool path calls this directly; `runOnSysboxContainer` stays as the create-then-run-then-destroy one-shot path used when a skill declares `resources.{cpu_shares,memory_mb}` overrides (the pool runs every worker at the default budget, so per-skill resource declarations bypass the warm pool — rare).

Per-task isolation comes from spawning a fresh python process inside the warm container — no long-lived python loop in v1, so module-level state, `sys.modules`, and threading state can't leak across tasks. The `recycleAfterTasks` policy bounds drift in the shared container (tmpfs growth, kernel state) independent of per-task python-process restart. Wall-clock kills mark the worker non-reusable: the safe response is recycle, not reuse — in-flight subprocesses inside the killed container's namespace aren't guaranteed to die just from the python parent exiting. Subinterpreter-per-task (PEP 734, ~50ms) is the deferred v2 (P3.2.B.2) — the `isolation: subinterpreter | recycle` enum is already in the manifest schema; v1 ignores it.

`SkillRunnerImpl.create` now eagerly stands the pool up when a sandbox is wired, so the first user-driven invocation is warm. Pool spawn failures surface at boot (clear signal for misconfig — bad image, sandbox unreachable) instead of being deferred to first invoke. New `runner.shutdown()` tears the pool down — bootstrap callers wire it into graceful-shutdown when SIGTERM handling lands; until then the sandbox reaper is the backstop (worker `expiresAt` set to the recycle ceiling + 1 h margin).

12 unit tests in `pool.test.ts` cover lifecycle invariants (eager `min` spawn, `max` ceiling under concurrent load, queue-and-handover at `max`, recycle on task-cap and on non-reusable-result, idle sweep with `min` floor, dispose rejecting queued waiters, idempotent dispose, post-dispose invoke errors, sync exception path). One new sysbox-e2e assertion in `runner.sysbox.integration.test.ts` registers a hostname-returning skill and asserts two sequential invocations report the same container short ID — proves pool reuse against a real sysbox container. Closes the `Later` `p2 Skills P3.2.B` line item.
