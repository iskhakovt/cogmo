Coding-delegation containers now receive the user's Claude Code subscription via `CLAUDE_CODE_OAUTH_TOKEN`, sourced from a new `claude_code_oauth_token` entry in the encrypted secrets table and injected at container create time through a new `env` field on `SessionSpec`. Setup wizard prompts for the token (output of `claude setup-token`) on first run and on rotation; non-interactive bootstrap reads `COGMO_CLAUDE_CODE_OAUTH_TOKEN` (with `_FILE` variant). The plan/execute and verify orchestrators fetch the token before `sandbox.create` so a missing secret fails fast at task start with an actionable message rather than letting `claude -p` hang on an OAuth prompt inside the headless sandbox. Token never lands on the per-task home volume — process env only. See `design/coding-delegation.md` → Subscription Auth.
