**Hindsight 0.10.1.** The npm client, the dev and test image pins (`ghcr.io/vectorize-io/hindsight-api:0.10.1`, full and `-slim`) and `cogmo.hindsightCompat` (`>=0.10.0 <0.11.0`) move together. Cogmo refuses to boot against a server outside that range, so production Hindsight upgrades alongside it. The release's own breaking changes (the retired bank profile and background endpoints, metadata-only mental-model lists, the dropped `count_chunks` extension hook) touch nothing Cogmo calls. Two server behaviours do reach recall, and `HindsightMemoryProvider` adapts to both:

- **Recall queries are truncated in `o200k_base`.** Hindsight counts the recall query cap in `o200k_base` and answers an over-cap query with a 400 rather than truncating it. A cut made in `cl100k_base` overshoots the cap on ordinary prose and code: on this repo's own design docs, over a third of 500-token cuts measure above 500. The resulting 400 would leave auto-recall empty for exactly the long messages that carry the most context. `HINDSIGHT_RECALL_MAX_QUERY_TOKENS` is counted in `o200k_base`, and the server's `HINDSIGHT_API_TOKENIZER_ENCODING` has to stay at that default.
- **A bank that was never created recalls as empty.** Hindsight creates a bank on its first write and answers recall on a missing one with a 404. With one bank per user, that covers every user with nothing retained yet, and treating the 404 as a failure would log an auto-recall failure on every turn of their first conversation and hand `memory_recall` an error. The adapter maps the 404 to no memories only when its detail is exactly `Bank '<id>' not found`, so any other 404 (a wrong base path, a gateway echoing the request path) still fails. The migration CLIs keep the 404 for an explicitly named bank. Integration tests pin both behaviours against the real server.

Hindsight retries a remote reranker, up to three times within a 10s budget, before failing over. Against production's 2s OpenRouter timeout, a dead primary would add about 11s to every turn. The production config in `design/memory.md` sets `HINDSIGHT_API_RERANKER_MAX_RETRIES=0`, which holds the cost at one timeout before `rrf` answers. The API images ship without `curl` or `wget`, so `DEPLOYMENT.md` gives a Python healthcheck. The API key covers everything except `/health`, `/version`, `/metrics`, `/docs` and `/openapi.json`.

In the test stack, Hindsight sends one text per embeddings request (`HINDSIGHT_API_EMBEDDINGS_OPENAI_BATCH_SIZE=1`). It coalesces a retain's concurrent embedding calls by timing, and llmock's key for a shared request depends on which facts share it and in what order, so batched requests replayed only when the grouping repeated the recording's. The recorded fixtures drop 41 that nothing can request any more: 27 extraction calls in the 0.9 prompt wording, 8 consolidation calls whose keys embed a wall-clock `mentioned_at` timestamp the replay normalizer leaves in place, and 6 embeddings of facts and queries that neither a test nor a remaining extraction fixture produces.
