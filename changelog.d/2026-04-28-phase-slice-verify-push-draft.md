Phase 6 P1 slice 4 (P1.5) — verify + push + draft PR. New `coding-task-verify` Inngest function triggered by `coding/task/cli-done` (emitted by execute orchestrator on the durable `pending_verify` transition) drives `runVerifyStreaming` → `runCommitAndPush` → `runOpenDraftPr` with durable `step.run` boundaries; status flows `pending_verify → verifying → pushed → pr_open`, four new events (`coding/task/cli-done`, `coding/task/verify-complete`, `coding/task/pushed`, `coding/task/pr-opened`). Schema: `coding_repos.identity_name TEXT NOT NULL DEFAULT 'default'` (selects which `github_identity:<name>` row in the secrets table this repo uses) + `verify_timeout_seconds INT NOT NULL DEFAULT 600` (wall-clock cap separate from the CLI's `task_wall_time_seconds`); `coding_tasks.pr_url TEXT` replaced with `coding_tasks.pr_metadata JSONB` carrying `{url, number, branchSha, openedAt}` validated by `PrMetadataSchema` — atomic-by-Zod, no half-recorded state. New `src/secrets/github.ts`: `GitHubIdentitySchema` validates `{pat, sshPrivateKey, sshPublicKey}` JSON bundles stored under `github_identity:<name>`; PAT and SSH key for a single bot account are inseparable so they live in one JSONB blob (CLAUDE.md atomic-cluster rule); `resolveGitHubIdentity` returns a `Result` discriminating `missing` / `malformed_json` / `schema_mismatch`. Per-repo override via `coding_repos.identity_name` does NOT fall back to `default` — typos fail loudly rather than authoring PRs under the wrong account. Setup wizard's GitHub step (interactive + non-interactive paths) prompts for the PAT, validates against `GET https://api.github.com/user`, generates an Ed25519 SSH signing keypair via `micro-key-producer/ssh.js` (Paul Miller, MIT, same noble family as `@noble/ciphers`/`@noble/hashes`) which returns OpenSSH-armored `privateKey`/`publicKey`/SHA256 `fingerprint` ready for `git config gpg.format=ssh -c user.signingkey=<path>`; prints the public key + `https://github.com/settings/ssh/new` link telling the operator to install it as a *signing key* (not authentication). Re-runnable: existing identity offers Keep / Replace PAT (re-uses key) / Regenerate. Non-interactive accepts `COGMO_GITHUB_PAT` (with `_FILE` variant) and optional `COGMO_GITHUB_SSH_PRIVATE_KEY` (currently warns and regenerates — extracting the public key from an arbitrary OpenSSH blob without ssh-keygen on the host needs a parser worth a follow-up). New `Transport.repos.cloneAndAdd({name, remoteUrl})` + Telegram `/repo add` FSM dialog (3 steps — name → remoteUrl → confirm) clones the remote into `${COGMO_REPOS_DIR}/${name}` using the default identity's PAT through a one-shot host-side `GIT_ASKPASS` helper; positional `/repo add <name> <path> <url>` form stays for scripting / pre-cloned repos. New `src/secrets/git-askpass.ts → withGitAskpass(pat, fn)` materialises a per-invocation tempdir with a 0700 helper script + 0600 secret file, runs `fn`, removes the tempdir unconditionally on return — even if `fn` throws; `runGit(args, env, opts)` spawns git with `GIT_TERMINAL_PROMPT=0` so missing auth fails fast. New `src/sandbox/askpass.ts → provisionAskpass({baseDir, rootTaskId, identity})` writes `helper`/`pat`/`signing-key`/`signing-key.pub` under `${SANDBOX_ASKPASS_DIR}/<rootTaskId>/` (default `/run/cogmo/askpass`), bind-mounted read-only at `/.cogmo-askpass/` inside the task container; `LocalInProcessSandbox.stopTask` calls `cleanupAskpass` in its `try/finally` so partial provisioning is recovered even when the cascade kill panics. Commit + push (`src/agent/coding/commit-push.ts`): `git status --porcelain` decides whether to commit (clean tree = idempotent retry-skip), commit via per-invocation `git -c gpg.format=ssh -c user.signingkey=<path> -c user.email=cogmo-bot@noreply -c user.name="Cogmo Bot" commit -S -m <goal>` (no global config), `git push origin cogmo/<idShort>`. Discriminated outcomes: `pushed` (with commit SHA via `rev-parse HEAD`), `nothing_to_commit`, `branch_conflict` (rejected / non-fast-forward), `auth_failed` (PAT/ssh deny), `failed`. Draft PR (`src/agent/coding/draft-pr.ts`): `octokit.pulls.create({draft:true})` from `@octokit/rest` v22; title = `task.goal` collapsed to one line + truncated 70 chars with ellipsis; body = `## Plan\n\n<plan>\n\n## Verify output\n\n` + fenced verify output + `_Generated by Cogmo_` (empty plan/output get `_(no plan recorded)_` / `_(no output)_` placeholders); discriminated by `RequestError.status` — 401/403 → `auth_failed`, 422 → `validation_failed` (PR already exists / head sha missing), other → `failed`. `parseRemoteUrl` accepts `git@host:owner/repo(.git)?`, `https://host/owner/repo(.git)?`, `ssh://...` and returns null for anything else. New runtime deps: `@octokit/rest@22` + `@octokit/request-error@7` + `micro-key-producer@^0.8.6` (drops the planned `gh` CLI from devbase image — one less binary, one less auth surface).
