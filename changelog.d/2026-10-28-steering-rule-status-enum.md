A steering rule's lifecycle is the pgEnum `steering_rules.status` — `live`, `learning`, `disabled`, `retired` — rather than an `active` flag read together with `retracted_at` and `source`. The state machine is in `design/evolution.md` → Explicit Instructions → Lifecycle: the transition table, and a failure-mode table covering a switch against a graduation, retiring a retired rule, a retirement during a merge, the backfill and a run across the deploy. `chk_steering_rules_lifecycle` holds each status to its sources (a learned rule is live, learning or retired; an operator's rule or a channel default is live, disabled or retired; an instruction is live or retired) and `retracted_at` to the retired status, so a source change can no longer re-read a disabled operator rule as a learning one. A retired row records why in `retired_reason` (`contradicted`, `superseded`, `removed_by_user`; `unknown` for rows the migration finds retired without a contradiction record), and a live rule carries no contradiction record: graduation clears it and the CHECK refuses it. One migration, `steering_rule_status`, in one transaction: the two types and columns, the backfills from `(active, retracted_at, source)` and the contradiction record, `SET NOT NULL`, `uq_steering_rules_instruction` rebuilt on `status = 'live'`, `DROP COLUMN active` and the CHECK — a row the CHECK refuses rolls the file back.

In the store every read filters on `status`; a reinforcement is one UPDATE that graduates a learning rule and reports it from the returned row, and `upsertCorrection` answers `inserted`, `reinforced`, `promoted` or `stale`, so a reinforcement of a live `evolution` row whose count crosses 2 no longer reports a promotion and one of a disabled operator rule writes nothing. `countLiveLearnedRules` replaces `countActiveLearnedRules`. `RuleMatch`, `ReviewedRule` and `ExtractionRule` carry `status`; `listRules` leaves a disabled rule out, as before. The migration test runs the file over every `(active, retracted_at, source)` combination and the rollback of a row it can't place; the store test pins the two behaviours the status fixes.
