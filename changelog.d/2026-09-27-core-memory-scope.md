Core memory is scoped by profile class (design/memory.md → Core Memory Scope by Profile Class). A shared `identity` block holds name, what to call the user, home, timezone and languages; every other block belongs to the writing profile's class, or to an unclassed bucket, and a classed persona sees only `identity` and its class's blocks. A restricted class's `identity` write becomes its own override, holding only the lines that differ, and the reply says so. Third-party profiles get no core memory or core-memory tools. The Service routes each write by its key and the turn's scope, frozen in a `freeze-core-memory-scope` step, so `core_memory_update` takes no scope argument. Migration `0060_core_memory_scope` adds `core_memory_blocks.profile_class`; `/classes rm` and `/classes unrestrict` need `confirm` to delete blocks.

The routing eval adds classed, restricted and legacy states; routing holds wherever blocks exist.
