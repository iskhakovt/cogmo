Core memory is scoped by profile class. An `identity` block (name, what to call the user, home, timezone, languages) is shared by every persona; every other block belongs to the writing profile's class, or to an unclassed bucket for profiles without one, so a classed persona never sees the unclassed bucket or another class's blocks. In a restricted class an `identity` write becomes the class's own override, storing only the lines that differ from the shared block, and the reply says it is saved only there. Third-party profiles get no core memory, onboarding or core-memory tools. The Service resolves each write from the key and a scope frozen per turn in a `freeze-core-memory-scope` step, and `core_memory_update` keeps one schema. Migration `0060_core_memory_scope` adds `core_memory_blocks.profile_class`. `/classes rm` and `/classes unrestrict` list the blocks they would delete and need `confirm`, and a confirmed unrestrict names the override it deleted; an unrestricted class never renders an `identity` of its own.

The routing eval adds classed, restricted and legacy states. Routing holds wherever blocks exist. With none, onboarding says to save a fact without waiting to learn the rest, since the `identity` routing lines alone held the agent off until it knew the user's name (31 of 33 core facts saved with the line, 16 without).
