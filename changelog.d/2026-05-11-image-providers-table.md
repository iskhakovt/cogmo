Image generation gains a user-configurable provider and model catalog. Two new tables — `image_providers` (with `pgEnum` `image_provider_type` ∈ {`fal`, `openai_compatible`}, CHECK-enforced `base_url` invariant: `openai_compatible ↔ NOT NULL`, `fal ↔ NULL`) and `image_models` (LLM-facing `name`, API-facing `model_string`, `description`, `capabilities JSONB`, `user_selectable`) — replace the hardcoded `MODEL_CATALOG`. `llm_providers.type` is converted to the matching `llm_provider_type` `pgEnum` in the same migration for symmetry; `switch(row.type)` in `buildProvider` can now go exhaustive without `assertNever`.

Per-model capabilities (currently `aspectRatios`, `seed`) are validated by `ImageModelCapabilitiesSchema` at the store boundary on read and write. The tool description lists supported ratios per model; the handler narrows the LLM's pick per model and returns text errors the LLM can act on. The Zod `aspectRatio` enum is the **union** of supported ratios across all user-selectable models — a fixed-size model doesn't collapse every other model's options.

Adding Venice (or any OpenAI-shaped image endpoint) becomes a wizard flow: add an `image_providers` row with `type = openai_compatible` and a validated `base_url`, then add `image_models` rows pointing at it. The fal default catalog is seeded idempotently after a `fal_api_key` secret exists; re-running preserves operator edits. Tool catalog is restart-only — hot-reload tracked as p3 alongside the LLM resolver and voice config equivalents.

Design doc `design/image-generation.md` flipped to `[confirmed]` for the providers, tool definition, and configuration sections. `design/providers.md` and `design/data-model.md` reflect the enum and new tables.
