Phase 6 P1 slice 3 — tool gate + Docker proxy + reaper + cgroup parent. Three new tables in migration 0012: `networks`, `volumes` (same lineage shape as `containers` — `parent_id` → containers, `root_task_id`, `depth`, `instance_id`, labels JSONB, ttl), and `coding_tool_decisions` (per-task permission decision log: `tool`, `pattern`, `decision`, `scope`). Pure in-process policy table (`src/agent/coding/policy.ts`) classifies tool calls under a default-broad-allow stance — file ops anywhere, read-only Bash, test/build/lint/format, package installs, local docker, in-container `rm` all auto-allow; narrow prompt set covers external state changes only (`git push`, `gh pr create/merge/review/close/edit/comment/ready/reopen`, `gh issue` mutations, `gh release/repo create/delete/edit`, `npm/pnpm/yarn publish | unpublish`, `cargo publish | yank`, `uv publish`, `twine upload | publish`, HTTP writes via `curl`/`wget` to non-localhost). Compound commands prompt if ANY sub-command is in the prompt set (worst-case wins). 90 unit tests cover happy paths, IPv6 localhost, quoted curl flags, weird input. `ClaudeCodeBackend.execute` drops `--permission-mode acceptEdits` and routes every tool call through Claude Code's stream-json control protocol — `control_request` events with `subtype: can_use_tool` arrive on stdout, the orchestrator writes `control_response` back on stdin. New `CodingExecuteHandle` returned by `execute(ctx, sessionId)` exposes `events: AsyncIterable<CodingEvent>` + `respondPermission(requestId, response): Promise<void>`. Handle is idempotent on duplicate respondPermission calls. New Docker socket proxy in `src/sandbox/proxy/` — `CogmoSocketProxy` listens on per-task Unix sockets at `/run/cogmo/sockets/<task-id>.sock`, classifies endpoints via pure `router.classify(method, path)` (deny `/swarm/*` `/plugins/*` `/nodes/*` wholesale, policy on `POST /containers/create`, hijack `/exec/{id}/start` `/containers/{id}/attach` `/events` `/build` `/session` `/containers/{id}/logs`, forward everything else), policy mutates the create body (deny `Privileged=true` / `NetworkMode=host` / host-path binds / dangerous caps SYS_ADMIN/NET_ADMIN/SYS_PTRACE/SYS_MODULE/SYS_BOOT/SYS_RAWIO/MAC_ADMIN/MAC_OVERRIDE; inject `Runtime` + `CgroupParent` + Cogmo labels). Single shared `http.Server`; one tiny `net.Server` per task socket tags accepted connections via WeakMap and hands them to the HTTP server. Hijacked / upgraded requests open a fresh upstream `net` connection, replay the request preamble, and pipe both directions raw (covers buildx `Upgrade: tcp` → HTTP/2 without speaking HTTP/2). 30 unit tests via two real Unix sockets (proxy task socket → fake upstream daemon socket). Supervisor wires the proxy into `LocalInProcessSandbox.createTaskContainer` — allocates a per-task socket BEFORE Docker createContainer (so the bind-mount path exists when Docker validates the spec), registers the scope with a placeholder `parentDockerId=""` first, then upserts with the real docker id once `createContainer` returns. `registerTask` is now an upsert that doesn't re-bind the socket on the second call, so connections in flight aren't disrupted. Bind appended to `HostConfig.Binds`. `stopTask` calls `proxy.unregisterTask`; `shutdown` calls `proxy.close`. Roll-back on Docker create failure or container.start failure unregisters the placeholder. Cgroup parent — every container in a task tree gets pinned under a shared `cogmo-task-<dashless-uuid>.slice` (systemd) cgroup parent. Slice 3.0h ships the slice naming + assignment infrastructure; aggregate-budget enforcement at the slice level (CPU/memory/pids quotas) is deferred until the spawn-many-children case becomes routine. Per-leaf limits via `NanoCpus`/`Memory`/`PidsLimit` already cap the task container directly. Tool gate orchestrator wiring: `runExecuteStreaming` now drives a real decision pipeline — build canonical pattern (`Bash(git push *)` etc.), replay task-scoped decision log (newest-first match wins), run `policy.evaluate` (allow short-circuits + persists scope=once for audit; deny short-circuits with reason), prompt path emits `coding/task/permission-requested` and blocks on `step.waitForEvent("coding/task/permission-decision")` filtered by `taskId + requestId`. New events: `coding/task/permission-requested`, `coding/task/permission-decision`. New `StepWaitForEvent` type derived from the SDK like `StepRun`. `transport.coding.respondPermission(params, tapperHandle)` — identity-checked Inngest event emit (no DB transition; the orchestrator's wait resumes on the event). New Telegram inline keyboard (Once / Task / Deny) with single-char wire codes (`o`/`t`/`d`) to fit Telegram's 64-byte callback_data limit alongside a full UUID taskId + 16-char requestId prefix; codes translated back on parse. New per-channel Inngest function listening on `coding/task/permission-requested` posts the keyboard message into the task's active Telegram session. Block-indefinitely on Telegram outage per slice3-plan #4 — wait timeout is 7 days (abandoned-task safety net), not deny-on-timeout. Reaper cron runs every minute and walks three passes per tick: TTL pass (current-instance containers with expired TTL still active, killed depth-DESC, marked `reaped`), orphan pass (Docker-side discovery via `listContainers({label=cogmo.managed=true})` — anything tagged with a dead/unknown `cogmo.instance` or with no DB row gets reaped), stale-DB pass (rows we still consider live but the daemon doesn't know about, marked `exited`). After containers, networks + volumes get a TTL pass. 1m cron interval (Inngest cron's minimum); slice3-plan + design/sandbox.md target 30s — close enough at personal scale. 16 reaper unit tests cover every pass (positive + negative), depth-DESC kill order, idempotency on re-tick, network/volume TTL, `docker.listContainers` failure mode. Sysbox + proxy-socket bind-mount compatibility verified on Fedora 43 via the karellen COPR sysbox-ce 0.7.0 build (no `/var/run` shadowing — sysbox's `sysbox-fs` only virtualises `/proc` and `/sys`); confirmed with `docker run --runtime=sysbox-runc -v /var/run/docker.sock:/var/run/docker.sock alpine sh -c "curl -s --unix-socket /var/run/docker.sock http://localhost/_ping"` returning `OK`. New env vars: `SANDBOX_PROXY_SOCKET_DIR` (default `/run/cogmo/sockets`), `SANDBOX_HOST_DOCKER_SOCKET` (default `/var/run/docker.sock`). 1155 unit tests pass (+~120 vs slice 2).
