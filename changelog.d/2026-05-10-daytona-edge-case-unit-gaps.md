Three regression tests pinning subtle Daytona client behavior that 3c.1's host-side fake doesn't cover (these live below the SDK boundary the fake replaces):

1. **`buildShellCommand` with empty `env: {}`** — verifies the gate `Object.keys(opts.env).length > 0` correctly suppresses the env prefix on an empty record. A buggy gate would synthesize `env exec ...`, which on most coreutils strips the inherited env and silently breaks PATH-dependent commands inside the sandbox. Test asserts the whole command is exactly `exec 'pwd'` with no leading `env ` prefix.
2. **`getSessionCommand` throwing post-WS-resolve** — exit-code-fetch race where the WS closes naturally but the follow-up HTTP fetch fails (transient daemon error, rate limit, network drop). Pins that the natural-exit branch in `exec-streaming.ts` forwards the throw to `wait()`'s reject (so consumers don't see a phantom `exitCode=0`) and still runs `cleanupSession` so per-call sessions don't leak on the failure path.
3. **Concurrent `tryResumeByTaskId` for the same taskId** — two callers race; both get the same SDK handle from `list()` with `state=STOPPED` snapshot; both fire `start()`. Pins that the client doesn't dedupe by design (list snapshots are stale by the time we act on them; re-checking would burn another HTTP roundtrip) and that both calls return wrapped sessions with consistent state. Mirrors the production race window between an orchestrator step.run replay and the reaper's reconcile pass.
