- In-worker catch paths in `runCodingTask`, `runCodingExecute`, and `runCodingVerify` now emit `coding/task/failed` via `step.sendEvent` with idempotency `id: "task-failed-${taskId}"` instead of `inngest.send(...).catch(() => {})`. Emit happens BEFORE the DB status update — if `step.sendEvent` ultimately fails (Inngest SDK retries exhausted), the catch throws, the function fails, `inngest/function.failed` fires, and `coding-task-reconcile` picks up a still-non-terminal row to flip + re-emit. With the previous shape a transient send blip would leave the row `failed` but no event on the bus, leaking the orphan run-branch until the weekly cron sweeper. Adds `StepSendEvent` export to `src/inngest/index.ts` and threads `stepSendEvent` through the three orchestrator `RunParams` shapes.
