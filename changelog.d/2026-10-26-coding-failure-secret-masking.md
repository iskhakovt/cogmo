**Coding-task failure text no longer carries credentials.** `redactSecretsInText` (`src/util/redact-secrets.ts`), the redactor the logger and OTel export already run, is the one place secrets are masked. It covers URL userinfo under any scheme (user and password, a token as the username, an empty username, an `@` inside the password), GitHub tokens (classic `gh[pousr]_`, `github_pat_`, and installation tokens in both the 36-character and the `ghs_APPID_JWT` forms), Anthropic `sk-ant-` keys and OAuth tokens, and Telegram bot-token segments. Each shape starts with a literal, so masking stays linear and matches inside identifiers, after JSON escapes and after ANSI colour codes.

A coding task's failure reason is masked once, where it is recorded, and that text goes to the chat message, the function's return value, `coding_tasks.failure_reason` and the `coding/task/failed` event alike, including the reconcile path and `inngest.send` failures at delegation. Git push output is masked before its 8 KiB tail cap. Verify output is masked before its cap too: a capture that ran past the cap keeps text only up to where a secret could start in its last whitespace-free run, so a secret the cut runs through is dropped whole. The PR body's plan and verify output are masked before publishing. Existing rows and already-emitted events are not rewritten.
