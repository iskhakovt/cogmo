**Turn authority is specified for turns no user started.** design/agents.md → Turn Authority (`[proposed]`) gives scheduled fires and pipeline stages less authority than a user turn: each tool declares `any_turn` or `user_turn`, and dispatch refuses `schedule_task`, `remove_task`, `delegate_coding`, the rule tools, `core_memory_update`, `register_skill` and the pipeline tools outside user turns, inside the tool's durable step so a refusal memoizes like any rejection. The source comes from the batch's inbound rows; a mixed batch takes the least authority present. Memory writes stay allowed and are tagged with the turn source for the Observer, web fetch and deployed skills stay allowed, and the turn context tells the model which tools are refused. Under it no fire can create another, so the task cap times cadence bounds unattended turns. design/scheduling.md, design/pipelines.md and design/evolution.md point at it, and todo.md carries the three implementation slices (deep review 2026-10-27, M3).
