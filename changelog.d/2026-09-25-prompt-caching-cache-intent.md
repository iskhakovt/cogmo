The agent loop's transcript is cached on Anthropic, and usage reports total prompt size — step 1 of `design/prompt-caching.md`.

- **Cache intent.** `ChatParams.cache` marks a transcript that will be sent again; the two agent-loop callers set it (`retention: "short"` for now) and one-shot calls don't. The Anthropic adapter turns it into top-level automatic `cache_control`, with the tools and system markers at the same TTL, so every iteration after the first reads the transcript from cache. Requests without an intent are unchanged.
- **Usage.** `Usage.inputTokens` is the total prompt size, with cache reads and writes as subsets: the Anthropic adapter adds them back into `input_tokens`, and the OpenAI-compatible adapter reads `prompt_tokens_details`. Otherwise a cached conversation would look nearly empty to `shouldSkipCounting`. The `cogmo.llm.tokens` `input` type counts the uncached remainder, so its four types stay disjoint.
- **Tests.** Both adapters take an injected `fetch`, and `src/test/wire-recorder.ts` captures request bodies and usage. A new `live` Vitest project (`pnpm test:live`, skipped unless `LIVE=1` and a key are set) asserts on real calls that each request reads exactly what the previous one cached, across plain turns (`src/llm/anthropic.live.test.ts`) and a tool-using turn's iterations (`src/agent/loop.live.test.ts`).
