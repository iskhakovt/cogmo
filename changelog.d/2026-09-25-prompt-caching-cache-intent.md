The agent loop's transcript is cached on Anthropic, and usage reports total prompt size — step 1 of `design/prompt-caching.md`.

- **Cache intent.** `ChatParams.cache` (`{ key, retention }`) says a request's transcript will be sent again. The two agent-loop callers set it on every iteration (`retention: "short"` for now); one-shot calls don't. The Anthropic adapter maps it to top-level automatic `cache_control` — a breakpoint on the last cacheable block that moves forward as the transcript grows — with the tools and system markers at the same TTL. Iterations 2 and later of a tool-using turn now read the transcript from cache instead of re-sending it at full rate. Without an intent, and on the structured-output path, requests are unchanged.
- **Usage.** `Usage.inputTokens` is the total prompt size, with `cacheReadTokens` / `cacheCreationTokens` as subsets. The Anthropic adapter adds the cache fields back into `input_tokens`, which counts only the uncached tail; the OpenAI-compatible adapter reads `prompt_tokens_details.cached_tokens` and `cache_write_tokens`. Without this, a cached conversation would look nearly empty to `shouldSkipCounting` and compaction would stop running. The span's `gen_ai.usage.input_tokens` carries the total; the `cogmo.llm.tokens` `input` type counts the uncached remainder, so its four types stay disjoint. The loop's turn totals carry the cache fields.
- **Test harness.** Both adapters accept an injected `fetch`. `src/test/wire-recorder.ts` records request bodies and the provider's usage block. A new `live` Vitest project (`pnpm test:live`, skipped unless `LIVE=1` and a key is set) holds `src/llm/anthropic.live.test.ts`, which asserts on real Sonnet 5 calls that each request reads exactly what the previous one cached. Its first run read 5,150 then 5,173 tokens, each equal to the previous read plus write, all written at the 1-hour TTL.
