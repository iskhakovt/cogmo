Evicting an MCP server while its connection is still being set up no longer leaves the connection running. Each server's pool entry is a pure state machine (`src/mcp/client/pool-state.ts`) the pool drives: `evict` and `close` abort an in-flight connect, fail its waiting calls, close any connection it still yields, and resolve once the server's connections are closed. So `/mcp remove` no longer leaves a removed server's subprocess running until idle eviction, and shutdown waits for connects in flight. Idle eviction is a per-connection timer; `MCP_EVICTION_INTERVAL_MS` is removed and ignored if set. The streamable-HTTP session-end DELETE carries its own 2 s deadline.
