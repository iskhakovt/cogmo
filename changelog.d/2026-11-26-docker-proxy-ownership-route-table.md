The Docker API proxy forwards container and exec requests only for a task's own containers and exec sessions, lets image creates only pull, and denies every route it doesn't list. A coding task can't inspect, exec into, archive, kill or list another task's containers or Cogmo's own, or replace a shared image.

- **Ownership.** A container ref, whether a full id, a prefix or a name, is resolved through the daemon and checked against the task's `containers` rows, read from the store on every request. The request then goes out under the full id, so a rename can't redirect it. A sibling's container, Cogmo's own, a missing one and an ambiguous prefix all get the daemon's `No such container` 404, so nothing tells them apart. An exec session is owned when the task's own socket created it.
- **The task's own container.** Its lifecycle routes (`start`, `stop`, `kill`, `rename`, `DELETE` and the rest) and `PUT /archive` are refused: Cogmo owns its lifecycle, and an archive extracted onto its host-bound `/workspace` would run as host root.
- **Lists and events.** `GET /containers/json` returns only the task's containers. `GET /events` drops every line that isn't the task's, including network and volume events, which carry no task label.
- **The route table.**
  - Routes follow moby's own router, so a ref spans path segments wherever the daemon's does.
  - A route the table doesn't list is refused, which covers `POST /containers/{id}/update` and every prune, build, swarm and plugin route.
  - Image, network and volume routes stay forwarded until their own policies land, except the three below. `DELETE /volumes/{name}` is refused. Network connect and disconnect work only for the task's own container on `bridge`, which testcontainers' port forwarder needs.
- **Images.** `POST /images/create` pulls only: it needs `fromImage`, forwards `tag` and `platform`, and refuses `fromSrc`, `repo`, `message` and `changes`. Its body is never forwarded, since the daemon reads a form body's parameters ahead of the query; a pull from testcontainers or dockerode, which carries its options as a JSON body too, still works. So a task can't import a tarball under the name of an image other tasks or Cogmo's salvage containers run. The route table refuses commit, tag and load, the other routes that name an image.
- **The forwarded request.** The proxy always forwards the canonical path it checked, with refs rewritten and the query re-serialised, never the client's raw request target. API versions below 1.44 are refused on every route. Hop-by-hop headers are dropped in both directions, along with the headers a `Connection` value names, but never `Content-Length`, `Transfer-Encoding` or `Host`, so a request's framing can't be stripped to smuggle its body in as a second request. Rebuilt bodies go out as `application/json`.
- **Pipelining and streams.** Only a real upgrade is raw-piped. Exec start and attach without `Upgrade`, `logs` and `distribution` go through the normal request path with a streamed response, so a request pipelined after one of them is checked on its own, and the exec start's body (testcontainers sends one) reaches the daemon. A request whose client has gone is not sent, except a container create. An upgrade goes out with `Connection: Upgrade, close`, so a daemon that refuses it, or answers a detached exec start without switching, closes the connection and never reads what the client pipelined behind it. An upgrade's body reaches the daemon: on Node 26 the server parses it into the request, so `docker exec` and dockerode's hijacked exec starts through the proxy hung waiting for it.
- **Crashes.** A task could crash `cogmo serve` with an uncaught exception: a `Trailer` header on a body-less request (`ERR_HTTP_TRAILER_INVALID`), or a request pipelined after a raw-piped one (`ERR_INTERNAL_ASSERTION`). Both now get ordinary answers.

Containers a task creates get no rows until the next slice, so testcontainers can create a child but every later request on it gets a 404. The `Upgrade` value each route allows and a chunked upgrade body are slice 4's (todo.md → Docker API proxy authorization boundary).
