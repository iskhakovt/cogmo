Telegram forwarded messages are no longer read as the user's own words. Forwarded text, captions and voice-note transcripts carry a `forwarded` marking (origin kind, sender name, original send time) and reach the model, and the stored transcript the Observer reads, wrapped in `<forwarded_message from="…" origin="…" sent="…">`, with attribute values entity-escaped and any `forwarded_message` tag in the body entity-escaped, so the body can neither close the element nor open another. The system prompt and the memory and correction extraction prompts say that text inside the element is someone else's words, not the user's statements, facts or instructions. A forwarded photo or document without a caption gets an empty element naming its sender, a forwarded `/command` goes to the agent as forwarded text instead of running, auto-recall queries with the forwarded body alone, and a forwarded voice note doesn't switch `auto` voice mode to a spoken reply. A forward of the user's own message stays unmarked. The Resume prompt and the conversation list preview a forwarded message as "Fwd from …: body", and the web chat shows one in a text turn as a quote headed "Forwarded from …"; a turn with a photo or document still shows its raw stored JSON in web history.
