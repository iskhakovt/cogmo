Phase 3 P3.3 first slice — dynamic skill creation end-to-end. `SkillRunner.register({branch})` reads `SKILL.md` + `skill.py` from the branch tip in the bare skills repo, parses the manifest, runs the stub classifier (`classifyManifest` in `src/skills/classifier.ts`, pinned to `notify` until the AST-lint pass lands), and atomically merges into `main` + writes the DB rows under a `pg_advisory_xact_lock(hashtext("skill_register:" + name)::bigint)`. Filesystem `git update-ref refs/heads/main` runs *inside* the transaction so a ref-update failure throws out cleanly; the small remaining hole (DB commit fails after `update-ref` succeeds) is documented and acceptable at personal scale. New `src/skills/git-ops.ts` wraps `revParse` / `gitShow` / `isAncestor` / `updateRef` (with CAS) / `deleteRef` / `getMainSha` against the bare repo and surfaces typed `GitOpsError` codes (`ref_not_found` / `file_not_found` / `non_fast_forward` / `ref_changed` / `exec_failed`). New atomic store ops `executeRegister` / `executeApprove` / `denyPendingDeploy` / `executeRollback` plus `getDeployById`. Companion RPCs: `approveDeploy({pendingId})` advances `main` for an approve-tier deploy and re-checks fast-forward at approve time; `denyDeploy({pendingId, reason})` is idempotent on missing/already-resolved ids; `rollback({name, toGitSha})` rewinds `main` + re-classifies the target SHA so the audit trail records what we rolled back to; `deregister({name})` soft-disables (audit history retained). The `cogmo skills` CLI exposes all five (`register` / `approve` / `deny` / `rollback` / `deregister`); `runner.register` removes `not_implemented_in_p3_1` from the API. New `register_skill` agent tool (`src/skills/skills-tool.ts` + `SKILLS_PROMPT_GUIDANCE`) + `Service.skills` namespace (`src/skills/skills-service.ts`) wrap the RPC for the LLM — agent authors a skill via `delegate_coding` against the skills repo, then calls `register_skill` with the branch name; the deploy is live immediately under the stub classifier. Dynamic per-turn tool registration in `handle-message`: `runner.listToolDefs()` reads each live skill's `SKILL.md` from git (cache keyed by `(name, gitSha)` so re-deploys invalidate automatically), `buildSkillTools` converts each into a `ToolSpec`, and the orchestrator constructs a fresh `ToolRegistry` per turn merging built-ins + skill tools — registered skills appear from the next turn onwards, disabled/rolled-back ones disappear. New `ToolRegistry.snapshot()` exposes registered specs for the per-turn merge. `runner.invoke` now also validates outputs against `manifest.outputs` JSON Schema via ajv (TODO marker in the file removed); a skill returning the wrong shape is recorded as `status=error` with the schema-failure detail rather than silently storing garbage on `skill_runs.output`. Source loading from git is the universal path now — `__registerForTests` stays as a fast in-memory test seed but production reads `git show <sha>:SKILL.md` via the `(name, gitSha)`-keyed cache. New unit tests: `git-ops.test.ts` (real bare repo + clones, all six wrappers exercised), `runner.register.test.ts` (16 tests covering register / re-register no-op / non-fast-forward rejection / missing branch / missing SKILL.md / invalid manifest / invoke after register / fresh-runner cross-instance source load / outputs validation / `listToolDefs` shape / source-cache invalidation across SHAs / rollback / deny idempotency / deregister soft-disable), `skill-tool-builder.test.ts` (handler success/error/throw, fault-tolerant `buildSkillTools`), `skills-tool.test.ts` (`register_skill` happy path + rejected verbatim + missing service); CLI tests extended to cover the five new subcommands. 1760 unit tests pass + 88 integration tests pass.
