`cogmo serve` shuts down cleanly with connections open. Chat streams end from the server side before the web server closes, so an open browser tab no longer holds shutdown until the process is killed; the browser reconnects to the next process. Removing a task's Docker socket proxy ends its streaming connections (`docker logs -f`, events, attach) and requests waiting on the daemon, and a proxy close during task registration leaves no listener behind. Every shutdown step is bounded, so a stuck or failing step no longer skips the rest; the order is in design/infrastructure.md → Shutdown. The Telegram adapter waits for grammY to confirm the last update offset, so Telegram doesn't redeliver the last batch on restart.
