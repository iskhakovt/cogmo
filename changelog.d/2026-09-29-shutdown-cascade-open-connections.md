`cogmo serve` shuts down cleanly with connections open. Chat streams end from the server side before the web server closes, so an open browser tab no longer holds shutdown until the process is killed; the browser reconnects to the next process. The web drain ends as soon as the last request in flight has answered, instead of waiting out keep-alive connections. Removing a task's socket ends its streaming connections (`docker logs -f`, events, attach) and requests waiting on the daemon, and a proxy close during task registration leaves no listener behind. Every shutdown step is bounded, so a stuck or failing step no longer skips the rest; the order is in design/infrastructure.md → Shutdown. On stop, the Telegram adapter confirms every update it handled, the rest of an in-flight batch included, so Telegram no longer redelivers them as duplicate turns on restart. Give cogmo's container a 60 s stop grace (DEPLOYMENT.md → Stopping).
