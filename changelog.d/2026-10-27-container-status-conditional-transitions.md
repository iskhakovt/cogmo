**Container rows move through an explicit state machine, one conditional transition at a time.** `SandboxStore.transitionContainerStatus(tx, { id, at } & ContainerTransition)` replaces the unconditional `updateContainerStatus`: a single conditional `UPDATE` (`status = <from>` for `running` and `exited`, `status <> 'reaped'` for a reap) returning `{ kind: "transitioned" } | { kind: "stale"; status }`, the shape of `DrizzleCodingStore.transitionTaskStatus`, with the legal transitions encoded in the `ContainerTransition` type. `at` stamps `started_at` into `running` and `exited_at` into a terminal state; an `exited` row keeps its `exited_at` when reaped. A reap names no `from`, so a row `create` moved `starting → running` while a cascade was killing its container still lands on `reaped`. One use case per transition — `markContainerRunning`, `markContainerExited` and `reapContainer` (kill + remove the daemon object, then `reaped`; a daemon refusal comes back as a `DaemonError` `Result` with the row untouched) — and every writer goes through them: the supervisor's `create` start-failure and `deleteByTaskId` cascade, boot `reconcileCrashedInstances`, and the reaper's TTL, orphan and stale passes. A `stale` result means another path finished the row first: logged at debug with the reap reason (`ttl_expired`, `cascade`, `dead_instance`, `crash_reconcile`, `start_failed`), never an error, not counted by the DB-driven passes. The stale pass no longer rewrites a `reaped` row as `exited`, and a racing cascade no longer overwrites the reaper's `exited_at`. A start failure reaps the container (`starting → reaped`) instead of marking a removed container `exited`; a daemon refusal during reconcile is logged and the pass continues instead of aborting.

`create` also handles the daemon succeeding where the row insert fails (the container is force-removed and the proxy scope released before the error propagates) and the running transition finding its row already finished (the container it started is removed before it throws). `reconcileCrashedInstances` closes the instance rows it targeted once its pass is done: a crashed instance keeps `stopped_at` NULL and the reaper's orphan pass counts an open instance as live, so a container reconcile could not kill is now retried every tick instead of waiting for the next boot.

`design/sandbox.md` gains a Container state machine section — unit, states, transition table, failure-mode table — and the Lifecycle section describes the create and teardown flow as implemented. `reaped_reason` is the planned column for the reason and the fate of the unwritten `exit_code` is open; both are `todo.md` entries, as is the finding that proxy-created child containers get no row and so meet the orphan pass's "no row ⇒ orphan" rule.
