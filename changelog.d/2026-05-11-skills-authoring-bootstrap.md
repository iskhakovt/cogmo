**Skill authoring works out of the box.** Three gaps that together broke `delegate_coding({ repo: "skills" })` end-to-end on fresh deployments — every one of them tractable, none documented, all surfaced by an actual "let's author a skill" attempt that failed three different ways before the third symptom revealed the chain.

- **Bare skills repo HEAD pinned to `main`.** `bootstrapSkillsRepo` was calling `git init --bare` without `--initial-branch=main`, so on hosts where `init.defaultBranch` is still `master` HEAD landed on `master`. The `pre-receive` hook only gates `refs/heads/main`, so a direct push to `master` would slip the gate entirely, and any clone taken before the first `register_skill` would check out an empty `master` worktree. Now passes `--initial-branch=main` on first init and unconditionally `git symbolic-ref HEAD refs/heads/main` on every boot — existing deployments converge without an operator step.

- **`coding_repos` row for the skill library is auto-seeded.** `bootstrapSkillsRepo` only sets up the filesystem half (the bare repo at `$COGMO_SKILLS_PATH` + the `pre-receive` hook). `delegate_coding({ repo: "skills" })` resolves repo config via `getRepoByName(tx, "skills")`, and that row was never written — fresh deployments hit `"Repo not registered: skills. Use /repo list to see available repos."` every time, even though every config field has an obvious default (`local_path = $COGMO_SKILLS_PATH`, `default_branch = "main"`, `allowed_backends = ["claude"]`, `max_concurrent_tasks = 1`, etc.). New `ensureSkillsCodingRepo` runs immediately after `bootstrapSkillsRepo` — idempotent insert with sane defaults, picks up `remote_url` from `git remote get-url origin` so an operator who attached a backup remote doesn't have to re-enter it.

- **Daytona post-task fetch lands on `refs/heads/<branch>` for bare mirrors.** The orchestrator's `fetchFeatureBranch` always fetched into `refs/remotes/origin/<branch>` — the right answer for non-bare `/repo add` mirrors, the wrong answer for the skill library's bare repo. `register_skill` reads from `refs/heads/<branch>`, so the round-trip silently stranded the skill author's work even after the prior two fixes. `fetchFeatureBranch` now checks `git rev-parse --is-bare-repository` and routes the refspec accordingly; non-bare paths are unchanged.

Net: from a fresh boot, the agent can call `delegate_coding({ repo: "skills", goal: "..." })`, Daytona executes the plan, pushes the feature branch, the host fetches it into the bare repo under `refs/heads/<branch>`, and `register_skill` advances `main`. No manual `/repo add`, no DB hand-fix, no HEAD-rename ritual.

Side note for operators on old deployments: the `tool_set` curated lists frozen into pre-`["*"]` default profiles are not touched by any of the above — if `delegate_coding` is still missing from your `coding-tool` list, widen `profiles.tool_set` directly.
