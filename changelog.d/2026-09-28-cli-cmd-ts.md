Every `cogmo` command parses its arguments with cmd-ts. Each command declares typed arguments, and value decoders validate before a handler runs: an unknown flag, a repeated option, a missing value or a malformed one is rejected under the offending token, and a mistyped command gets a "did you mean". `--help` works at every level, and `--flag=value` works everywhere. A handler loads its own dependencies, so help and a rejected command line never bootstrap the database.

Exit codes are uniform: 0 for success and help, 1 for an operation that failed, 2 for a command line cmd-ts rejects — including an unknown subcommand. `help` is no longer a subcommand; `--help`, `-h` or no arguments show it. `--tag a,b` and `--bankId x` join the `=` forms on `cogmo backfill profile-class`.

An optional option given with no value (`cogmo model add m --provider p --context`) is an error rather than a silent omission — cmd-ts reads it as omitted, so optional options go through `optionalOption` in `src/cli/args.ts`. A name or id refuses a value that looks like a flag, so `--provider --all` doesn't register a provider called `--all`.

cmd-ts builds the whole command tree before it parses, so `main.ts` imports only the command group being run: `gen-key` starts in 50 ms, not the 600 ms importing every group costs.
