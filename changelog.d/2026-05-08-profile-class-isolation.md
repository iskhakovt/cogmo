Speaker-driven memory isolation via a new **profile class** axis on `memory_scope`. Each user owns a registry of named classes (`profile_classes` table — `(name, description)` per user) and assigns profiles to a class via `/profile class <profile> <classname>`. The Observer stamps every retained memory with a `profile_class:<class>` tag when the conversation's active profile carries one; recall is gated by an optional third leaf in the scope filter (`AND-of-ORs`, `any_strict`) that excludes memories without a matching class tag. The two existing dimensions — `compartments` and `trust` — keep their semantics unchanged; `profileClasses` is opt-in per profile, so unscoped or class-less profiles see today's behaviour. New Telegram surface: `/classes [list|add <name> <description>|rm <name>]` for the registry, `/profile class <name> <class|clear>` for assignment, `/profile scope <name> … classes=<a,b>` to add the class dimension to an existing scope. `formatScope` and `/profile list` annotate classed profiles inline. The compartment enum gains a `misc` value as an explicit "none of the above" bucket so the classifier never has to force-fit a fact into one of the existing five domains. Existing memories are untagged on the class dimension — under `any_strict` they're invisible to a profile scoped on classes, so opting in requires either a follow-up backfill PR or accepting that scoped recall starts cold. Solves the "intimate writes invisible to assistant" requirement: set `intimate.profile_class = "intimate"`, `intimate.memory_scope.profileClasses = ["intimate", "general"]` (so intimate keeps seeing general facts), and `assistant.memory_scope.profileClasses = ["general"]`.
