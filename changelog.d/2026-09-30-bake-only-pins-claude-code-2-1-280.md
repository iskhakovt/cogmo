**`docker-bake.hcl` is the only copy of the task images' toolchain pins.** The devbase Dockerfile declares `UV_VERSION`, `UV_DIGEST`, `NPM_VERSION`, `PNPM_VERSION` and `CLAUDE_CODE_VERSION` without defaults, as the skills Dockerfile already did, so a build outside bake fails at the uv `FROM`. npm installs `latest` for an empty version, so each install expands its version with `:?`. The one consumer that built devbase without bake, skill-authoring's record-mode Daytona prebuild, resolves the target through `docker buildx bake --print` and writes the values in as ARG defaults (`src/test/bake.ts`), because `Image.fromDockerfile` uploads the file verbatim and takes no build args. `version-pins.test.ts` holds both task Dockerfiles to declaring no defaults and to getting a value from bake for every ARG; `packageManager` (pnpm) and `ci.yml`'s `setup-uv` (uv) remain the two mirrors it compares to bake.

Claude Code 2.1.280 changes what the CLI sends: environment and model-identity system reminders open the first user turn, and `-p` runs no longer make a background title request. The `claude-cli` cassette is recorded from scratch against it. Two behaviours change under an unchanged interface:

- A headless `--resume` carries the session's cost total forward, so the execute run's `total_cost_usd`, and with it `resource_usage.cost_usd`, covers plan and execute. `tokens_input`/`tokens_output` stay the execute run's own.
- Opus 5.5 is the CLI's default Opus model, and Pro and Team Standard plans default to Opus. Coding tasks pass no `--model`, so they run on whatever the subscription's default is.

The plan test asserted an `ExitPlanMode` call, which a fresh recording doesn't repeat: the CLI offers `ExitPlanMode` and `AskUserQuestion` in `-p` mode only alongside `--permission-prompt-tool`, which `claude.ts` doesn't pass (2.1.236 and 2.1.280 alike), so the recorded call was the model reaching for a tool it wasn't given, and a plan ends as streamed text.
