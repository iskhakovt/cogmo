Compaction no longer rewrites tool results, so a turn replays the transcript it sent (Append-only step 1). Strategy 1 is a request-level edit intent, `ChatParams.clearToolResults`: past 60% of the budget, clear every tool result but the last five, provided they free at least a tenth of the budget. Every request of a chat or stage turn carries it — the counts, each loop iteration and its in-step replay, the summarization fork and the degraded-reply synthesis — and the adapter applies it. Anthropic clears on the server with `clear_tool_uses_20250919` in `context_management`, on messages and on `countTokens`; the preserved-thinking check compares what was sent, so thinking stays valid. The OpenAI-compatible adapter applies the same rule to the wire body and to its count. Strategy 0, same-tool supersession, is retired from turns and from `/compact`, since it rewrote a `tool_result` later thinking blocks are bound to.

The Anthropic adapter moves to the SDK's beta Messages API. Every request to a first-party endpoint (no base URL, or `api.anthropic.com`) carries the `thinking-binding-controls-2026-08-01` beta; an Anthropic-compatible third-party endpoint gets neither it nor `block_binding`. A new `llm_providers.attrs.prefixMismatchBehavior` (`drop_block` | `error`), unset by default, goes out as `thinking: { type: "adaptive", block_binding }` on messages and counts to Opus 5.5, Fable 5.1 and Sonnet 5.5 only. A deployment on an account created on or after 2026-08-31 sets `drop_block` on its Anthropic row.

Live scenario B now runs through the provider setting with `"error"` on Opus 5.5 and a server-side clearing from the draw call's own turn on: six requests, no 400, no `input_transformations`, and cache reads that follow each request's predecessor exactly. A run in flight at the deploy replays counts measured before clearing as counts after it, so that one turn can summarize or truncate on a stale count.
