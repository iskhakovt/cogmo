Compaction no longer rewrites tool results, so a turn replays the transcript it sent (Append-only step 1). Strategy 1 is a request-level edit intent, `ChatParams.clearToolResults`: past 60% of the budget, clear every tool result but the last five, provided they free at least a tenth of the budget. Every request of a chat or stage turn carries it: the counts, each loop iteration and its in-step replay, the summarization fork and the degraded-reply synthesis. A fork is its own request, so the server evaluates the trigger on the fork's prompt and keeps the fork's last five results. Strategy 0, same-tool supersession, is retired from turns and from `/compact`, since it rewrote a `tool_result` later thinking blocks are bound to.

Anthropic's API clears on its server, with `clear_tool_uses_20250919` in `context_management`, on messages and on `countTokens`; the preserved-thinking check compares what was sent, so thinking stays valid. The OpenAI-compatible adapter applies the same rule to the wire body and to its count, and so does the Anthropic adapter for an Anthropic-compatible third-party endpoint, which gets no request controls at all. Every local encode counts a tokenizer marker such as `<|endoftext|>` as plain text, so one in a tool result no longer fails the conversation's requests.

The server clears after the bytes arrive, so a view whose raw JSON passes 80% of the smallest request cap (20 MB) summarizes on any path without a count first, and truncates until it fits if the summary doesn't come. The context window itself is checked after the edits: on Haiku 4.5 a 289,343-token request with the intent returned 200 at 30,210 input tokens, and the same request without it was a 400.

The Anthropic adapter moves to the SDK's beta Messages API. Every request to Anthropic's own API, as the SDK resolves the base URL, carries the `thinking-binding-controls-2026-08-01` beta. A new `llm_providers.attrs.prefixMismatchBehavior` (`drop_block` | `error`), unset by default, goes out as `thinking: { type: "adaptive", block_binding }` on messages and counts to Opus 5.5, Fable 5.1 and Sonnet 5.5 only. A value the API doesn't take reads as unset, and a row on a third-party endpoint logs a warning. A deployment on an account created on or after 2026-08-31 sets `drop_block` on its Anthropic row.

Live scenario B runs through the provider setting with `"error"` on Opus 5.5 and a server-side clearing from the draw call's own turn on: no 400, no `input_transformations`, and each request reads exactly what the one before it cached.

Runs in flight at the deploy:
- A count measured before clearing is read as a count after it, and the size trigger can skip a count. Either can plan a `summarize-prefix-outcome`, `persist-summary` or `count-tokens-<n>` the run never planned, which fails with `step-not-found` in a run that planned a parallel group.
- A `count-tokens-2` measured after client-side clearing is read as the count after a summary.
- A turn whose view Strategy 0 or client-side clearing rewrote sends its remaining iterations, and the next turn, with those results verbatim: one cache miss.
