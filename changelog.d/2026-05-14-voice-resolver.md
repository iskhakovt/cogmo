Voice setup gains hot reload, OpenAI-compatible providers, and ElevenLabs TTS. Bootstrap no longer constructs `OpenAIVoiceProvider` once at boot — it builds a `VoiceProviderResolver` (`src/voice/resolver.ts`) that reads `voice_config` + decrypts both secrets per turn and caches constructed providers by content hash. Operator changes (swap voice id, change TTS model, rotate API key, switch provider) take effect on the next message with no `systemctl restart`. `voice_config.tts_provider` and `stt_provider` columns become typed pgEnums (`tts_provider_type`, `stt_provider_type`), and matching `chk_voice_config_{tts,stt}_base_url` CHECK constraints reject hand-edited rows where `openai`/`elevenlabs` carries a base URL or `openai_compatible` is missing one — bad shapes fail at write time instead of producing a silent voice-disabled state. The resolver's cache key is SHA-256'd so decrypted secrets never sit on the heap as plaintext beyond the provider instance that needs them. `ElevenLabsTtsProvider` (`src/voice/elevenlabs.ts`) implements `TtsProvider` against ElevenLabs's REST API directly — no SDK dependency — and emits OGG/Opus via `output_format=opus_48000_128` so Telegram's `sendVoice` accepts it without ffmpeg. The wizard's `stepConfigureVoice` adds per-direction provider selects (openai / openai_compatible / elevenlabs for TTS; openai / openai_compatible for STT) with a base-URL prompt for compat providers; the reuse-one-key shortcut is gated on matching provider type + base URL, so an identical string pasted across incompatible providers stores two rows with accurate descriptions. `handle-message` swaps the three legacy deps (`ttsProvider`, `sttProvider`, `voiceConfig`) for a single optional `voiceResolver`, threading the resolved bundle through STT, voice-mode resolution, and TTS in one turn-start lookup. Drops the "Voice config hot-reload" p3 from `todo.md` — the resolver-based design lands the feature directly.
