Voice setup gains hot reload, OpenAI-compatible providers, and ElevenLabs TTS. Bootstrap no longer constructs `OpenAIVoiceProvider` once at boot — it builds a `VoiceProviderResolver` (`src/voice/resolver.ts`) that reads `voice_config` + decrypts both secrets per turn and caches constructed providers by content hash. Operator changes (swap voice id, change TTS model, rotate API key, switch provider) take effect on the next message with no `systemctl restart`. `voice_config.tts_provider` and `stt_provider` columns become typed pgEnums (`tts_provider_type`, `stt_provider_type`). `ElevenLabsTtsProvider` (`src/voice/elevenlabs.ts`) implements `TtsProvider` against ElevenLabs's REST API directly — no SDK dependency — and emits OGG/Opus via `output_format=opus_48000_128` so Telegram's `sendVoice` accepts it without ffmpeg. The wizard's `stepConfigureVoice` adds per-direction provider selects (openai / openai_compatible / elevenlabs for TTS; openai / openai_compatible for STT) with a base-URL prompt for compat providers and the historical reuse-one-key shortcut preserved when both directions hit the same endpoint. `handle-message` swaps the three legacy deps (`ttsProvider`, `sttProvider`, `voiceConfig`) for a single optional `voiceResolver`, threading the resolved bundle through STT, voice-mode resolution, and TTS in one turn-start lookup. Drops the "Voice config hot-reload" p3 from `todo.md` — the resolver-based design lands the feature directly.
