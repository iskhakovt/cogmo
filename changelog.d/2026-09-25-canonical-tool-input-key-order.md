Tool-call inputs enter the transcript in canonical key order — keys sorted at every depth, arrays kept in order — both where the agent loop appends an iteration's content and where `messages.content` is parsed back from `jsonb`. The model emits keys in its own order and `jsonb` reloads them in a length-first order, so without one canonical order every turn after a tool call would re-send that call with different bytes and break the provider's prompt cache from there on (measured on Anthropic as `messages_changed`; the OpenAI-compatible path serializes `arguments` from the same object). A shared `canonicalKeyOrder` helper in `src/util/` does the sorting; the loop applies it outside the `llm-iter<N>` step so memoized outcomes come out canonical too, and `ToolUseBlockSchema.input` applies it on every read. Handlers receive the same values; idempotency keys and loop fingerprints are already order-independent. Regression tests cover a PGlite round-trip, four loop paths (streamed, recovery replay, memoized step, non-streaming) and the helper. First shipped slice of `design/prompt-caching.md`.
