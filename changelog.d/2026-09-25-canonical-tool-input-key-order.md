Tool-call inputs enter the transcript in canonical key order — keys sorted at every depth, arrays kept in order — both where the agent loop appends an iteration's content and where `messages.content` is read back from `jsonb`. The model emits keys in its own order and `jsonb` reloads them length-first, so without one order every turn after a tool call re-sends that call with different bytes and breaks the prompt cache from there on (Anthropic reports `messages_changed`). The shared `canonicalKeyOrder` helper (`src/util/`) is iterative, so it never throws on deeply nested model output. Handlers receive the same values; idempotency keys and loop fingerprints are already order-independent. Strategy 0 compaction summaries now name a call by its first string argument in the tool's declared parameter order, since input order is now alphabetical. Tests cover a real-Postgres round trip through postgres-js, a PGlite round trip, four loop paths and a seeded randomized comparison of the helper.
