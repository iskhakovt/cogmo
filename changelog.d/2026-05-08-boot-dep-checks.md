Boot-time dependency checks. `bootstrap()` in `src/index.ts` now probes three external dependencies that production code paths previously assumed silently, failing fast at boot rather than mid-turn after the user has already sent a message. Three checks land in a new `src/boot/checks.ts` module:

- **`checkUuidv7(db)`** — runs `SELECT uuidv7()` after `migrate()` returns. Schema PKs default to `uuidv7()` (`scripts/init-db.sql` installs it: native on PG18+, plpgsql fallback for older versions); a missing function turns every INSERT into a mid-turn `function does not exist` error in deployments that skipped the init script. Hard fail with a fix hint pointing at `scripts/init-db.sql`.
- **`checkS3Bucket(s3, bucket)`** — `HeadBucket` against the configured bucket right after the `S3Client` is constructed. Cheapest probe — no list, no read, no write. Confirms credentials work and the bucket exists before image / file / attachment tools start serving traffic. Hard fail.
- **`checkHindsightVersion(memory, compat)`** — `GET /version` against the running Hindsight server, parsed and compared against a `[min, max)` range. Hard fail when out-of-range (deterministic compatibility problem — e.g. against 0.5.x the async `retainBatch` path silently drops items past the first); soft fail (`logger.warn`, return) when `/version` itself can't be reached, since killing `serve` over a transient Hindsight blip is worse UX than letting memory tools surface their own errors at request time.

The Hindsight compat range is pinned in `package.json` under a custom `cogmo.hindsightCompat: { min, max }` key, currently `{ "min": "0.6.0", "max": "0.7.0" }`. Loaded once at boot via `loadHindsightCompat()` (Zod-parsed `JSON.parse` of `package.json` resolved relative to `import.meta.url`). Pinning as deployment metadata next to the npm client version (`@vectorize-io/hindsight-client: ^0.6.0`) keeps the two surfaces in step — anyone bumping the client sees the server pin and bumps it together — and unblocks future Renovate regex-manager rules that auto-open bump PRs against the field. Long term, once the upstream client exposes real `CLIENT_VERSION` (filed [vectorize-io/hindsight#1535](https://github.com/vectorize-io/hindsight/pull/1535)) and supported-server-range metadata, we'd consume that instead.

`HindsightMemoryProvider.getServerVersion()` is the new public method that backs the version check — calls `sdk.getVersion` directly without the retain/recall retry budget, since boot-time we want a fast yes/no rather than a 10-second backoff that hides the network problem. Throws on `error` or missing `data`. Errors classified as `BootCheckError` for any future `BootError`-aware entrypoint logic; serve-mode propagation is unchanged (constructor-style `throw`).

14 unit tests in `src/boot/checks.test.ts` cover: the package.json loader returns a Zod-valid range; uuidv7 success / failure paths with a fix hint in the error message; S3 success / failure with the bucket name in the error; version comparison across major-then-minor-then-patch (`0.10.0` is correctly NOT below `0.6.0`, which a string compare would get wrong), exclusive max boundary, prerelease/build suffix tolerance (`0.6.0-rc.1` parses as 0.6.0), unparseable-version hard fail, and network-error soft-fail (no throw, warn logged). Integration tests pass against the live Hindsight 0.6.0-slim container, exercising the real `/version` endpoint at boot.
