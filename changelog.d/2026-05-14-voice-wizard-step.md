Wire the setup wizard to configure voice (TTS + STT). New `stepConfigureVoice` after the image-providers step prompts for an OpenAI key dedicated to voice, picks a TTS model + voice, picks an STT model, then runs a 1-word TTS probe against `/v1/audio/speech` to validate the key before persisting. The probe failure path offers "save anyway" so a key the operator knows is good can still be stored when the network is flaky. The wizard reuses one `secrets` row for both `voice_config.tts_secret_id` and `stt_secret_id`; the FK split is preserved so a future TTS-on-ElevenLabs swap is a single column update. Re-running setup with an existing config offers keep / reconfigure / remove. `AgentStore` gains `upsertVoiceConfig` (singleton-aware `ON CONFLICT (singleton) DO UPDATE`) and `deleteVoiceConfig`; the previous raw-SQL insert pattern in tests is replaced. `design/voice.md` drops the stale `VOICE_TTS_API_KEY` / `VOICE_STT_API_KEY` env-fallback paragraph that contradicted the no-env-only-phase decision and was never wired in code.
