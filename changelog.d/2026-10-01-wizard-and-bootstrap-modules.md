The setup wizard and the server bootstrap are split by step and by stage, behaviour unchanged.

- **Wizard.** `setup/wizard.ts` (~1.8k lines) is `runWizard` over one module per step under `setup/wizard/` (LLM provider, models, Telegram, optional tools, image providers, voice, GitHub identity, Claude Code auth, Daytona, skills remote, Hindsight, summary), each with its own tests. Prompts, defaults, step order and non-interactive mode are unchanged. A credential and its "validated" mark are written in one transaction, so a crash can't leave a stored but unmarked secret, and `runWizard` reuses the transactor and secrets store `runSetup` builds.
- **Bootstrap.** `src/index.ts` (~1.35k lines) is `bootstrap()` over stage modules under `src/boot/`: core (stores, storage, LLM, memory), sandbox, skills, and runtime (coding, MCP, transport, agent), plus the web UI start and shutdown. Plain wiring, no container; construction order, the Inngest function list and shutdown order are unchanged. Dependency objects that were spelled out two or three times (the channel and web Transport deps, the agentic stage deps, the coding orchestrator deps) are built once, and the master key is parsed once.
