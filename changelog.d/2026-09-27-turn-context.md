The system prompt carries nothing per-turn. The time, recalled memories and reply modality lead each turn-starting user message as a turn context block, which a standing `# Turn context` section of the system prompt explains, so a new minute, a new recall or a voice turn no longer rewrites the cached prefix or the prompt preserved thinking is bound to. A `render-turn-context` step renders the block once, after compaction, and stores the exact text in a new `turn_contexts` table; later turns send it unchanged. Recalled memories sit in a data-not-instructions envelope, and a memory an earlier turn context still shows is left out. Chat turns cache for an hour; pipeline stage turns, which narrow the tool set, stay at five minutes until they share the chat prefix.

`prompt-caching.integration.test.ts` holds every request of a five-turn conversation to append-only (the previous code fails at turn 2's system prompt), and a replay-equality test pins a replayed turn's request bytes. Live, on Sonnet 5 and Opus 5.5 with preserved thinking enforced, each request read exactly what the one before it cached.
