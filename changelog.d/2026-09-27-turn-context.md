The system prompt carries nothing per-turn. The time, recalled memories and reply modality lead each turn-starting user message as a turn context block, and a standing `# Turn context` section of the system prompt says what the block is and how to write when it says `Reply modality: voice`. Alternating voice and text turns, a new minute or a new recall no longer rewrite the system prompt, so the next turn reads the cached prefix on every provider, and preserved thinking no longer sees an edited system prompt on every turn.

A `render-turn-context` step renders the block once, after compaction, and stores the exact text in the new `turn_contexts` table with its structured inputs (`TurnContextSchema`, whose `channelTypes` and `announcedCoreMemoryBlocks` stay empty until the system prompt snapshot); the loop sends the stored text and later turns load it, so a change of format or timezone reaches new turns only. The time is the user row's `created_at` in `USER_TIMEZONE`. Recalled memories sit in a data-not-instructions envelope a memory can't close, and a memory a surviving earlier turn context already shows is left out. Pipeline stage turns get the time and a text modality. Chat and stage turns cache for an hour (`retention: "long"`).

`prompt-caching.integration.test.ts` holds every request of a five-turn conversation to `assertAppendOnly` (the pre-change code fails it at turn 2's system prompt), and a replay-equality test holds a replayed turn's request bytes to a fresh run's. llmock keys drop the time line and recalled memories, and the chat cassettes are re-recorded. Live, on Sonnet 5 and Opus 5.5 with preserved thinking enforced, each request of a five-turn conversation read exactly what the one before it cached, and a turn after a 6.5-minute gap read the whole prefix.
