History contract hardening — agent-loop bug + retry-storm fix. Production incident: `claude-sonnet-4-20250514` returned a single `tool_use` block with `stop_reason: end_turn`; the streaming loop's "we're done" gate was `meta.stopReason !== "tool_use"`, so it returned without executing the tool, and `handle-message` persisted an orphan `tool_use` row. Every subsequent turn loaded that history, sent it to Anthropic, and got a 400 ("`tool_use` ids were found without `tool_result` blocks"); Inngest retried every 2 min indefinitely. Four changes ship together: (1) **content-driven flow control** in `runAgentLoop` + `runStreamingAgentLoop` — the early-return now keys off `content.some(b => b.type === "tool_use")`, not `stopReason`. The Anthropic contract is "every tool_use must be answered by a tool_result"; content presence is the only safe gate. Two regression tests cover `tool_use + stop_reason: end_turn` and `tool_use + stop_reason: max_tokens`. (2) **history invariant validator** at agent-loop entry (`src/agent/history-invariants.ts`) — pure function `validateHistory(messages)` returns `{ messages, repairs[] }`, repairing three violation classes: orphan `tool_use` (synthesize an error `tool_result` and merge with the next user message, including string-content user messages converted to a content block array), stray `tool_result` (drop the block; drop the message if it becomes empty), and empty content (drop). Defensive pre-flight: even after fix (1), historical orphans in the DB would still poison loads — the validator self-heals. 12 unit tests cover the matrix. Wired via a `sanitizeHistory` helper in `loop.ts` that logs repairs through `pino` so we can see whether stale state is still showing up. (3) **Provider-error → Inngest retry policy translation** in `handle-message.ts` — `isRetriableProviderError` (already in `src/llm/fallback.ts`) classifies the catch'd error; non-retriable (4xx except 408/425/429) is rethrown as `inngest.NonRetriableError` so Inngest fails the run on the first attempt instead of burning ~6 minutes of retries. Two regression tests: 400 → `NonRetriableError` with `cause` preserved, 429 → rethrown as-is. (4) **`onFailure` handler** + new `conversation/errored` event (`src/inngest/events.ts`) — after retries exhaust (or on `NonRetriableError`), the handler reaches the user via a new `DeliveryRouter.notifyConversation(conversationId, text)` method (off-path notification surface; bypasses source routing because there's no inbound cursor to anchor against, fans out to every active session via `transportStore.getActiveSessionsForConversation`, swallows per-session errors so one bad session doesn't block others, skips pure-StreamingAdapter sessions that have no `deliver` method) and emits `conversation/errored` with `{ conversationId, runId, errorClass, errorMessage }` for downstream consumers (PR2 recovery function, future evolution failure-reflector). Distinct from `response/ready` so the Hindsight Observer never sees errored turns — failed turns produced no user-facing assistant content, would only dilute the memory bank. New unit test covers the full handler shape. Two follow-up `p2` items added to `todo.md`: stuck-conversation watchdog cron, and evolution failure-reflector subscribed to `conversation/errored`.
