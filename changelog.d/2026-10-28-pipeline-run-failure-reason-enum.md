**`pipeline_runs.failure_reason` is an enum, and the run lifecycle is a documented state machine.** The column was free text built from interpolated messages, and the gate resolver's failure handler recognised a failure it had committed by comparing that text, so a different error class on the re-run went unrecognised and the "run has stopped" notice was lost. Now the reason is `pipeline_run_failure_reason` — `stage_error`, `unknown_stage`, `unsupported_stage`, `turn_degraded`, `turn_truncated`, `artifact_invalid`, `gate_resolution_error` for a failed run, `cancelled_by_user` or `gate_timeout` for a cancelled one — with the variable part in `failure_detail`, and the handler matches on the reason and the cursor. Two CHECKs make the half-states unrepresentable: a reason is set exactly when the run is `failed` or `cancelled` and belongs to that status, and a run parked on a gate never holds the claim on it. The migration backfills every recorded text onto its label and keeps the text as the detail. `design/pipelines.md` gains the run's state diagram, transition table and failure-mode table.
