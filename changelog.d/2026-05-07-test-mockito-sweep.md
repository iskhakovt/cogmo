Mockito-style mocks for project interfaces in tests. Adds `vitest-mock-extended@4.0.0` as a devDep and converts the `{ partial fields } as any` + `// biome-ignore lint/suspicious/noExplicitAny` stub pattern to `mock<T>()` from the new lib for project-owned interfaces — `MemoryProvider`, `SecretsStore`, `SkillStore`, `Service`. `mock<T>()` returns a typed `MockProxy<T>` with every method as a `vi.fn()`, so test code stays fully typed without the cast escape hatch. Five files swept (`src/skills/{ctx-handler,runner,runner.register}.test.ts`, `src/transport/adapters/telegram/skills-approval-poster.test.ts`, `src/agent/coding/tool.test.ts`); the remaining `as any` sites stay because they're either stateful test fixtures with custom call-tracking (the dockerode stubs in `supervisor.test.ts` / `reaper.test.ts`) or partial third-party types where only one method is exercised (`{ send } as any` for Inngest in `coding-flow.test.ts`) — `mock<T>()` adds noise without removing casts in those cases. Caught one auto-mock gotcha worth knowing: optional/nullable properties on the mocked type are auto-mocked too, so a test that asserts the property is `undefined` must explicitly assign `mock.foo = undefined` after construction (see `src/agent/coding/tool.test.ts`'s `service(undefined)` helper). `CLAUDE.md` Testing → Principles section gains a new bullet codifying the rule and both caveats. 2298 unit tests pass.
