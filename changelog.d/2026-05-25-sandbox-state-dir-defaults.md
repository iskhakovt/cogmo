**Sandbox host-state defaults moved under `/var/lib/cogmo/`.** `SANDBOX_ASKPASS_DIR` (`src/env.ts:229`) and `SANDBOX_PROXY_SOCKET_DIR` (`src/env.ts:217`) previously defaulted to `/run/cogmo/askpass` and `/run/cogmo/sockets` — the FHS-canonical runtime-state location on bare-metal systemd hosts, but root-owned tmpfs in an OCI container with no equivalent of `RuntimeDirectory=`. A cogmo deployment running as a non-root user (the shipping image's `USER node`, uid 1000) would `EACCES` on the first task's `mkdir` under either path, manifesting as `EACCES: permission denied, mkdir '/run/cogmo/askpass/<task-id>'` in under a second. Defaults are now `/var/lib/cogmo/askpass` and `/var/lib/cogmo/sockets`, matching the persistent-state root the Dockerfile already pre-creates and chowns to `node` (added `/var/lib/cogmo/sockets` to the same `mkdir -p` line). All other `COGMO_*_DIR` defaults already sat under `/var/lib/cogmo/`; the two `/run/cogmo/...` outliers are now consistent with the rest of the image. Bare-metal deployments that previously relied on systemd-managed `/run/cogmo/` directories must now either bind-mount their existing path through `SANDBOX_ASKPASS_DIR` / `SANDBOX_PROXY_SOCKET_DIR` overrides, or accept the new `/var/lib/cogmo/` location.

**Startup writability probe.** New `checkDirWritable(path, envVarName)` in `src/boot/checks.ts` runs `mkdir -p` then `fs.access(W_OK)` before the orchestrator accepts traffic; throws `BootCheckError` naming the env var and the override path on failure. Wired into `bootstrapSandbox` for `SANDBOX_PROXY_SOCKET_DIR` (local-docker only) and `SANDBOX_ASKPASS_DIR` (both backends — host-side `provisionAskpass` writes the files that the daytona `askpass-upload.ts` then ships into the sandbox). Replaces the previous "sub-second EACCES on first task that looks transient" failure mode with a loud boot-time crash carrying a concrete remediation. Three new unit tests cover happy path (missing dir created), idempotent path (existing dir), and unwritable path (env var name surfaced in the message).
