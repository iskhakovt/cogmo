Bundles four follow-ups from the deps-stack reviews:

- **`UV_CACHE_DIR` on the register-time compile sandbox** (`makeSandboxLockfileCompiler`). When the shared deps-cache volume name is configured, the compile sandbox mounts it at `/skill-venvs` and exports `UV_CACHE_DIR=/skill-venvs/.uv-cache` so wheel metadata fetched during compile is reused by every subsequent populate. Repeated registers drop from 5-30s (fresh PyPI fetch) to ~2s.
- **`COGMO_SKILLS_DEPS_VOLUME` documented + scoped per-deployment.** Default stays `cogmo-skills-deps-cache` (matches Docker Compose's "named volume with sensible default" convention); multi-instance deployments on shared infra must override (`...-staging`, `...-prod`) to avoid cross-mounting and the resulting "pre-stage a poisoned `<hash>/.ready`" trust scenario. DEPLOYMENT.md + `design/skills.md` -> Security posture call out the multi-tenant footgun.
- **Register-time Pyodide-compat pre-check** (`src/skills/pyodide-compat.ts`). For tier-1 (WASM) skills with declared deps, reads `pyodide-lock.json` from the installed pyodide package and verifies each `name==version` is either bundled exactly or has a pure-Python wheel on PyPI. Rejects register with `tier1_incompatible_dependency` otherwise. Closes the design-vs-implementation drift PR #325's review flagged.
- **Daily cache reaper for `/skill-venvs/`** (`src/skills/deps-reaper.ts` + Inngest scheduled function). Sweeps unreachable `<hash>/` directories older than 7 days by mounting the volume in a transient sandbox and running a `find` + `grep -qxF` filter against `skills.lockfile_hash` reads. Works for both LocalDocker and Daytona via the same `SessionSpec.depsCacheVolume` plumbing. Cron at 03:17 daily, singleton, retries=0 (next day's tick is the recovery mechanism).
