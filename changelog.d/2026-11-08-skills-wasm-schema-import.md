A wasm-tier skill's pydantic models are now its schemas (design/skills.md → Contracts).

- Register imports `skill.py` in a Pyodide child, started as a task's is (the boundary's flags, the run's memory cap, no network, the skill's packages). `Input.model_json_schema()` becomes `skills.inputs`, the LLM tool schema and the pre-flight check, and the `Output` model's serialization schema becomes `skills.outputs`. A skill that does not import, or whose model cannot be described, is rejected as `schema_import_failed`. A child that does not finish, or packages a retry may still fetch, is rejected as `schema_import_unavailable`.
- A model is its schema's one source: frontmatter `inputs` beside an `Input` model, or `outputs` beside an `Output` model, is refused. A skill with no `Input` model still declares frontmatter `inputs`. Container-tier skills keep their frontmatter until their import lands.
- Each deploy records the schemas it checked in `skill_deploys.schemas`. Approve and rollback put those live without running skill code, and fall back to the sha's frontmatter for a deploy that recorded none. A rollback to a sha with neither is refused as `schemas_unknown`.
