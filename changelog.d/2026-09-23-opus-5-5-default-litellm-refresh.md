**The current frontier models resolve real limits, and a fresh install starts on Claude Opus 5.5.** The bundled LiteLLM snapshot had drifted a month behind upstream, so every model released since — `claude-opus-5-5`, `claude-fable-5-1`, `gpt-6-astra` / `-sol` / `-luna`, `grok-4.7` — missed the snapshot entirely and fell through to the resolver's conservative 128k/4k default. That boots and answers, it just compacts turns that would have fit: a 1M-context model budgeted at 128k throws away seven eighths of its window, and the only signal is one `WARN` per model id. `pnpm tsx scripts/refresh-litellm-models.ts` takes the snapshot from 2,162 to 3,012 entries and every id above now reports `litellm` in `cogmo model list`.

The default org profile targets `claude-opus-5-5` instead of `claude-sonnet-5`. Anthropic direct is the adapter with the richest feature support — native `countTokens` (an exact compaction budget rather than the OpenAI-compatible path's tiktoken estimate) and prompt caching on the system prompt and the tool block — and Opus 5.5 leads the tool-loop benchmarks at $4/$20 per MTok, which a single-user deployment carries. Operators retarget it with `/model` as before; the id is only what a fresh DB starts on.

No adapter change was needed for the newer request surface. `AnthropicProvider` sends no `thinking` parameter, leaving each model on its own default (adaptive on the 5 series), and already drops `temperature` for Anthropic ids — the two shapes Opus 5.5 and Fable 5.1 answer with a 400.

The seeded id is now `DEFAULT_PROFILE_MODEL`, exported from `setup/seed.ts`, and `seed.test.ts` pins that it resolves from the snapshot rather than the fallback. A default the snapshot doesn't know breaks nothing loudly, so nothing else in the suite would have caught it — the failure mode is a quieter one, every fresh install compacting early forever.
