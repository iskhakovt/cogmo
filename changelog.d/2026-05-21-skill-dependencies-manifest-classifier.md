Add a `dependencies` field to the skill manifest (`SKILL.md`) for declaring direct Python dependencies in strict `name==version` form, with ranges, extras, URL/git refs, and bare names rejected at the schema layer. Register now requires a committed `requirements.lock` next to `skill.py` whenever the manifest declares dependencies, computes its sha256 atomically with `git_sha`, and persists it as the new `skills.lockfile_hash` column — the cache key for the per-lockfile-hash venv populator landing in a follow-up. The classifier folds declared dependencies into the risk decision: an allowlist of HTTP/data libraries (`httpx`, `pydantic`, etc.) stays auto-tier-eligible, an approve-list of cloud/financial/credential-bearing packages (`boto3`, `paramiko`, `stripe`, ...) forces `approve`, and anything in between bumps to at least `notify`. The wider deploy-time install path (uv binary in the runtime image, sandbox-side `uv pip compile`, populate with advisory lock + atomic rename, venv activation) is staged for the next PRs.
