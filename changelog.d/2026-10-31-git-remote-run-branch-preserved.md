**A failed git-remote coding task keeps its run branch.** On git-remote (Daytona) `cogmo/run/<task-id>` is the only copy of Claude's work from execute's push until verify publishes `cogmo/<idShort>`, so a verify failure no longer deletes it: `coding-cleanup-run-branch` keeps the branch on `coding/task/failed` and deletes it only on `coding/task/pr-opened`, resolving to a `kept | deleted | not_found | unavailable` outcome matched on the triggering event's payload. Its idempotency key carries the event name, so a `failed` for a task cannot swallow a later `pr-opened` for the same task. The weekly orphan sweep owns the eventual delete, and its 7-day retention clock now starts at `plan_approved_at` (falling back to `created_at`), read in a new `load-task-retention` step, so a plan's wait at the approval gate does not shorten the time a failed task's work stays fetchable.
