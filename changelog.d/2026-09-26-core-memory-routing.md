The agent's guidance and tool descriptions state what belongs in core memory: what every conversation needs (who the user is, active projects, standing preferences and constraints), written in the same turn it comes up, even in passing. Everything else goes to Hindsight through `memory_retain`. Onboarding saves to core memory, so the first block written ends it. The rule lives in design/memory.md → Core Memory vs Hindsight. A live eval (`core-memory-routing.live.test.ts`, 29 labelled cases including boundary cases such as a trip or a partner's promotion, each run with empty and existing core memory) measures the routing on the real prompt and tools, and with existing blocks checks what each write says. With existing blocks, every core fact reached its expected block, including facts mentioned in passing, no rewrite lost an existing line, and no other message wrote core memory; a finished project was marked completed rather than removed. With no core memory, 4 of 11 core facts reached it, against 3 of 11 before. The built-in tool and guidance lists move to `src/agent/built-ins.ts` so the eval builds the prompt production sends.
