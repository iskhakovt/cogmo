The agent's guidance and tool descriptions state what belongs in core memory: what every conversation needs (who the user is, including who their close family are, active projects, standing preferences and constraints), written in the same turn it comes up, even in passing. Everything else goes to Hindsight through `memory_retain`. Onboarding saves what it learns about the user to core memory, so the first block written ends it. The rule lives in design/memory.md → Core Memory vs Hindsight. A live eval (`core-memory-routing.live.test.ts`) measures the routing on the real prompt and tools: 29 labelled cases, including boundary cases such as a trip or a partner's promotion, each run with no core memory and with existing blocks, except a finished project, which runs only with existing blocks. It also checks which block each write targets and, with existing blocks, what a rewrite keeps. Over three samples per case, every core fact reaches an expected block with existing blocks, and 24 of 33 samples do with none (8 of 11 in each run), including 5 of 9 samples of facts mentioned in passing. No rewrite loses an existing line beyond those the case changes or drops, and no message worth storing nowhere writes core memory; with existing blocks, 2 of 27 Hindsight samples append a family member's detail (a birthday, a promotion) to `user_profile`. The known miss is a finished project, which the rule removes from `active_projects` and the agent marks completed instead. The built-in tool and guidance lists move to `src/agent/built-ins.ts` so the eval builds the prompt production sends.
