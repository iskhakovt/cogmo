The agent's guidance and tool descriptions state what belongs in core memory: what every conversation needs (who the user is, active projects, standing preferences), written in the same turn it comes up, even in passing. Everything else goes to Hindsight through `memory_retain`. Onboarding saves to core memory, so the first block written ends it. The rule lives in design/memory.md → Core Memory vs Hindsight. A live eval (`core-memory-routing.live.test.ts`, 25 labelled cases, each run with empty and existing core memory) measures the routing on the real prompt and tools. With the new guidance, every core fact reached core memory when blocks existed and most did from empty, including facts mentioned in passing, with no writes for facts that belong elsewhere. The built-in tool and guidance lists move to `src/agent/built-ins.ts` so the eval builds the prompt production sends.
