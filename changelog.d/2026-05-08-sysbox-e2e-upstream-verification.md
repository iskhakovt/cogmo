Verified that the `sysbox-e2e.yml` workflow installs genuine upstream Nestybox sysbox v0.7.0, not a community fork. The `.github/scripts/install-sysbox.sh` pin (`downloads.nestybox.com/sysbox/releases/v0.7.0/sysbox-ce_0.7.0-0.linux_amd64.deb`, SHA256 `eeff273671467b8fa351ab3d40709759462dc03d9f7b50a1b207b37982ce40a9`) is canonical and stays as-is.

The "community fork" concern stemmed from Nestybox's GitHub *Releases* page only listing up to v0.6.7 (May 2025). Investigation showed Nestybox simply stopped publishing GitHub Release objects after v0.6.7 while continuing to tag commits and ship binaries through their own infrastructure: the `v0.7.0` git tag is present on `nestybox/sysbox` (commit `2086179...`) with a CHANGELOG entry dated 2025-03-02 covering runc CVE-2025-3133/52881/52565 patches and sysbox-deploy-k8s K8s v1.33–1.35 support, and the .deb URL redirects to Nestybox's own GCS bucket (`storage.googleapis.com/sysbox-releases/`) with a last-modified timestamp of 2026-03-03. The downloaded .deb's SHA256 matches our pinned value exactly. Issue [nestybox/sysbox#996](https://github.com/nestybox/sysbox/issues/996) — filed 2026-03-11 asking for the v0.7.0 GitHub Release artifacts and unanswered by the maintainer as of 2026-05-08 — confirms the gap is upstream's process, not a fork. The repo remains actively maintained by Cesar Talledo (Nestybox CTO/co-founder) with commits through 2026-05-04.

Added a comment block to `.github/scripts/install-sysbox.sh` documenting this verification chain so future reviewers don't repeat the investigation. Also corrected the todo.md entry tracking the eventual `ubuntu-24.04` → `ubuntu-26.04` GHA runner bump, which had picked up the same incorrect "v0.7.x is NOT a real Nestybox release" claim while otherwise capturing accurate blockers (runner image not yet GA + sysbox broken on 26.04 per [issue #1005](https://github.com/nestybox/sysbox/issues/1005)).
