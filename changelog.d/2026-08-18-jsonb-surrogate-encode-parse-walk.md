`stringifyWellFormedJson` well-forms the parsed JSON value rather than the escape sequences of the JSON text.

The invariant it enforces is unchanged: a JS string can hold an unpaired UTF-16 surrogate, JSON text cannot, and Postgres rejects the `\udXXX` escape `JSON.stringify` emits for one with `22P02 invalid input syntax for type json`. Because `jsonbZod`'s `toDriver` is the single point where a JS value becomes Postgres JSON text, closing the gap there covers every JSONB column at once — including `messages.content`, where a lone surrogate arrives from a model through `tool_use.input` and, since the write lands after the turn's tool side effects, would otherwise fail identically on every Inngest retry.

The encoding sequence is `JSON.stringify` → fast-negative regex over the encoded text → on a hit, `JSON.parse` it back and walk that value applying `String.prototype.toWellFormed()` to every string and every key before re-encoding. Parse output is six shapes and no more — string, number, boolean, `null`, array, plain object — so the walk is total by construction: encoding first has already resolved a `toJSON` carrier to its replacement value, a class instance to the fields that got serialized, a boxed primitive to its primitive, an array hole to `null`. Nothing in the walk needs to know JSON escape syntax, so a string whose own text spells `\ud800` is data like any other and comes back verbatim. The round trip is only paid when the regex hits; the common path is one test over the encoded text.

Two keys differing only in their lone surrogates well-form to one key, and the last value wins — the rule Postgres applies to any duplicate key in `jsonb`.

Tests cover the shapes that separate the encoded text from the value graph it came from: a lone surrogate behind a value's own `toJSON`, in a field of a non-plain object, and inside a boxed `String`; text spelling a surrogate escape in either case; a `Date`; array holes; keys colliding after replacement; a lone surrogate between valid emoji pairs; and non-surrogate escapes. The strongest of them run through a real PGlite `jsonb` column, pinned against the raw `22P02` rejection the sanitising exists to prevent.
