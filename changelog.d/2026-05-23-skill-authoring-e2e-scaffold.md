Foundation for the chat -> `delegate_coding` -> `register_skill` -> skill-invoke integration test, plus the production fixes that surfaced while building the cassette-recording flow against real Daytona + Anthropic.

**Repro 1 (PTY stdout pollution).** The PTY-backed `claude -p` path in `src/sandbox/daytona/exec-pty.ts` sent `exec <argv> < stdin 2> stderr` into Daytona's default interactive bash; the shell echoed the typed line in cooked mode AND emitted OSC title sequences via `PROMPT_COMMAND` (even with `PS1=""`), polluting the JSONL parser's stdout with non-JSON noise that broke `runPlanStreaming` -> "plan phase produced no plan" 8 seconds after every fresh-deploy task. Three-layer fix: (Layer A) `readJsonl` in `src/agent/coding/jsonl.ts` now extracts JSON from the first `{` on each line rather than requiring it as the leading char — bash's final OSC icon-name sequence (`\x1b]1;exec\x07`) arrives with NO newline before claude's first `{"type":"system",...}` event, so a strict first-char-must-be-`{` filter drops the `system init` event and the orchestrator never captures `session_id`; (Layer B) the PTY shell line wraps the inner exec in `exec bash --norc --noprofile -c '<inner>'` so the default interactive shell is replaced atomically by a non-interactive bash — no readline, no `PROMPT_COMMAND`, no OSC chain after the initial swap; (Layer C, the load-bearing one for `--input-format stream-json`) the inner script now pipes stdin via `cat <tmpfile> | <cmd>` rather than `<cmd> < <tmpfile>`, because claude 2.1.138 silently exits 0 with zero output when stream-json input arrives via a regular file FD (vs a pipe FD). Also lifts the stderr-tmpfile-download failure log from `debug` to `warn` so the breadcrumb survives at `LOG_LEVEL=info` when claude exits silently. Upstream issue worth filing at `anthropics/claude-code`.

**Repro 2 (snapshot 409 race).** `daytona.snapshot.create` occasionally leaks a stub row when its internal retry re-attempts the same name after the "repository … not found" transient — attempt 0 fails, attempt 1 then 409s on the conflict, `withRetry` classifies 409 as non-retryable and propagates as a hard failure. `src/sandbox/daytona/client.ts` now wraps `#buildSnapshot` with one-shot `DaytonaConflictError` recovery: on 409, rebuild once under `<name>-r-<hex>`. The orphan stub stays in ERROR / REMOVING until Daytona's reaper drains it; we don't wait. Catches the every-fresh-deploy failure mode that the existing background-warmer's state-aware rebuild only fixed for the second invocation, not the first.

**`DaytonaMock` toolboxProxyUrl rewrite (test infrastructure).** The mock previously rewrote `toolboxProxyUrl` only on the `POST /sandbox` create response, so `sandbox.resume(sessionState)` -> `daytona.get(sandboxId)` returned the *original* `toolboxProxyUrl` and the SDK's axios `baseURL` was bound to real Daytona Cloud — every subsequent toolbox call from the resumed handle (`fs.uploadFile`, `createPty`, `executeSessionCommand`, ...) bypassed the mock and hit production. `src/test/daytona-mock.ts` now walks every JSON response recursively, replacing every `toolboxProxyUrl` field at any depth and populating the `{sandbox-id -> upstream toolbox URL}` map from each. List endpoints (`/sandbox/paginated`) that return arrays of sandbox objects are covered in the same pass.

**`DaytonaMock` binary WS frames.** PTY frames are binary (terminal output), but `WsFrameSchema` previously only carried `text`. Added a base64-encoded `bytes` field with mutual-exclusion with `text` enforced via `.refine`. Record-mode discriminates by `isBinary`; replay sends `bytes` frames as binary so consumers seeing `isBinary === true` on replay match the live-record signal. Three new tests cover schema invariants + record-mode + replay-mode round-trip.

**`DaytonaMock` body-secret redactor.** The existing `BodyRedaction` field-name rules only mask top-level JSON fields, so secrets nested two levels deep (`request.bodyJson.env.ANTHROPIC_API_KEY` from every `exec` request body) and credential-bearing fields the SDK happens to use under custom names (`git.password` carrying the bot PAT in `/git/clone` payloads) slipped past the mask. Added a last-line-of-defense string-pass on the serialized fixture that rewrites any `sk-ant-api03-*` or `gh[pousr]_*` / `github_pat_*` token to a stable placeholder before write. New test in `daytona-mock.test.ts` exercises both patterns.

**Container askpass dir moved to `/tmp/cogmo-askpass`.** `CONTAINER_ASKPASS_DIR` was `/.cogmo-askpass` (root of the container FS). Local-Docker bind-mounts work there because Docker root has write access. The Daytona toolbox uploads files via the SDK as the sandbox image's non-root user (`vscode` in cogmo-devbase), which can't `mkdir /<anything>` — every askpass upload errored with `mkdir /.cogmo-askpass: permission denied`. Moved to `/tmp/cogmo-askpass`, which is user-writable on every base image we ship. Local-Docker bind-mount works equally well at the new path (the mount target's parent doesn't need to pre-exist for `docker run -v`). Production fix — every Daytona-backed coding task was failing in `verify` until this landed. The test files that hardcoded the path got updated in the same diff.

**Daytona SDK patch (`patches/@daytonaio__sdk@0.175.0.patch`).** Bare `require('stream')` at `esm/utils/FileTransfer.js:320` and `esm/FileSystem.js:114`. The SDK's `scripts/post-build.js` prepends a `createRequire(import.meta.url)` shim to `Import.js` only and missed these two sites — works in plain Node, throws `ReferenceError: require is not defined` under vite-node / Vitest. Local patch replaces both bare requires with a top-level `import { Transform } from 'node:stream'`. Patch survives lockfile changes via `pnpm-workspace.yaml` -> `patchedDependencies`. Upstream issue worth filing at `daytonaio/sdk`.

**Test-only `codingAuthOverride` deps hook.** Added to both `CodingOrchestratorDeps` and `VerifyOrchestratorDeps` and threaded through `BootstrapOptions.codingAuthOverride`. Production `loadCodingSandboxEnv` resolution unchanged — missing `claude_code_oauth_token` still fails fast, no silent API-key fallback for users who forget to set the subscription token. The skill-authoring integration test injects `ANTHROPIC_API_KEY` (plus `ANTHROPIC_MODEL` and `MAX_THINKING_TOKENS` to pin the recording) into the sandbox env via this hook.

**Integration setup test-mode SANDBOX_ASKPASS_DIR.** `SANDBOX_ASKPASS_DIR` defaults to `/run/cogmo/askpass` for production (root-owned tmpfs, written by the cogmo service user). Integration tests run as the developer's user; redirect to a `mkdtemp`'d tmpdir we can mkdir into. Cleaned up in `teardown()`.

**Integration setup also opts into `LOG_LEVEL` override.** Default stays `warn` (noisy info-level logs would drown test output), but `LOG_LEVEL=info pnpm test:integration ...` is now honored for record / debug sessions.

**Test setup ORM migration.** `test/e2e-setup.ts` + `test/integration-setup.ts` swapped raw-SQL seed inserts (`sql\`INSERT INTO secrets ...\``) for typed Drizzle inserts using the same schema barrel the app does. Aligns with the project's code-style rule that `sql\`\`` is for fragments Drizzle's typed API can't express. Behavioral parity — same rows, same transaction boundaries.

**Tier 3 scaffold.** Test file at `src/test/skill-authoring.integration.test.ts` (gated via `describe.skipIf(!RUNNABLE)` so CI passes cleanly until cassettes are recorded), design contract at `design/testing.md` -> Skill-Authoring Integration `[proposed]`. The scaffold sets up a real `DaytonaSandboxClient` pointed at `DaytonaMock`, wires the cogmo-skills repo's `origin` to a throwaway GitHub repo via `COGMO_TEST_SKILLS_REMOTE`, seeds `github_identity:default` (PAT from `gh auth token`, ephemeral Ed25519 keypair for commit signing), and drives the chat -> register -> invoke flow end-to-end.
