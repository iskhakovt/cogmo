Profile-class backfill — `cogmo backfill profile-class --tag=<a,b> [--bankId=<id>]` stamps `profile_class:*` tags onto existing Hindsight memories so opting a profile into `profileClasses` scope doesn't blank recall on pre-feature rows. Pure mechanical re-retain (option B from PR #180's design discussion): `listMemories` → write JSON backup to `.dev/memory-backups/<bankId>-<iso>.json` → augment each row's `tags` with one `profile_class:<v>` entry per `--tag` value (rows already carrying any `profile_class:*` tag pass through unchanged) → `clearBankMemories` → `retainBatch` with the augmented rows, preserving original `network/compartment/trust` tags + `timestamp` + `metadata` + `context`. No LLM call in the loop — sidesteps the classifier-drift risk that the existing `migrateUntaggedMemories` path carries on already-correct compartment/trust labels. Idempotent: a second run on a fully-classed bank is a no-op (no clear, no retain). Verified by 11 unit tests + an integration test against real Hindsight covering the augment/skip/idempotent paths.
