Skills with declared dependencies now actually install and import them. On first invocation per worker per lockfile hash, the host shells `uv venv` + `uv pip sync --require-hashes --only-binary=:all:` inside the worker container — populates `/skill-venvs/<lockfile-hash>/` via tmp-dir + atomic rename, gated on a `.ready` marker for idempotent retries. The supervisor then activates the populated venv before forking each task child (prepends `<venv>/lib/pythonX.Y/site-packages` to `sys.path`, sets `VIRTUAL_ENV`, prepends `<venv>/bin` to PATH) so `import httpx` in skill code resolves against the skill's pinned version rather than the runtime's stdlib. The protocol gains an optional `skillVenv` field on `task_invoke`; the host computes and threads it from `skills.lockfile_hash` + the lockfile contents (read alongside SKILL.md / skill.py from git and cached). Populate failures (hash mismatch, yanked wheel) surface as `skill_venv_populate_failed` and poison the worker so a partial venv can't leak into the next task. The venv lives in the container's overlay FS today — survives across tasks on the same worker, vanishes on worker recycle; a persisted-volume mount for cross-worker reuse is a follow-up.
