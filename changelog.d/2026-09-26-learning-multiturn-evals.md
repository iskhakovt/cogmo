Two live evals measure how the agent learns across turns and conversations. `core-memory-multiturn.live.test.ts` runs scripted conversations that carry core memory from turn to turn: a core fact mentioned in passing mid-conversation, and a change that should replace the value it supersedes. `correction-learning.live.test.ts` puts a behavioural correction through two conversations, the Observer's correction extraction and graduation against PGlite, then checks whether a fresh conversation's reply follows the active rule, against a baseline without it. Both report rather than assert and share `src/test/live-eval.ts` with the core-memory routing eval: the production prompt, tools and agent loop, with core memory held in process and every other tool handler stubbed. `EVAL_REPEATS=N` samples every case of the live evals N times and reports pass counts per case and rates per run. On Sonnet 5, in one run, the agent writes each core fact in the turn it comes up and never leaves an old value as current, but keeps it in the block as history instead of removing it. Every correction becomes an active rule; the next reply follows three of four, and runs past a 100-word limit the rule sets. One extraction in 29 fails when the model omits `matchedExistingRuleId` twice.
