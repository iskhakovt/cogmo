Voice slice 1 — speech-to-text on inbound, text-to-speech on outbound, end-to-end through Telegram. **Provider abstraction:** `TtsProvider` and `SttProvider` interfaces in `src/voice/` mirror `LlmProvider`'s narrow surface, split so an operator can mix OpenAI STT with ElevenLabs TTS independently. `OpenAIVoiceProvider` ships with both directions (`gpt-4o-mini-tts` / `gpt-4o-mini-transcribe`); reuses the existing `openai` SDK; emits OGG/Opus directly via `response_format: "opus"` so Telegram's voice-bubble UI works without ffmpeg. **Inbound:** Telegram `bot.on("message:voice")` and `bot.on("message:audio")` upload OGG to `AttachmentStore`, emit a new `voice` content block with `{path, mediaType, durationMs}`; the orchestrator runs `step.run("transcribe-voice")` to substitute voice refs with text BEFORE persisting the user message — Inngest retries replay from the step cache rather than re-charging STT, OGG persists for audit/re-transcription, and the persisted `messages.content` carries the transcript directly so subsequent turns load cleanly. **Outbound:** new `Adapter.sendVoice(addr, {audio, mediaType})` capability flag; `DeliveryHandle` gains `canDeliverVoice()` and `deliverVoice(audio)` for fan-out (per-session resilience via swallow-and-log). After persist, the orchestrator TTSes `result.text` via the configured `ttsProvider` only when `resolveVoiceMode` returns true and the text is within the channel's cap. Streaming UX: text streams as today, voice clip arrives as a follow-up (Option B per design/voice.md — voice + transcript) so TTS failures never strand the user. **Resolution:** `resolveVoiceMode` is a pure helper consuming five gates (adapter capability, voice-config presence, conversation override, profile default, last inbound modality); decided once at turn-start, fed to prompt assembly AND delivery. **Schema** (migration 0021): `voice_mode` pgEnum (`auto`/`always`/`never`); `profiles.voice_mode` NOT NULL DEFAULT `'auto'` (mirrors `auto_recall`); `conversations.voice_mode` nullable (NULL = follow profile, so `/voice always` survives `/new`); `channels.voice_max_reply_chars` INT NOT NULL DEFAULT 700 (~60s of speech) — above the cap, TTS skips, text is already streamed; `voice_config` singleton table with FKs to `secrets` (credentials in encrypted DB rows from day 0 per design/decisions.md, no env-only phase). **Prompt injection:** `assemble-prompt` receives `voiceMode: boolean` and appends a voice-style hint ("response will be spoken aloud, prefer one or two sentences, no markdown/lists, skip filler acknowledgments") when active. **Telegram `/voice` command:** `/voice [auto|always|off|clear]` sets the per-conversation override via new `Transport.conversations.setVoiceMode`; bare `/voice` shows current effective mode + profile fallback.
