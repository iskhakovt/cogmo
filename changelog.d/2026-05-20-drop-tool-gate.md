Drop the runtime per-tool-call permission gate from coding delegation; the sandbox container is now the security boundary. Verifying the protocol against the official `@anthropic-ai/claude-agent-sdk` source confirmed that Claude Code only opens its stream-json `control_request` / `control_response` channel when `--permission-prompt-tool stdio` is passed (which the SDK only adds when `canUseTool` is supplied) — and Cogmo never passed that flag. The wrapper's "auto-allow plan-mode permissions" loop, the execute-mode `respondPermission` plumbing, the static policy table, the `coding_tool_decisions` decision log, the per-profile `coding_autoapprove_mode` toggle, the Telegram inline-keyboard permission flow, and the two `coding/task/permission-*` Inngest events were all wired against `control_request` frames that the CLI doesn't emit under our invocation; the entire stack was dead code that nevertheless wedged plan-mode runs because `runClaudePlan` kept stdin open waiting for control responses that never arrived, and the post-`result` `stdin.end()` couldn't traverse the Daytona session-command stdin proxy before the idle timer fired. Both runners now write the user prompt as a single stream-json frame and immediately close stdin (the documented graceful-shutdown signal for `--input-format stream-json`); the CLI runs to completion against `--allowedTools` defaults inside the sandbox, where sysbox isolation + Docker socket proxy + per-repo PAT scoping bound what can actually reach outside (`git push`, `gh` writes, outbound HTTP). Removes ~2,700 LOC of gate machinery and the `coding_tool_decisions` table + `profiles.coding_autoapprove_mode` column. The two human checkpoints that remain — plan approval and draft-PR review — provide the same end-to-end guarantee at lower complexity. See [design/coding-delegation.md → Sandbox isolation](design/coding-delegation.md) for the CLI invocation contract and the four flags that intentionally aren't passed.
