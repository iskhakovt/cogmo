Drop the runtime per-tool-call permission gate from coding delegation; the sandbox container is now the security boundary, and re-route `profiles.coding_autoapprove_mode` to the **plan-approval** gate instead. Verifying the protocol against the official `@anthropic-ai/claude-agent-sdk` source confirmed that Claude Code only opens its stream-json `control_request` / `control_response` channel when `--permission-prompt-tool stdio` is passed (the SDK adds that flag only when `canUseTool` is supplied) — and Cogmo never passed it. The wrapper's "auto-allow plan-mode permissions" loop, the execute-mode `respondPermission` plumbing, the static policy table, the `coding_tool_decisions` decision log, and the two `coding/task/permission-*` Inngest events were all wired against `control_request` frames that the CLI doesn't emit under our invocation; the entire stack was dead code that nevertheless wedged plan-mode runs because `runClaudePlan` kept stdin open waiting for control responses that never arrived, and the post-`result` `stdin.end()` couldn't traverse the Daytona session-command stdin proxy before the idle timer fired. Both runners now write the user prompt as a single stream-json frame and immediately close stdin (the documented graceful-shutdown signal for `--input-format stream-json`); the CLI runs to completion against `--allowedTools` defaults inside the sandbox, where sysbox isolation + Docker socket proxy + per-repo PAT scoping bound what can actually reach outside (`git push`, `gh` writes, outbound HTTP). PR #308's `coding_autoapprove_mode` column and `/profile autoapprove` Telegram subcommand keep their names but now control the orthogonal plan-approval gate: when `on`, the plan orchestrator stamps `plan_approved_at` and emits `coding/task/plan-approved` itself once the plan text persists, skipping the Telegram approve/revise/cancel round trip — the plan still streams to Telegram for visibility. Removes the `coding_tool_decisions` table + the `tool_decision` / `decision_scope` enums; keeps `profiles.coding_autoapprove_mode` + the `coding_autoapprove_mode` enum re-purposed to plan approval. The two human checkpoints that remain — plan approval (skippable per profile) and draft-PR review — bracket an unattended execute phase that runs inside the sandbox. See [design/coding-delegation.md → Sandbox isolation](design/coding-delegation.md) for the CLI invocation contract and the four flags that intentionally aren't passed, and [Plan gate → Per-profile auto-approve](design/coding-delegation.md) for the re-routed semantic.
