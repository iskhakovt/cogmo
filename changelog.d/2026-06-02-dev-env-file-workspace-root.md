Fix `pnpm dev` (and the other dev/test entrypoints) loading the wrong `.env` after the workspace split. The `cogmo` package now lives at `apps/server/`, so pnpm runs its scripts with that as the cwd — but the `dev` / `dev:app` / `console` / `dev:infra` scripts still passed `--env-file-if-exists=.env`, which resolved to `apps/server/.env` and silently missed the repo-root `.env` (Node printed "`.env` not found. Continuing without it." and `pnpm dev` then died on the missing `ANTHROPIC_API_KEY`). The integration and e2e test setups had the same latent bug in their `loadEnvFile(".env")` guard, so `RECORD=1` runs missed the root keys too.

All of these now resolve the root `.env` via `../../.env` (relative to the `apps/server` cwd). The repo root stays the canonical home for `.env` — that's where `.env.example` lives and what the root `.gitignore` ignores. The `console` script's second `--env-file-if-exists=.dev/env` is unchanged: that scratch env is written under `apps/server/.dev/` and is already package-relative.
