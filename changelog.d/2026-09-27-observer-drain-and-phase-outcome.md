The pending-memory drain retains each staged row as the Hindsight document named by the row's id. Retain and delete are separate steps, so a delete that fails for good leaves the row pending and the next Observer fire retains it again; Hindsight upserts on `document_id`, and a re-retain of unchanged content only refreshes the document's tags and metadata, so the repeat leaves one copy. `RetainBatchItem` gains an optional `documentId`; transcript extraction, which has no durable id per fact, still gets a fresh document per item.

The `evolution_events` payload records which Observer phases failed after their step retries, as `failedPhases` (`corrections` / `consolidation` / `memories` / `drain`, in run order, `[]` for a clean fire). A failed phase's zero counts are its fallback, and `/learned` says so: a digest line ends `; failed: …`, and the detail view shows `failed after retries` in place of the phase's counts. The web cockpit's evolution table gains an Outcome column and the same marker in its detail drawer. The field is optional with no default: rows recorded before it existed read back without it and render as before, since whether their phases failed is unknown. No SQL migration; the column is JSONB. The contracts parity guard also compares the `Required` form of the payload, which catches an optional field missing from one side.
