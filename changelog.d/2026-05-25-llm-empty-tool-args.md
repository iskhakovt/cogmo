Streamed tool calls with no arguments now yield `input: {}` instead of tripping the `stream_truncation` repair budget. Both Anthropic and OpenAI-compatible adapters were calling `parseProviderJson("")` on a tool block that emitted zero `input_json_delta` events (the canonical streaming shape for a zero-arg tool); `JSON.parse("")` and `jsonrepair("")` both throw, so the adapter raised `ProviderProtocolError`, the agent loop classified it as `stream_truncation`, and the non-streaming replay consumed the per-turn budget. Two zero-arg tool calls in the same conversation pushed the second turn past the budget and into the degraded-synthesis off-ramp.

Both adapters now treat empty / whitespace-only accumulated arguments as `{}`, matching the non-streaming SDK shape. `parseProviderJson` stays strict for non-tool callers (e.g. `chatTyped`'s structured-output parsing).
