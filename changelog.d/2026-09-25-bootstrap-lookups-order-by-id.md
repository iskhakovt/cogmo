`getDefaultProfile`, `getFirstUser` and `getChannelByType` order by `id` (UUIDv7, so creation order) and return the oldest matching row. A `LIMIT 1` without `ORDER BY` has no defined row, and in practice an in-place `UPDATE` changes which one comes first. That matters for the default profile: after a data migration rewrites the seeded org profile (as `0019` rewrites `profiles.model`), a restart could boot with another profile's model and tool set. The user and channel orderings are defensive, since setup creates one user and keeps one channel per type. PGlite store tests pin all three.
