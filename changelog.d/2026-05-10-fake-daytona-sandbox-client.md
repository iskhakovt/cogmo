New `FakeDaytonaSandboxClient` (`src/test/daytona-sandbox-fake.ts`) for integration tests that exercise the orchestrator's `git-remote` worktree branch without paying for a Daytona Cloud account or pulling a 10-service self-hosted compose. Implements the full `SandboxClient<DaytonaSessionState>` contract host-side: `create()` clones the requested run-branch into a host temp dir, askpass material is mirrored locally with `helper` script paths rewritten to the real host paths, and `execStreaming` runs commands on the host via `child_process.execFile`. Capability shape (`workingTreeTransport: "git-remote"`, `hostBindMount: false`, `volumes: "managed"`, etc.) matches the real `DaytonaSandboxClient` so capability-aware orchestrator code branches identically.

What this fake exercises end-to-end: the orchestrator's `pushTaskBranchToRemote` → `WorktreeSpec.git-remote` construction → sandbox-side clone → post-create `git checkout -B cogmo/<idShort>` → host-side `runCommitAndPush` → post-PR `fetchFeatureBranch`, plus the cleanup-event-subscriber paths. New integration test arm in `verify-orchestrator.integration.test.ts` runs the full verify→push→PR sequence against the existing Gitea testcontainer using this fake — pushes the run-ref upstream, sandbox clones it, feature branch lands on Gitea, scoped octokit captures the PR-create call, local mirror's `refs/remotes/origin/cogmo/<idShort>` updates via `fetchFeatureBranch`. 21 unit tests for the fake itself + 1 new integration test (3 total in the verify file).

What the fake deliberately does NOT exercise — gap covered by the deferred Phase 3c.6 self-hosted-Daytona conformance suite: SDK payload shape drift, WS framing in `getSessionCommandLogs`, exit-code race in natural-close→`getSessionCommand`, auto-stop / archive state-machine in `tryResumeByTaskId`, `refreshActivity` keepalive contract, image-pull / snapshot-build error paths.
