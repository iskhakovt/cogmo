The OpenAI-compatible adapter sends a reply's token cap as `max_completion_tokens` to OpenAI's reasoning models (the o-series and GPT-5 onward, by bare id), which reject `max_tokens` with a 400, so a direct OpenAI row can serve them. Every other model keeps `max_tokens`, including OpenRouter's `openai/…` slugs, which OpenRouter accepts it for. Live scenario D's OpenAI route runs on `gpt-5.4-nano`.
