ZeroEntropy shut down. The company was acquired by Notion and sunset every hosted product on 2026-09-04, which retired `zerank-2` — the reranker `design/memory.md` had prescribed for production since the provider comparison was first written. The model weights are Apache-2.0 on HuggingFace, but only as an H100-class self-hosting exercise that personal scale does not justify, and no gateway resells them.

Production now points at `voyageai/rerank-2.5` through Hindsight's native `openrouter` reranker provider, which lands on the OpenRouter account already serving Hindsight's LLM and embeddings — the key falls back to `HINDSIGHT_API_LLM_API_KEY`, so the swap adds no credential. The reranker line of the cost estimate roughly doubles, from ~$4/mo to ~$8/mo, because rerank-2.5 is $0.05/M tokens against zerank-2's $0.025/M; `voyageai/rerank-2.5-lite` gives most of that back for 24 points of Agentset ELO.

The config now ends in an `rrf` failover member. Hindsight is not fail-open by default — an unreachable reranker takes the whole recall call down with it — and `recall` blocks the interactive path, so the chain is load-bearing rather than defensive. Members are tried in order with no circuit breaker, so the primary's timeout is pinned below the 5s recall budget `HindsightMemoryProvider` enforces; otherwise a dead primary burns the client's entire budget before the fallback is reached.

The reranker docs also stopped implying that RRF is a reranker. It is the fusion stage that combines Hindsight's four retrieval arms and always runs; `HINDSIGHT_API_RERANKER_PROVIDER=rrf` selects *no* cross-encoder and keeps the fused order. The comparison table listed it as a peer with an ELO-shaped quality figure, which made "RRF vs a reranker" look like a choice of algorithm rather than a choice of whether to rerank at all.

On the test side, `hindsightSlim()` loses its `rerankerProvider` / `rerankerApiKey` / `rerankerBaseUrl` options. The `zeroentropy` branch behind them was never reached — none of the three callers (`integration-setup.ts`, `e2e-setup.ts`, `record-fixtures.ts`) ever passed a provider, so every run took the `?? "rrf"` default. Reranking is now pinned to `rrf` in the factory, which is what the recorded fixtures were captured against and what keeps the tier hermetic.

No runtime behaviour changes here. Production reranker config lives in the deploy environment, not in this repo, so switching the running Hindsight over is a separate operational step — a gap now tracked in `todo.md`, since nothing in CI or the test tier could have detected that the documented production reranker had gone dark.
