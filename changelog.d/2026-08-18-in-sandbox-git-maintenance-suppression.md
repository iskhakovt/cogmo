**In-sandbox `git commit` / `git push` run with background maintenance suppressed.** Both commands spawn a detached `git maintenance run --auto` that keeps writing inside `.git/` — new packs, `objects/info/packs`, `info/refs` — after the foreground command exits. A task working tree is a standalone clone, so that `.git` sits inside the very directory teardown deletes once the task settles, and on the bind-mount backend `/workspace` in the container *is* that host tree. A detached writer inside the sandbox therefore repopulates directories mid-delete, `fs.rm` fails with `ENOTEMPTY`, and what remains is a half-deleted clone at a per-task-stable path that blocks the next `allocateWorktree` there.

`runCommitAndPush` prepends `-c maintenance.auto=false -c gc.auto=0` to every in-container git argv, in the one helper that builds it, so a new call site inherits it. The environment it hands to the exec is the caller's `askpassEnv`, untouched.

Config on the argv rather than in the environment, because `GIT_CONFIG_COUNT` numbering only composes if you can enumerate every pair already declared, and the container's ambient environment is not visible from the host. Writing it blind overwrites index 0 of whatever is there — `safe.directory` being the entry that makes this concrete, since it is what gets added when a bind mount's owner uid doesn't match the exec user, and shadowing it makes git refuse the worktree outright.

Teardown keeps the environment form, and keeps it to itself: on the host the whole environment is built here from `process.env`, so appending pairs after any already declared is safe, and its tests pin that against real git. `maintenance.auto=false` is the setting that stops the spawn either way; `gc.auto=0` gates the work the spawned process would find rather than the spawn, and rides along for the older `gc --auto` path.

Tests that locate a git call now match the subcommand past any leading `-c` pairs instead of at a fixed argv index, which survives further flags rather than trading one hardcoded offset for another.
