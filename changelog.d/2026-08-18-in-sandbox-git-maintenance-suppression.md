**In-sandbox `git commit` / `git push` run with background maintenance suppressed.** Both commands spawn a detached `git maintenance run --auto` that keeps writing inside `.git/` — new packs, `objects/info/packs`, `info/refs` — after the foreground command exits. A task working tree is a standalone clone, so that `.git` sits inside the very directory teardown deletes once the task settles; on the bind-mount backend `/workspace` in the container *is* that host tree, so a detached writer inside the sandbox repopulates directories mid-delete and `fs.rm` fails with `ENOTEMPTY`, leaving a half-deleted clone at a per-task-stable path that then blocks the next `allocateWorktree` there. `runCommitAndPush` now threads `maintenance.auto=false` / `gc.auto=0` into the env record every in-container git invocation carries, alongside the askpass credentials. The pairs come from a shared `noBackgroundMaintenanceEnv` helper that host-side teardown uses too, so both sides of the sandbox boundary suppress the same writer through one definition; the `GIT_CONFIG_*` entries are numbered after whatever pairs the caller's env already declares, leaving an ambient injection (a `safe.directory` entry, a wrapper script) intact.
