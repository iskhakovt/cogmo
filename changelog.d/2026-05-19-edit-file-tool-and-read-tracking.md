Added `edit_file` agent tool and tightened `write_file` so overwrites of existing files require a prior read in the same conversation turn. `createFileService` now keeps a per-instance read cache (content, S3 `LastModified`, partial-view flag); reads populate it, writes and edits gate on it. mtime drift since the read triggers a content fallback — bytes that genuinely changed reject the operation with "modified since you read it", a benign re-upload of identical bytes refreshes the cache and proceeds. Reads larger than `MAX_READ_LENGTH` (100 KB) now mark the entry as a partial view and block subsequent edits/overwrites until the file is re-read. `edit_file` does exact-string replacement with a unique-anchor default (errors on 0 or >1 occurrences) and `replace_all` for batch replacements. Truncation policy moved from the tool layer into the service so the partial-view flag tracks what the model actually saw.
