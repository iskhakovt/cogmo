**postgres-js 4: the bootstrap lock accepts a pool size from `DATABASE_URL` or `PGMAX`.** postgres-js 4 opens as many connections as a `?max=` or `PGMAX` string's number, so `cogmo serve`, `cogmo seed`, `cogmo setup` and `pnpm db:migrate` start with `?max=5`, and refuse a pool under two connections or a `max` that isn't a number, which opens none. Queries through Drizzle behave as on 3.4.9 although the server now types every parameter, since Drizzle hands dates and JSON to the driver as strings: timestamps, `jsonb`, booleans, SQLSTATEs on the error's `cause` and savepoint rollback are unchanged, and a raw `Date` in a `sql` fragment is still rejected. The release's other breaking changes (`sql.array()`, ESM-only, released-connection reuse, unsafe `BEGIN`) touch nothing cogmo calls.
