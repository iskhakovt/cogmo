**A late reply now stops before it streams.** Each `llm-iter<N>` step of `handle-message` first asks `isTurnSuperseded`, before it calls the provider. That use case asks the persist check's two questions in one transaction, over rows newer than the reply admission found: has another run of the batch already replied on the turn's cursor (`TranscriptStore.isCursorAnswered`, new), and has a later turn row re-batched the cursor (`isCursorRebatched`)? If either holds, the step stores `{ kind: "superseded" }` and the loop stops without calling the provider or emitting anything. `finish-stream` closes the stream as finished, and the run ends `skipped: superseded` without `degraded-reply`, `persist-new-messages`, delivery or announcements. Remaining residuals are in design/crash-recovery.md → Late replies: an iteration that started before the covering row committed still streams, and the stream closes with whatever it holds at the stop. That can be earlier iterations' output, a failed attempt's fragment or a status banner, and none of it gets a transcript row.
