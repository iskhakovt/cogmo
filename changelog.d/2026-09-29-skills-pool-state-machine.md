The skills warm pool runs on a pure state machine (`worker-sysbox/pool-state.ts`) that `SysboxWorkerPool` shells, like the worker channels. Every transition ends in one level-triggered `reconcile`: it grants idle workers to the oldest waiters and spawns for each waiter and for any shortfall to `min`, so no waiter waits on nothing whichever event queued it, and a grant the worker refuses requeues its waiter. A waiter's worker counts toward `min`, so freed slots spawn only for the waiters queued. A worker's `dead` resolves with who ended it, `host` or `worker`, so the crash-loop cap needs no side set, and every acquire pending at disposal fails as `disposed before worker available`. A transition table, five properties over 3,000 seeded schedules and the pool fuzz (run to 20,000 seeds) cover it; each of 25 mutations of the machine is caught.
