Per-skill virtualenvs are now keyed by both the lockfile hash AND the runtime's Python ABI. The path becomes `/skill-venvs/<lockfile_hash>-py<major>.<minor>/` (e.g. `...-py3.14/`); previously just `/skill-venvs/<lockfile_hash>/`. Closes the wedge that the next `cogmo-skills` image bump changing Python minor would have triggered: stale venv at `<hash>/lib/python3.14/...` while the new supervisor looked for `lib/python3.15/...` -> `RuntimeError: skill_venv has no site-packages`. The populate script and supervisor both compute the ABI from their own `sys.version_info` (same image, same Python), so they agree by construction; the host doesn't need to know the image's ABI. The `task_invoke` protocol now carries `lockfileHash` instead of `skillVenv` (full path), since the supervisor constructs the venv path on its side. Reaper widens its regex to match both legacy bare-hash dirs and the new ABI-suffixed shape, and strips the suffix before reachability lookup. Includes a Python-side regression test that pins the ABI-in-path contract (`test_skill_venv_path_includes_python_abi`).
