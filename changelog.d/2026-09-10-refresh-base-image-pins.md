**Dependabot's Node major-block now matches the dependency it names, and the pins it was starving are refreshed.** `.github/dependabot.yml` ignored `dependency-name: node`, but Dependabot calls this image `library/node` — visible in the title of the digest bump it did land, #290 *"bump library/node from `03eae3e` to `24dc26e`"*. The rule matched nothing, so four major PRs (#227, #352, #401, #408) were opened and closed by hand after it was added, and no digest update has arrived since May.

The runtime base moves to the current `node:24-trixie-slim` digest, which carries **Node 24.21.0** in place of the 24.19.0 the image had been shipping. `uv` goes 0.12.5 → 0.12.12 and `@anthropic-ai/claude-code` 2.1.233 → 2.1.267, both ARG-pinned and likewise untracked. Each version lives in four places — `docker-bake.hcl`, `images/devbase/Dockerfile`, `.github/workflows/ci.yml`, and for uv also `images/skills/Dockerfile` via bake — and `version-pins.test.ts` enforces the match.

Two pins were already current and are left alone: `mcr.microsoft.com/devcontainers/base:ubuntu-24.04`, whose digest is byte-identical to upstream, and `python:3.14.7-slim`, which Dependabot bumped in #451.

The devbase CVE surface is not a pin problem, and a bump does not move it. That image runs `apt-get upgrade -y`, so its package versions are fixed at *build* time — and nothing triggers a build. `publish.yml` runs on `workflow_call` and `workflow_dispatch` only, the base digest hasn't changed so Dependabot opens nothing, and the published image therefore still carries the packages that were current on 2026-08-17. Rebuilding it today from an unmodified Dockerfile takes curl from `8.5.0-2ubuntu10.11` to the patched build and vim from `2:9.1.0016-1ubuntu7.18` to `7.20`, clearing 20 of the 24 vim/curl findings; the four that remain (CVE-2026-51400, CVE-2026-51401) have no Ubuntu fix published. Under the filter `publish.yml` actually reports on — HIGH/CRITICAL, `ignore-unfixed` — the rebuild goes from 11 findings to 4, all seven resolved being `linux-libc-dev`, and introduces none.

Merging this releases, and a release rebuilds every image, so the staleness clears as a side effect. That it takes a release to do so is the underlying gap: image CVE exposure here is a function of time since last build, and nothing schedules one.
