**Dependabot's Node ignore rule names `library/node`** — the dependency name Dependabot uses for the runtime base image. A rule naming `node` matches nothing and blocks no major, and majors here are a once-a-year manual call on the LTS cadence.

The pins it governs are current: the runtime base carries **Node 24.21.0**, `uv` is 0.12.12, `@anthropic-ai/claude-code` 2.1.236 — its `stable` dist-tag, since `latest` and `next` point at the same build and following it would run the sandbox CLI ahead of the stable rollout. They are mirrored in different numbers of places and guarded unevenly: `uv` spans four sites (`docker-bake.hcl`, `images/devbase/Dockerfile`, `images/skills/Dockerfile` via bake, and `ci.yml`'s `setup-uv`) and `claude-code` two (bake and devbase), both held together by `version-pins.test.ts` along with npm and pnpm. The node digest is a single line in the root `Dockerfile` with no such guard — devbase installs Node from nodesource and CI pins the major, so neither mirrors it. `uv` and `claude-code` are ARG-pinned rather than `FROM`-pinned, which puts them outside Dependabot's reach; they move by hand. `devcontainers/base:ubuntu-24.04` and `python:3.14.7-slim` already sit on their upstream digests.

**devbase's CVE surface is a build-time property, not a pin.** It runs `apt-get upgrade -y`, so its packages are whatever was current at build time; `publish.yml` builds on `workflow_call` and `workflow_dispatch` only, and an unchanged base digest gives Dependabot nothing to trigger on. Exposure therefore tracks time since the last release rather than any pin going stale. A rebuild takes curl to the patched `8.5.0-2ubuntu10.12`/`.13` and vim to `2:9.1.0016-1ubuntu7.20`, clearing 20 of the 24 vim/curl findings — CVE-2026-51400 and CVE-2026-51401 have no Ubuntu fix — and under the filter `publish.yml` reports on (HIGH/CRITICAL, `ignore-unfixed`) goes from 11 findings to 4, seven `linux-libc-dev` resolved and none introduced. A scheduled rebuild is the standing fix; nothing schedules one.
