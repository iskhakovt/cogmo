**Integration and e2e teardown stop containers before the host-side mocks.** Containers reach llmock through the testcontainers SSH forwarder: `ssh-remote-port-forward` (1.0.4, the latest release, which `testcontainers` 12.1.0 still depends on) dials the host port from the Vitest main process for every forwarded connection and attaches no `error` listener to that socket. A container calling llmock once llmock has stopped — Hindsight finishing background work, typically — raises an unhandled `ECONNREFUSED` and kills the process, so a job whose every test passed exits 1 with an `AggregateError` pointing at llmock's port. `test/integration-setup.ts`, `test/e2e-setup.ts` and `scripts/record-fixtures.ts` stop their containers and network first and llmock last, so no container that can open a forwarded connection outlives it. The test setups stop llmock only when every container stopped; if one didn't, llmock stays up until the process exits right after teardown. The Telegram and MCP echo mocks aren't forwarded and stop alongside llmock. A standalone reproduction — an alpine container polling an exposed host port — crashes with the same trace when the server stops first and exits cleanly with the containers stopped first.
