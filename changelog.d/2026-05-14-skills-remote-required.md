Skills repo's remote is now a first-class requirement, synchronized with `register` instead of treated as optional backup. The original `design/skills.md` model — local bare repo authoritative, remote optional for off-host sync — was written when Local-Docker bind-mount was the default coding backend. Once Daytona's `git-remote` working-tree transport (`design/sandbox.md` → Daytona Backend) became the production path, the Daytona sandbox started cloning from `coding_repos.skills.remote_url` for every delegation, but `register` only advanced `refs/heads/main` on the local bare repo and `ensureSkillsCodingRepo` silently inserted rows with `remote_url=""`. The result was `delegate_coding({ repo: "skills" })` failing at `allocate-worktree` with "remote_url is empty" on every fresh deployment, plus a quieter divergence where successful registers left the remote stale.

Surface area:

- **`design/skills.md` → Repo location / Repo invariants** rewritten: remote is required (any provider — GitHub, Gitea, Forgejo, sourcehut), three operator-facing modes (own URL / GitHub auto-provision / skip), local-authoritative model preserved (filesystem `update-ref` is still atomic; the new mirror push is the second leg). The `pre-receive` hook reframed as secondary defense — primary `main`-gate is now operator-configured remote branch protection. `design/coding-delegation.md` gains a "Skills repo special case" paragraph in the `coding_repos` schema notes flagging the bare-repo `local_path` and the post-`register` push.
- **`src/skills/configure-remote.ts`** new shared helper. `configureSkillsRemote({deps, mode})` with discriminated `own / auto-provision / skip` modes. Validates URLs via `parseRemoteUrl` + `git ls-remote`, refuses empty remotes (no `refs/heads/main` to fetch), attaches/replaces `origin` on the bare repo, fetches main, calls `ensureSkillsCodingRepo` to sync the DB row. Idempotent; same URL twice is `unchanged`. 7 unit tests against on-disk bare repos cover skip / invalid URL / unreachable / empty-remote / happy path / idempotency / GitHub 422.
- **`ensureSkillsCodingRepo`** (`src/skills/repo.ts`) tightened from "insert with whatever origin reports, including empty string" to a discriminated upsert: `skipped_no_origin` (no DB write when bare repo lacks `origin`), `created` (first insert), `updated` (origin moved — uses new `CodingStore.updateRepoRemoteUrl`), `unchanged`. The "remote_url=`''`" code path that motivated the failure is now unrepresentable. Test file rewritten to assert each variant; `authoring-bootstrap.test.ts` updated to attach origin in `setupRepos` (mirroring the new production flow).
- **Wizard step** (`src/setup/wizard.ts:stepConfigureSkillsRemote`) slotted between Daytona (step 8) and Hindsight check (now step 10). Bootstraps the bare repo idempotently, offers keep/replace when origin is already attached, otherwise prompts own / auto-provision / skip. Auto-provision option only shown when a GitHub identity is configured — gated to that one provider because the convenience lives in the wizard only, with no permanent per-provider client code anywhere else.
- **`cogmo migrate-skills-remote`** new standalone CLI (`src/skills/migrations-cli.ts`, dispatched from `src/main.ts`). Same three-way UX the wizard offers, reachable without re-running the full setup flow. Backup-before-mutate to `.dev/skills-backups/<timestamp>.json`, matching the `cogmo migrate-memories` convention. Used for two scenarios: existing deployments with the `remote_url=""` bug, and post-setup remote swaps (e.g. GitHub → self-hosted Gitea).
- **`register` / `approveDeploy` / `rollback`** (`src/skills/runner.ts`) now mirror the new `main` SHA to `origin` after the DB transaction commits. Register and approve use fast-forward push (rejects loudly if the remote has drifted); rollback uses `--force-with-lease=refs/heads/main:<observedMainSha>` (rollback is intentionally non-fast-forward, but the lease catches concurrent remote moves). The mirror is **non-blocking** — push failures log a warning and leave the local advance in place, so a network blip or revoked credential can't roll back a tx that already committed. Two new tests in `runner.register.test.ts` cover both the happy mirror path (remote main equals registered SHA) and the failure path (register reports `live` even when origin is unreachable).
- **`CodingStore.updateRepoRemoteUrl(tx, id, remoteUrl)`** added — narrow single-field mutation, the only update the otherwise insert-once `coding_repos` table now accepts. Doesn't loosen the "prefer immutable rows" invariant for any other column.

Operators on an existing deployment with `remote_url=""` run `cogmo migrate-skills-remote` once to attach a remote — fresh installs are guided through the wizard step. The local bare repo at `$COGMO_SKILLS_PATH` stays as a fetch-only mirror of the authoritative-for-`register` ref store; the remote is the off-host sync surface that the Daytona sandbox clones from.

Verified by 3146 unit tests passing; typecheck + lint clean.
