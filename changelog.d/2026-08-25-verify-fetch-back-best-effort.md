**The verify orchestrator's post-PR fetch-back is best-effort.** `fetch-feature-branch` refreshes the host mirror after the sandbox pushes `cogmo/<idShort>` to origin, and it swallows its own failure — the catch sits inside the step body, so the step records success and a mirror lagging origin surfaces as a warning naming the branch.

That containment is load-bearing. By the time the step runs the branch is pushed and the PR is open, so the task has succeeded, and this function's outer catch is its designed failure channel: an error escaping the fetch reaches it, overwrites `pr_open` with `failed`, and emits `coding/task/failed` for a task that shipped. Origin is the source of truth and any later host-side operation can fetch on demand, which is what makes discarding the error the right trade. `fetchFeatureBranch`'s docstring and `design/coding-delegation.md` → Inngest step boundaries state the same contract.

`orchestrator-git-remote.test.ts` covers the verify phase alongside plan and execute. A rejecting `fetchFeatureBranch` leaves the task at `pr_open` with a null `failure_reason` and no `coding/task/failed` emitted; a companion pins that the step is wired at all, so a skipped call cannot pass for a tolerated one.

**`skill-authoring.integration.test.ts` gives the feature branch a single writer.** On replay the sandbox is a cassette, so the stub Octokit's `POST /pulls` commits `test/fixtures/skill-authoring-branch/` into the bare remote — the point at which origin is taken to have learned the branch, and one the orchestrator's own step sequence orders strictly before the fetch-back, so nothing polls against a live run. Both host-side consumers, the fetch-back and the skill-register fetch, pull that one commit from the remote and run their production path. `AutoRegisterSkillDeps` carries no git seam.

Single-writer is a correctness requirement rather than tidiness. Two writers minting separate commits for one branch — one into the skills repo, one into the remote — put siblings on a single ref whose order an Inngest event decides rather than program order, and the skills repo's pre-receive hook (`bootstrapSkillsRepo`) declines the non-fast-forward the later arrival becomes.
