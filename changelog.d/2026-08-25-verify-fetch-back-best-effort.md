**The verify orchestrator's post-PR fetch-back is best-effort in code, not just in prose.** `fetch-feature-branch` refreshes the host mirror after the sandbox pushes `cogmo/<idShort>` to origin, and the step, `fetchFeatureBranch`'s docstring and `design/coding-delegation.md` all called it best-effort — origin is the source of truth and any later host-side operation can fetch on demand. The code did not agree: the call sat unguarded above the orchestrator's broad `catch`, which is this function's designed failure channel. A fetch that failed for any reason ran after `set-status-pr-open`, overwrote a `pr_open` row with `failed`, and emitted `coding/task/failed` — reporting a task whose branch was pushed and whose PR was open as broken, over a mirror lagging by one ref. The catch now sits inside the step body, so the step records success and the lag surfaces as a warning naming the branch.

`orchestrator-git-remote.test.ts` gains the verify phase its header always claimed. The tolerated-failure case is pinned against a rejecting `fetchFeatureBranch` — the task reaches `pr_open`, the row keeps a null `failure_reason`, and `coding/task/failed` is never emitted — beside a companion asserting the step is wired at all, so a silently skipped call can't pass for a tolerated one.

**`skill-authoring.integration.test.ts` gives the branch one writer, so every host-side fetch runs its production path.** On replay the sandbox is a cassette, so the push that puts the feature branch on origin never reaches the bare `file://` remote and both host-side consumers of that branch — the verify fetch-back and the skill-register fetch — looked for a ref nobody wrote. The stub Octokit's `POST /pulls` now commits `test/fixtures/skill-authoring-branch/` into the bare remote: that is where origin is meant to learn the branch, and the orchestrator's own step order puts it strictly before the fetch-back, so no background poller races the run.

With the branch actually on the remote, the `gitFetchOverride` test seam on `AutoRegisterSkillDeps` has nothing left to do and is deleted along with its `bootstrap` plumbing — the register flow does its real `git fetch` in replay. That is also the only correct shape, not merely the tidier one: the override minted its own commit for the branch in the skills repo while the fetch-back wrote the remote's, two siblings on one ref ordered by an Inngest event rather than by program order. Whichever landed second was a non-fast-forward, and the skills repo's pre-receive hook (`bootstrapSkillsRepo`) declines those — so the register step failed and the skill never appeared. Fetching from a single writer means both consumers agree on one commit and neither pushes at all.
