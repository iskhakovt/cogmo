- `DaytonaSandboxClient` snapshot prewarm gains three reliability fixes against Daytona-side pipeline flakes observed when image warm hits a fresh tag.
- `snapshot.create` is now wrapped in a retry envelope (3 retries, 1s/2s/4s jittered backoff) that fires only on the documented Daytona builder-pipeline race signature — `repository … not found` from an internal-registry repo that wasn't pre-provisioned before push. Persistent failures (broken Dockerfile, auth, validation) are filtered out by the predicate so they surface immediately.
- Rebuilding a snapshot in `ERROR` / `BUILD_FAILED` / `INACTIVE` / `REMOVING` no longer attempts a delete-then-recreate against the original name. Daytona's `snapshot.delete` returns 2xx immediately but the row drains asynchronously, and a follow-up `create` against the same name races the `REMOVING` state and 409s. The new path fires the delete fire-and-forget and rebuilds under a freshly-suffixed `<base>-r-<hex>` name; the orphaned stale row is left to Daytona's own reaper.
- The boot-time `scheduleSandboxImageWarm` helper is no longer one-shot. It now retries `ensureImagePresent` per image with 5s → 10s → 20s → 40s → 60s backoff (capped, ~20 attempts ≈ 20 min total) so a transient provider blip doesn't leave the image cold until the first task pays the multi-minute cold start. After exhaustion the helper logs and gives up; the per-task `step.run("ensure-image-present")` triggers a fresh cycle when a failed prior warm has evicted the cache.
- A new test helper `FakeDaytonaSnapshotPipeline` (`src/test/daytona-snapshot-pipeline-fake.ts`) models Daytona's async snapshot lifecycle — REMOVING-state drain, BUILDING → ACTIVE polling, conflict-on-same-name-recreate while in REMOVING. Flat `vi.fn().mockResolvedValue(...)` setups can't represent these because they're stateless, which is why the original 409-on-rebuild bug shipped past unit tests. The fake's contract is pinned by a dedicated assertion so future tests don't lose the safety net.
- The `snapshot.create` retry predicate (`isTransientSnapshotCreateError`) is now table-driven across the documented Daytona error hierarchy — auth / authorization / validation / not-found / conflict / rate-limit / timeout / connection all pinned non-retryable with the rationale per row, and the narrow `repository … not found` transient signature pinned retryable. Future edits to the predicate have to declare an explicit policy per error class instead of changing behavior implicitly.
