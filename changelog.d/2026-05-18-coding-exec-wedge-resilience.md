- Add per-call `timeoutMs` (total wall-clock) and `idleTimeoutMs` (no-byte-flow watchdog) to `ExecOptions`; both backends (Local-Docker, Daytona) wire them in. New `ExecTimeoutError` sentinel on `wait()` separates "we hit the cap" from `DisposedError` ("we cancelled"). Per-callsite defaults at `checkoutFeatureBranchInSandbox` (60 s total / 30 s idle), `runClaudePlan` + `runClaudeExecute` (30 min / 5 min), and `runCommitAndPush` (60 s local-mutating ops, 5 min for `git push`).
- Add `coding-task-reconcile` Inngest function subscribed to the `inngest/function.failed` system event. Flips non-terminal `coding_tasks` rows whose function id matches a coding orchestrator (`coding-task-start`, `coding-task-execute`, `coding-task-verify`) to `failed` via a `step.run("reconcile", …)` durable step, then emits `coding/task/failed` via `step.sendEvent("emit-failed", …)` with idempotency `id: "reconcile-${run_id}"`. The two-step split is load-bearing: if the emit were inside the cached `step.run`, a transient send blip would leave the row `failed` but the event un-emitted — the retry would see `already_terminal` (DB UPDATE already committed) and skip the emit forever. Conditional `failTaskIfNonTerminal` store method makes the path racefight-safe against the in-worker `try/catch`. Covers the worker-disconnect class that per-function `onFailure` is documented not to fire reliably on ([inngest/inngest#3549](https://github.com/inngest/inngest/issues/3549)).
- Motivating incident: a `coding-task-start` run wedged for 4 days when `getSessionCommandLogs` held its Daytona WebSocket open silently (Daytona [#2513](https://github.com/daytonaio/daytona/issues/2513) — no async exit notification; [#2510](https://github.com/daytonaio/daytona/issues/2510) — WS doesn't always close). The total + idle pair caps `wait()` and runs the same `deleteSession` cleanup `dispose()` does; the reconcile function recovers the row state from the system event. Pattern matches e2b ([#1128](https://github.com/e2b-dev/E2B/issues/1128)), Modal (`timeout` + `idle_timeout`), and the WebSocket-heartbeat "75% rule."
