**Worktree teardown runs no git on the host.** The task's clone is bind-mounted read-write into its container, so the sandbox writes its `.git/config` and hooks; a git command the host ran there executed under that config as the Cogmo user (hooks, `core.fsmonitor`, clean filters, `credential.helper`, a rewritten `remote.origin.url` that received the PAT). Teardown now reaps the task's containers and commits the tree as `wip: <task-id>` in a salvage container with no credential (`runWipCommit`). Only when HEAD still has to reach the remote does it create a second container holding the PAT and no signing key, which fetches HEAD into a scratch bare repo and force-pushes it to `refs/cogmo-wip/<task-id>` on the registered remote URL (`runWipPush`), so the tree's remotes and transport config never apply to the push. Every salvage exec runs with hooks, fsmonitor and credential helpers off. The host removes the tree only after a clean or pushed salvage with both containers reaped; otherwise it keeps the tree (`salvage_unavailable_kept`, `salvage_reap_failed_kept`, `wip_push_failed_kept`) and never falls back to git in it. The `allocate-worktree` adopt check opens `.git/HEAD` with `O_NOFOLLOW` and replaces a clone whose `.git` is a symlink.
