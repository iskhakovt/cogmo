**Worktree teardown runs no git on the host.** The task's clone is bind-mounted read-write into its container, so the sandbox writes its `.git/config` and hooks; a git command the host ran there executed under that config as the Cogmo user (hooks, `core.fsmonitor`, clean filters, `credential.helper`, a rewritten `remote.origin.url` that received the PAT). Teardown now reaps the task's containers, runs the WIP salvage (`runWipSalvage`: status, `add -A`, `commit --no-verify`, `push --force --no-verify origin HEAD:refs/cogmo-wip/<task-id>`) in a fresh salvage container that mounts the tree and the askpass material, deletes that container, and only then removes the tree on the host. A tree the salvage could not finish stays on disk as `salvage_unavailable_kept` or `wip_push_failed_kept`; the host never falls back to git in it. The `allocate-worktree` adopt check reads `.git/HEAD` as a file and refuses a symlinked HEAD or `.git`.
