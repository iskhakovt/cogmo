**Use cases plan durable steps through a project-owned `Durable` port instead of Inngest's `step`.** `src/inngest/durable.ts` defines the four primitives the domain uses — `run`, `sendEvent`, `sleep`, `waitForEvent` — typed against the events `events.ts` defines, so emitting an undefined event or a mistyped payload no longer compiles. Each function's handler calls `fromStepTools(step)` once and passes the port to its use cases; every use case that planned steps on Inngest's types now takes it, except the Observer. The agent loop's `StepRunner` is the port's `run`.

`Durable.run` returns `T` and rejects at compile time a result type the JSON round-trip would change (a `Date`, an `Error`, a `Map`, a class with methods, `undefined` in a union). Six steps relied on that rewrite. Four now return `null` for a missing row, which a replay already returned; the branch sweep's `load-repo` and `load-tasks` return only the fields the sweep reads, `createdAt` as the ISO string it already arrived as. Step ids are unchanged, and a run in flight replays its stored results into the new readers as they are.

Deps bags that only emit take an `EventPublisher` (`send`) instead of the Inngest client. The debounce functions are thin controllers over use cases in `agent/debounce/`, tested against the in-memory fake in `src/test/fake-durable.ts`. design/architecture.md → Orchestration Coupling records why the port is Inngest-shaped rather than engine-neutral.
