**Use cases plan durable steps through a project-owned `Durable` port instead of Inngest's `step`.** `src/inngest/durable.ts` defines the four primitives the domain uses — `run`, `sendEvent`, `sleep`, `waitForEvent` — typed against the events `events.ts` defines, so an emit of an undefined event name or a mistyped payload no longer compiles. Each function's handler calls `fromStepTools(step)` once and passes the port down; the handle-message phases, the coding, verify and branch-sweep orchestrations, the pipeline stage runner, gate resolver and gate waiter, both cron tickers and the Direct adapter's inbound now take it, and the `StepRun`/`StepSendEvent` aliases are gone. The agent loop's `StepRunner` is the port's `run`.

`Durable.run` returns `T` and checks at compile time that `T` survives Inngest's JSON round-trip: a `Date`, a `Map`, a class with methods or `undefined` in a union fails at the call site. The check found six steps relying on the round-trip's rewrite. `load-conversation`, `last-assistant` and both `load-last-tokens` steps now return `null` for a missing row, which is what a replay already returned, and the branch sweep's `load-repo` and `load-tasks` return only the fields the sweep reads, with `createdAt` as the ISO string it already arrived as. Step ids are unchanged, and a run in flight replays its stored results into the new readers as they are.

Deps bags that only emit take an `EventPublisher` (`send`) rather than the whole Inngest client: the transport namespaces, boundary use cases, coding service and orchestrators, skills service and pipeline start. The debounce functions are thin controllers over three use cases in `agent/debounce/` (`route-inbound`, `fire-debounce-timer`, `emit-native-ready`), tested against the in-memory fake in `src/test/fake-durable.ts`. design/architecture.md → Orchestration Coupling records why the port is Inngest-shaped rather than engine-neutral.
