Skills tier-2 pre-fork supervisor (P3.2.B.2). Replaces P3.2.B.1's spawn-fresh-`python -c`-per-task lifecycle with a long-lived python supervisor process inside the warm container that forks a child per `task_invoke`. Steady-state cost drops from ~300 ms (full python startup + asyncio/json/uuid imports) to ~10-30 ms (COW fork from a parent that's already imported the runner prelude). Common imports are paid once at supervisor spawn; per-task isolation is preserved at the OS process boundary — every task runs in a fresh fork from the supervisor's `sys.modules` snapshot at create time.

`supervisor.py` is hand-rolled stdlib-only (~150 LOC): `sys.stdin.readline()` task-dispatch loop, `os.fork()` per task, `os.pidfd_open()` + `selectors.select(timeout=...)` for wall-clock timing, `os.kill(pid, SIGKILL)` + `os.waitpid` reaping. EOF on stdin = clean shutdown. Wall-clock kill is per-child: the supervisor itself stays alive across tasks and forks a fresh child for the next invoke — pool worker stays reusable, in contrast to B.1 where wall-clock kills tore down the whole container. Children inherit stdin/stdout from the supervisor (real `os.fork()` inherits FDs cleanly), so the existing one-shot `runner.py` ctx-bridge runs unchanged in the child.

Considered and rejected: PEP 734 `concurrent.interpreters` (numpy/pandas/cryptography don't support `Py_mod_multiple_interpreters`, no production adopters, cross-interp asyncio bridging is hand-rolled — research summary pinned in `design/skills.md` "State reset between tasks"); `pebble.ProcessPool` over `multiprocessing.forkserver` (`multiprocessing.process.BaseProcess._bootstrap()` unconditionally calls `util._close_stdin()` in every worker child regardless of start method — workers can't read host stdin, which breaks the ctx-bridge; workarounds re-introduce the complexity hand-rolling avoids).

Architecture changes: `task_invoke.body` (skill source) and `task_invoke.isolation` are new protocol fields — body is per-task because the supervisor is long-lived across tasks and can't pre-bake any one body. `Dispatcher` refactored to support a persistent transport with per-task `ctxHandler` (was: one dispatcher per task with fixed handler). `SysboxSkillWorker.create` now spawns the supervisor via `session.execStreaming(["python3", "-u", "-c", SUPERVISOR_PY])` once at create time and holds a single dispatcher for the worker's lifetime; `invoke(task)` routes through the persistent dispatcher with a per-task ctxHandler. `runOnSysboxContainer` (the resource-override one-shot path) becomes a thin wrapper around `SysboxSkillWorker.create` + `invoke` + `dispose` — same supervisor model, just disposed after one task. `runner.py`'s `_main` was refactored to take `(body, inputs, task_id)` arguments directly instead of reading `task_invoke` from stdin.

Wall-clock kill semantics changed: the supervisor handles per-task wall-clock internally (SIGKILLs the child, emits `task_result {ok: false, error: "wall_clock_exceeded"}`), supervisor stays alive, worker remains reusable. The host-side `Dispatcher` still has a watchdog at `wallClockS + 5 s` (`SUPERVISOR_GRACE_S`) as a safety net — fires only if the supervisor itself hung; surfaces as `supervisor_unresponsive` and poisons the worker. `isolation: recycle` skills poison the worker after each task regardless of result, so the pool replaces them on next acquire.

Code: new `src/skills/worker-sysbox/supervisor.py.ts`. Refactored `runner.py.ts` (`_main(body, inputs, task_id)`), `dispatcher.ts` (per-task ctxHandler), `worker.ts` (long-lived supervisor + persistent dispatcher), `host.ts` (one-shot wrapper around the worker), `runner.ts` (isolation pass-through), `protocol.ts` (`body` + `isolation` + `wallClockS` on `task_invoke`). `host.test.ts` deleted (paths covered by `worker.test.ts` + `dispatcher.test.ts`); `worker.test.ts` rewritten for the supervisor model (39 tests including state-machine, host watchdog, isolation:recycle, exec-failed cleanup); `runner.sysbox.integration.test.ts` extends the warm-pool e2e with a per-task state-isolation assertion (skill A pollutes `sys.modules`, skill B's fresh fork doesn't see it) and a same-supervisor-PPID assertion (proves process reuse). Smoke-tested locally against `cogmo-skills:test` — 3 sequential tasks share supervisor PID 1, each gets a fresh child PID, state isolation holds across tasks.
