Skills tier-2 pre-fork supervisor (P3.2.B.2). Replaces P3.2.B.1's spawn-fresh-`python -c`-per-task lifecycle with a long-lived python supervisor inside the warm container that forks a child per `task_invoke`. Steady-state cost drops from ~300 ms (full python startup + asyncio/json/uuid imports) to ~10-30 ms (COW fork from a parent that's already imported the runner prelude). Common imports are paid once at supervisor spawn; per-task isolation is preserved at the OS process boundary — every task runs in a fresh fork from the supervisor's `sys.modules` snapshot at create time.

The supervisor is hand-rolled stdlib-only Unix code (~150 LOC): `sys.stdin.readline()` task-dispatch loop, `os.fork()` per task, `os.pidfd_open()` + `selectors.select(timeout=...)` for wall-clock timing, `os.kill(pid, SIGKILL)` + `os.waitpid` reaping. EOF on stdin = clean shutdown. Wall-clock kill is per-child: the supervisor itself stays alive across tasks and forks a fresh child for the next invoke — pool worker stays reusable, in contrast to B.1 where wall-clock kills tore down the whole container. Children inherit stdin/stdout from the supervisor (real `os.fork()` inherits FDs cleanly), so the existing one-shot runner ctx-bridge runs unchanged in the child.

Considered and rejected: PEP 734 `concurrent.interpreters` (numpy/pandas/cryptography don't support `Py_mod_multiple_interpreters`, no production adopters, cross-interp asyncio bridging is hand-rolled — research summary pinned in `design/skills.md` "State reset between tasks"); `pebble.ProcessPool` over `multiprocessing.forkserver` (`multiprocessing.process.BaseProcess._bootstrap()` unconditionally calls `util._close_stdin()` in every worker child regardless of start method — workers can't read host stdin, which breaks the ctx-bridge; workarounds re-introduce the complexity hand-rolling avoids). Revisit subinterpreters at Python 3.16+ (late 2027) when the ecosystem catches up.

Architecture changes: `task_invoke.body` (skill source) and `task_invoke.isolation` are new protocol fields — body is per-task because the supervisor is long-lived and can't pre-bake any one body. `Dispatcher` refactored to support a persistent transport with per-task `ctxHandler` (was: one dispatcher per task with fixed handler). `SysboxSkillWorker.create` spawns the supervisor via `session.execStreaming(["python3", "-u", "-m", "cogmo_skills_runtime"])` once at create time and holds a single dispatcher for the worker's lifetime; `invoke(task)` routes through the persistent dispatcher with a per-task ctxHandler. `runOnSysboxContainer` (the resource-override one-shot path) becomes a thin wrapper around `SysboxSkillWorker.create + invoke + dispose` — same supervisor model, just disposed after one task. Wall-clock semantics changed: the supervisor handles per-task wall-clock internally (SIGKILLs the child, emits `task_result {ok: false, error: "wall_clock_exceeded"}`), supervisor stays alive, worker remains reusable. The host-side `Dispatcher` still has a watchdog at `wallClockS + 5 s` (`SUPERVISOR_GRACE_S`) as a safety net — fires only if the supervisor itself hung; surfaces as `supervisor_unresponsive` and poisons the worker. `isolation: recycle` skills poison the worker after each task regardless of result.

The python source ships as a real **uv-managed Python project** at `images/skills/`, not as TypeScript template-literal embeds. `pyproject.toml` + `uv.lock` (reproducible builds), `src/cogmo_skills_runtime/{__init__,__main__,supervisor,runner}.py` with full type annotations and `py.typed` marker, `tests/{test_supervisor,test_runner}.py` (21 pytest tests covering the bridge correlation, fork+pidfd timeout primitives, SIGKILL+reap, syntax-error / skill-raises / missing-async-run shapes). Dev tooling: ruff (`F E W I B UP RUF`, 100-col), pyrefly as the typechecker (Meta's Rust replacement for Pyre — picked over mypy and Astral's still-beta ty per the comparison in `design/tooling.md` "Python sub-projects"), pytest with `asyncio_mode = "auto"`. New `skills-runtime` CI job runs `uv sync --locked` + `ruff check` + `pyrefly check` + `pytest` on every PR.

The image becomes a multi-stage Docker build: builder syncs the locked deps from a uv binary copied out of `ghcr.io/astral-sh/uv:0.11.12` (no apt install of uv); runtime stage copies just the venv to `/opt/cogmo-skills/.venv` and adds it to `PATH`. Default `CMD` is `python3 -u -m cogmo_skills_runtime` — the TS host overrides at create-container time. Production has zero runtime python deps today (stdlib only); the uv pipeline is wired so adding a dep is `uv add` + `uv lock` + the image picks it up — no Dockerfile changes per dep. Sets the convention for P3.4 per-skill `requirements.txt` resolution and for any future python sub-project in the codebase.

TS side: `src/skills/worker-sysbox/worker.ts` spawns the supervisor via `python3 -u -m cogmo_skills_runtime`. `Dispatcher` reuses transport across tasks with per-task ctx handlers. `runner.sysbox.integration.test.ts` extends with a state-isolation assertion (skill A pollutes `sys.modules`, skill B's fresh fork doesn't see it) and a same-supervisor-PPID assertion (proves process reuse). `host.test.ts` deleted (paths covered by `worker.test.ts` + `dispatcher.test.ts`); `worker.test.ts` rewritten for the supervisor model (39 tests including state-machine, host watchdog, isolation:recycle, exec-failed cleanup). Smoke-tested locally against the rebuilt `cogmo-skills:test` image: 3 sequential tasks share supervisor PID 1, fresh child PIDs per task, state isolation holds, wall-clock kill works, supervisor recovers for next task.

Codebase: 443 TypeScript skills tests + 21 Python tests pass. typecheck + lint clean.
