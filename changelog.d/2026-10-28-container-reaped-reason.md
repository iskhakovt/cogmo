**`containers.reaped_reason` records why a container was reaped; `exit_code` is dropped.** A reap transition (`transitionContainerStatus` with `{ to: "reaped", reason }`) carries one of `ttl_expired | cascade | dead_instance | crash_reconcile | start_failed` and writes it to the new nullable `container_reaped_reason` column. `chk_containers_reaped_reason` ties the column to the status, so a reaped row without a reason and a live row with one are both unrepresentable. A stale reap leaves the first writer's reason. The enum's sixth value, `unknown`, belongs to rows reaped before the column existed: the migration writes it and no code path can.

`containers.exit_code` had no writer: a reap removes the container before anything inspects it, and a container the stale pass finds missing took its exit code with it. The column is gone, and `design/sandbox.md` says an `exited` row carries none.

One migration, one transaction: the enum and column, the backfill of `unknown`, the column drop and the CHECK. Its test runs the raw SQL over rows in every status; store, reaper and supervisor tests assert the reason each path writes. `design/sandbox.md` → Container state machine carries the column, the transition writes and the deploy-overlap failure modes.
