**`containers.reaped_reason` records why a container was reaped; `exit_code` is dropped.** A reap transition (`transitionContainerStatus` with `{ to: "reaped", reason }`) carries one of `ttl_expired | cascade | dead_instance | crash_reconcile | start_failed` — the type requires it — and the same conditional UPDATE writes it to the new nullable `container_reaped_reason` column. `chk_containers_reaped_reason` ties the column to the status: `(status = 'reaped') = (reaped_reason IS NOT NULL)`, so a reaped row without a reason and a live row with one are both unrepresentable. A stale reap leaves the first writer's reason, as it leaves its `exited_at`. The enum's sixth value, `unknown`, belongs to rows reaped before the column existed; the backfill migration writes it and no code path can (`ContainerReapReason` excludes it).

`containers.exit_code` had no writer: a reap removes the container before anything inspects it, and a container the stale pass finds missing took its exit code with it. The column is gone, and `design/sandbox.md` says an `exited` row carries none.

Three migrations, each its own transaction: the enum and column, the backfill `UPDATE`, then the CHECK and the column drop. `migration-0077.test.ts` runs the raw SQL over rows in every status and checks that the CHECK migration fails before the backfill and holds after it. Store, reaper and supervisor tests assert the reason each path writes; `design/sandbox.md` → Container state machine carries the new column, its transition writes and the deploy-overlap failure modes, marked `[proposed]`.
