Log the full LLM request and response body on failure. A new `withFailureLogging` fetch wrapper sits between cogmo and both SDK clients (`openai`, `@anthropic-ai/sdk`), buffers the outbound request body once at entry, and emits a single pino `error` record carrying URL, method, redacted headers, request body, response status, and response body — but only when the upstream returns `!res.ok` or the call throws. Successful requests stay silent. Bodies are truncated at 100KB with a marker. `authorization` / `x-api-key` / `anthropic-api-key` / `proxy-authorization` / `cookie` headers are redacted before logging. Motivation: the xAI grok-4.3 enum-slash 502 lost hours of diagnosis because production logs carried only the SDK's terse `err.message`; a request-body dump would have been a one-line ops task.
