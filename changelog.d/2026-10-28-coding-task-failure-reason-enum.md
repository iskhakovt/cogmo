`coding_tasks.failure_reason` is the `coding_task_failure_reason` enum: one label per writer branch (`cli_exit_error`, `no_plan_produced`, `branch_conflict`, `auth_failed`, `push_failed`, `verify_failed`, `verify_timed_out`, `pr_auth_failed`, `pr_validation_failed`, `pr_open_failed`, `credentials_unavailable`, `run_terminated`, `start_emit_failed`, `unexpected_error`, `user_cancelled`, `user_requested_revisions`, plus `claude_auth_failed` reserved by the design and `unknown` for the backfill). The masked text each branch had — a CLI exit code, the suite's output, a thrown error's message — moves to the new `failure_detail` column, null when there is none (a Cancel). Every writer passes a `TaskFailure = { reason, detail }`; `coding/task/failed` carries both fields; the Telegram progress message renders the reason's label and the detail. The plan and execute runs gain a memoized `check-credentials` step: a missing Claude OAuth token, or on git-remote a missing GitHub identity, is `credentials_unavailable` before any worktree or container exists, where it was a throw recorded as the catch's error. The verdict is memoized, so a secret deleted later in the run no longer reroutes a replay down the failure exit of a task that has already moved on. `plan-cli` and `execute-cli` memoize `{ kind: "errored" | "completed" }`.

Per-state data is tied to its status by CHECKs: a reason exactly at `failed` / `cancelled`, a detail only with a reason, a bare row at `queued`, a plan from `awaiting_approval`, an approval from `executing`, PR metadata only from `pushed` and always at `pr_open`. The execute run's `plan_approved_at` pre-check is therefore unreachable at the database; `session_id` stays untied, since the plan run advances without one.

Migration 0076 is one file, one transaction: the type, the column, the backfill, the type change and the CHECKs. The backfill first clears the reason on rows that are not `failed` / `cancelled` — a Cancel's text that an earlier build's unconditional status writes carried past the Cancel, which the CHECKs would otherwise refuse on every boot — then moves the stored text to `failure_detail` (a Cancel's is dropped) and maps it by the prefix each branch wrote, the pre-#397 `draft PR open failed` included; other text is the catch's, `unexpected_error` on a `failed` row, and a row with no or empty text is `unknown`. A row the CHECKs refuse rolls the whole file back, and boot stops until the row is repaired. A run in flight across the deploy that memoized the old `failureReason` text in `plan-cli`, `execute-cli` or `reconcile` reads it as the detail of the one reason that step produces; a memo with neither text nor failure is refused.

Tests: the migration's mapping, every status's row surviving the CHECKs, and the rollback; store-level CHECK refusals for seven impossible combinations; each writer's reason (verify timeout, the push and PR-open matrices, no plan, start emit, cancels, reconcile, catch); the legacy-memo parses; the event-schema enum pinned to the store's. A `parkCodingTaskAt` fixture drives test rows through the real transitions so they carry the data their status requires.
