`coding_tasks.failure_reason` is the `coding_task_failure_reason` enum: one label per writer branch (`cli_exit_error`, `no_plan_produced`, `branch_conflict`, `auth_failed`, `push_failed`, `verify_failed`, `verify_timed_out`, `pr_auth_failed`, `pr_validation_failed`, `pr_open_failed`, `credentials_unavailable`, `run_terminated`, `start_emit_failed`, `unexpected_error`, `user_cancelled`, `user_requested_revisions`, plus `claude_auth_failed` reserved by the design and `unknown` for the backfill). The masked text each branch had — a CLI exit code, the suite's output, a thrown error's message — moves to the new `failure_detail` column. Every writer passes a `TaskFailure = { reason, detail }`; `coding/task/failed` carries both fields; the Telegram progress message renders the reason's label and the detail.

Per-state data is tied to its status by CHECKs: a reason exactly at `failed` / `cancelled`, a detail only with a reason, a bare row at `queued`, a plan from `awaiting_approval`, an approval from `executing`, PR metadata only from `pushed` and always at `pr_open`. The execute run's `plan_approved_at` pre-check is therefore unreachable at the database; `session_id` stays untied, since the plan run advances without one.

Migration 0076 is one file, one transaction: the type, the column, the backfill (stored text → `failure_detail`, mapped by the prefix each branch wrote → `failure_reason`, `unknown` otherwise), the type change and the CHECKs. A row the CHECKs refuse rolls the whole file back for the next boot to retry. A run in flight across the deploy that memoized the old `failureReason` text in `plan-cli`, `execute-cli` or `reconcile` reads it as the detail of the one reason that step produces.

Tests: the migration's mapping, every status's row surviving the CHECKs, and the rollback; store-level CHECK refusals for seven impossible combinations; each writer's reason (verify timeout, the push and PR-open matrices, no plan, start emit, cancels, reconcile, catch); the legacy-memo parses; the event-schema enum pinned to the store's. A `parkCodingTaskAt` fixture drives test rows through the real transitions so they carry the data their status requires.
