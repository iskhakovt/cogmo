Telegram chats can now be pinned to a default profile that survives `/new`. A new `chat_default_profiles` table holds `(channel_id, platform_address) → profile_id` bindings; the Transport consults it inside `createConversation` and falls through to the global default when no row exists. The Telegram adapter surfaces this as a new subcommand: `/profile default <name>` to pin, `/profile default clear` to unpin, `/profile default` to show the current binding. The binding is identity-checked (the profile must be visible to the caller), upserted on set, and swept on channel removal via `ON DELETE CASCADE`. Direct-adapter and CLI flows are unaffected — they don't write to the new table, so they continue to use the global default.
