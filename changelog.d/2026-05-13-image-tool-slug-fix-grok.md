Strip the provider prefix from image-model identifiers in `generate_image`'s tool schema so xAI's grok-* family no longer 400s on `Invalid arguments`. The model is exposed to the LLM as `flux-pro` rather than `fal-ai/flux-pro`; the handler resolves the slug back to the canonical row. xAI compiles tool JSON Schema into a constrained-decoding grammar server-side, and its compiler rejects any `enum` literal containing `/` ([vercel/ai#8024](https://github.com/vercel/ai/issues/8024), [zed#34185](https://github.com/zed-industries/zed/issues/34185)). The store enforces slug uniqueness at insert time (`createImageModel` / `upsertImageModelsByName` raise `ImageModelSlugCollisionError` if a new row would collide with an existing one — e.g. inserting `replicate/flux-pro` while `fal-ai/flux-pro` is registered), so operators get a clear error at admin time instead of a boot-time `createImageTools` throw at the next restart.
