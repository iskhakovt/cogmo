**Skill runs and deploys carry their per-state data under CHECK.** `skill_runs` keeps its lifecycle as a phase (`recovery_point`) and a verdict (`status`) with nullable payload columns beside them; `chk_skill_runs_status_iff_finished`, `chk_skill_runs_executed_payload` and `chk_skill_runs_outcome` now pin which columns each phase has set. `skill_deploys` gets `chk_skill_deploys_resolved_at_iff_terminal` and `chk_skill_deploys_approved_by_only_live`, and `skill_deploy_status` loses `approved`, which no transition writes. The shapes, transitions and guards are in `design/skills.md` → Per-state data (`[confirmed]`), with the failure modes of the migration and of a run or deploy in flight across it.

In code the payloads are values: `transitionToExecuted` takes `ExecutedOutcome` (`{ kind: "output", output } | { kind: "error", error }`) and `transitionToFinished` takes `SkillRunVerdict` (`{ status: "success", output } | { status: "error", error }`), each mapped onto the columns in the store; `finishedVerdictOf` reads a `finished` row back into its verdict and throws on a shape the CHECKs forbid; `reconstructFinishedResult` and `executedOutcomeOf` match exhaustively, and the skill tool reports the error a result carries, so nothing falls back to `unknown_error`. The store's enum types derive from the `pgEnum`s. `insertDeploy` takes `resolvedAt`; `resolveDeploy`, with no production caller, is removed.

One migration, `0076_skill_run_and_deploy_state_checks`, in one transaction: the type rewrite, then the CHECKs, with the one repair they need inline — runs that finished before `resource_usage` existed get the wall clock from `created_at` to `finished_at`. Any other shape the CHECKs reject has no writer in a shipped build and rolls the file back naming the constraint, so the next boot retries it. Store tests pin each CHECK against a write the old schema accepted; `migration-0076.test.ts` seeds the pre-migration shape, applies the file, and covers the repair, the enum, each CHECK and the rollback.
