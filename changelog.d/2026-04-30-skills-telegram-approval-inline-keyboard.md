New `src/skills/skills-keyboard.ts` mirrors `plan-keyboard`: pure encoder/parser/regex with `skill:<pendingId>:<approve|deny>` callback_data (≤50 bytes, well under Telegram's 64-byte cap), strict UUID regex rejection of malformed input, round-trip + budget tests. New `transport.skills.{approveDeploy, denyDeploy}` namespace with identity check via `transportStore.resolveUser` (any resolved user passes — single-user model; multi-user channels get strict handle→userId mapping for free), pre-checks deploy status to surface precise error codes (`skill_deploy_not_found`, `skill_deploy_not_pending`, `skill_deploy_register_failed`). New `SkillsApprovalDeps` adapter dependency wires `inngest + skillStore + transportStore` into the per-channel function. `telegram-skills-approval-${channelId}` Inngest function listens on the event, fetches the deploy + skill row to surface declared effects on the prompt ("Declared effects: sends_message, posts_public"), and posts the keyboard into the originating conversation's active session. `handleSkillsApprovalCallback` translates a parsed tap into the Transport call, edits the original message in place, and clears the keyboard. New `errorMessage` cases for the four skills error codes. 24 new unit tests (10 keyboard, 5 callback handler, 4 service emit, plus regression coverage for the existing patterns updated to the new mock shape). 1812 unit + 88 integration tests pass; typecheck + lint clean.
