The `apt-get upgrade` layer in all three published images (`cogmo`, `cogmo-devbase`, `cogmo-skills`) is keyed on a new `APT_REFRESH` build arg, which `docker-bake.hcl` defaults to the build date. The base images are pinned by digest, so without a changing input that RUN line was a permanent GHA layer-cache hit (`mode=max`) and shipped whatever package set it first saw: the release scan flagged CVE-2026-13221 (Perl regex trie overflow, critical) in `cogmo` and `cogmo-skills` at perl `5.40.1-6`, while `trixie-security` already carries the fixed `5.40.1-6+deb13u1`. With the date as a key, every release re-runs the upgrade against the current security archive, and PR/e2e builds on the same day still hit the cache. Set `APT_REFRESH` explicitly to force a refresh mid-day.

Verified locally: `bake --print` resolves the arg for all three targets, and a fresh `skills` build installs `perl-base 5.40.1-6+deb13u1`. The Trivy alerts close on the next release scan.
