**Voice slice 2 — OpenAI voice fetch interceptor + integration round-trip.** Slice 1 voice tests were unit-only because `@copilotkit/aimock` doesn't speak `/v1/audio/speech` or `/v1/audio/transcriptions`. Slice 2 closes that gap with the same record/replay pattern as `fal-mock.ts`.

**Interceptor (`src/test/openai-voice-mock.ts`).** A scoped `fetch` wrapper, passed via `OpenAIVoiceConfig.fetch` → `new OpenAI({ fetch })`. Intercepts `POST https://api.openai.com/v1/audio/speech` (TTS) and `POST /v1/audio/transcriptions` (STT); anything else falls through to `globalThis.fetch`. Fixture keys: `tts-{model}-{voice}-{sha256(text):12}.{ogg|mp3}` paired with a `.json` metadata sidecar; `stt-{model}-{sha256(audio_bytes):12}.json` carrying the raw OpenAI response. Replay mode returns 503 on miss (strict); `RECORD=1 OPENAI_API_KEY=...` passes through to real OpenAI and writes fixtures atomically. Hashing the audio bytes (rather than logical text) is what makes STT replay deterministic — the integration test commits the input clip alongside the response.

**`bootstrap()` plumbing.** New `voiceFetchOverride` option parallel to `falFetchOverride`. Threaded into both the TTS and STT `OpenAIVoiceProvider` instances so a single interceptor handles both directions. Production wiring leaves the option undefined and the SDK's default fetch applies — zero overhead.

**Direct adapter `sendVoice`.** Mirrors the existing image-on-`directOutbound` pattern: emits a separate `directOutbound` event with a `voice: { data, mediaType }` field carrying base64 audio. The integration tier (Direct adapter only — Telegram is unit-tested via grammY mocks) can now assert on voice delivery the same way it asserts on image delivery. The event schema gained an optional `voice` field; the per-text fan-out path is untouched.

**Integration round-trip (`pipeline.integration.test.ts`).** New test seeds `voice_config` + `secrets` row before `bootstrap()` (the bootstrap reads voice_config exactly once, so the row must exist before then), creates a conversation with `voiceMode: "always"`, uploads fixture OGG bytes via `AttachmentStore`, inserts an `inbound_messages` row with a voice content block, fires `inbound/arrived`, and waits for a `directOutbound` event carrying a voice payload. Asserts the stored user-message content is the STT transcript (i.e. voice→text substitution happened at persist boundary, not just at delivery). First record run TTS's a known phrase via the same interceptor and writes the bytes to `test/fixtures/voice/inbound.ogg` — subsequent replays read those exact bytes so the STT-bytes-hash is stable.
