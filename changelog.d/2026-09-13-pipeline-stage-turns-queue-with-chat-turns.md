**Pipeline stage turns and chat turns on a run's conversation run one at a time.** `handle-message` and `pipeline-stage-runner` share `conversationTurnConcurrency`, a limit of 1 on an env-scoped Inngest key per conversation, and `pipeline/stage.due` carries the run's `conversationId` to key on. A message sent into the run conversation while a stage turn is mid-flight waits for it instead of running a concurrent chat turn whose transcript interleaves with the stage's, and a stage due while a chat turn is in flight waits for that turn. Inngest counts executing steps rather than runs: a started run keeps its place ahead of newer runs, and a run parked in a sleep or event wait frees the slot. An integration test holds a stage's model call, sends a chat message into the run conversation, and asserts the chat turn reaches the model only after the stage call ends.
