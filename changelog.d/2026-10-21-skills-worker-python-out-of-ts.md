**The tier-1 worker's Python lives in `.py` files.** `apps/server/src/skills/worker-wasm/py/` holds the `ctx` SDK and the dependency installer. `worker-entry.ts` reads them as it loads, and the build copies `py/` (subpackages included) into its output directory, so a missing file fails worker init. CI's skills-runtime job runs `ruff check` and `ruff format --check` over them, and `tsup-config.test.ts` checks the build output holds every one.

The skill-venv ABI tag has one definition, `cogmo_skills_runtime.abi.python_abi_tag()`. The supervisor calls it, and the populate and reaper scripts run `python3 -I -m cogmo_skills_runtime.abi` (`PYTHON_ABI_TAG_COMMAND`). `-I` keeps the exec's cwd, a warm worker's task-writable `$HOME`, off `sys.path`, so a package a task plants there can't stand in for the module. The supervisor protocol is version 3, so a host on this release refuses a skills image without the module at worker creation, with the existing "use the skills image matching this Cogmo version" error; a cached `:latest` from before the release needs a `docker pull`.
