**The tier-1 worker's Python lives in `.py` files.** `apps/server/src/skills/worker-wasm/py/` holds the `ctx` SDK (`ctx.py`) and the dependency installer (`install_deps.py`). `worker-entry.ts` reads them from `py/` beside itself as it loads, and the build copies them to `dist/py/`, so a missing file fails the worker at init. CI's skills-runtime job runs `ruff check` and `ruff format --check` over them with the tier-2 runtime's rules; pyrefly skips them, since `pyodide.ffi`, `js` and `micropip` resolve only inside Pyodide. The one-line glue that names the bridge module or awaits at top level stays in `runPythonAsync` calls.

The skill-venv ABI tag (`py<major>.<minor>`) has one definition, `cogmo_skills_runtime.abi.python_abi_tag()`. The supervisor calls it, and the populate and reaper scripts run `python3 -m cogmo_skills_runtime.abi`. Importing `cogmo_skills_runtime` loads neither `runner` nor `supervisor`, so the module runs without runpy's warning. The scripts need a cogmo-skills image from the same release, which `COGMO_SKILLS_IMAGE`'s default pairs by `VERSION`; an older `cogmo-skills:latest` fails a tier-2 populate with `No module named cogmo_skills_runtime.abi`.
