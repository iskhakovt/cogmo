**The tier-1 worker's Python lives in `.py` files.** `apps/server/src/skills/worker-wasm/py/` holds the `ctx` SDK and the dependency installer. `worker-entry.ts` reads them as it loads, and the build copies them to `dist/py/`, so a missing file fails worker init. CI's skills-runtime job runs `ruff check` and `ruff format --check` over them.

The skill-venv ABI tag has one definition, `cogmo_skills_runtime.abi.python_abi_tag()`: the supervisor calls it, and the populate and reaper scripts run `python3 -m cogmo_skills_runtime.abi`. The host therefore needs a cogmo-skills image from this release or later. Against an older one, such as a cached `:latest` (`docker pull` it), tier-2 populate fails with `No module named cogmo_skills_runtime.abi` and the reaper deletes nothing.
