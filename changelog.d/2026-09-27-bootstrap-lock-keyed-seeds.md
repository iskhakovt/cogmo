`cogmo serve`, `cogmo seed` and `cogmo setup` migrate and seed under one session-level bootstrap lock, so concurrent runs apply them one at a time; the setup wizard also takes it to create the skills repo. The lock needs a database pool of at least two connections and refuses to start with `max=1` or `PGMAX=1`. The default profile and the direct and web channels are written through keyed inserts, the channels on a new unique index over fixed-identity channel types. Concurrent skills-repo bootstraps each install the pre-receive hook through their own temp file, and a boot racing the wizard reads the skills origin after its row snapshot, so it can't write an older URL back. An install already holding two direct or two web channels fails migration 0061 until the newer channel and its identities are deleted.
